# Auto-G16 v2.7 exact direct qstat acquisition and scheduler evidence

Status: production-shaped and offline-validated; production and live operation
remain blocked and unauthorized.

## Exact owner chain

The public controller entry accepts only an exact canonical W5 submission
receipt, its original reviewed server-session artifacts, and a live
backend-owned `DirectReviewedReadProfileCapability`. It accepts no job ID,
qstat path, command, argv, environment, SSH option, host, user, identity,
subsystem, proxy, forwarding setting, timeout, output limit, or raw profile
override.

The reviewed read-profile owner reads one fixed no-follow backend path in
production and issues a process-local, registry-backed, single-use capability.
The controller and server issue independent capabilities and compare the exact
canonical profile and transport binding. Portable profile bytes and capability
projections are evidence only; neither is authority.

The query operation receives its job ID only through the Q1 private issuance
join. The fixed SSH channel consumes an exact operation-and-frame join, invokes
only `/usr/bin/ssh` with the reviewed transport profile and read subsystem, and
uses one absolute deadline across the request write, single response plus EOF,
and child wait. Any partial-write, close, timeout, malformed/extra response,
SSH stderr, nonzero child, or retirement ambiguity is terminal
`ControllerTransportUnknown`; it cannot be retried automatically.
Once a query transport is already unknown, cleanup consumes a closure-private
child handle (PID, exact active Query operation ID, creator PID/thread, epoch
and nonce). No raw-PID handle issuer exists: the owner atomically validates
and consumes the running Query operation's sole fork transition, performs the
fork itself, and registers only the PID returned to that parent. A post-fork
registration failure is retired inside that same closure and remains unknown.
The retirement path
requires default `SIGCHLD`, and proves the PID is still this process's
unreaped child with `waitpid(WNOHANG)` before each signal. Only then may it use
`SIGTERM`, bounded wait, then `SIGKILL` and a second bounded reap. `ECHILD`, a
numeric/foreign PID, PID-reuse ambiguity, or an unprovable `ESRCH` path causes
zero further signal and a failed retirement. It never signals a process group
or a different PID. This local child retirement is not PBS cancellation, `qdel`,
job cleanup, or authority to repeat the query; the query remains unknown and
no-retry regardless of retirement success.

## Server acquisition and closed outcomes

The production server owner requires fixed `python -I -S`, cwd `/`, and
`LANG=C`, `LC_ALL=C`. It independently reopens the fixed reviewed read profile,
replays the existing-job lineage owner over the exact W5/W2 artifacts, and
consumes the exact live `DirectSubmittedJobReadCapability` into a retained
lease. The qstat job ID comes only from that lease.

The sole executable is `/usr/bin/qstat`. The schema, reviewed-profile owner and
runtime independently require a regular, single-link, root-owned mode-0755
file with no group/world write bit and the exact reviewed SHA-256. After the
initial open and hash, the clean child immediately before descriptor exec
replays `fstat`, a rewind/full-read SHA-256, a second `fstat`, and same-identity
`stat(..., follow_symlinks=false)` of the fixed named path. Any in-place byte
change or path replacement exits the child before exec and becomes terminal
unknown/no-retry at the controller. Execution is descriptor-bound with exact
argv `/usr/bin/qstat -f <lease-job-id>`, no shell or path fallback, and fixed
environment. Output is bounded to 64 KiB under one monotonic deadline, complete
EOF is mandatory, and the executable, read-profile and lineage leases must
remain current after observation.

This contract treats root, host administrators and the package manager that
owns `/usr/bin/qstat` as trusted TCB. An adversarial root racing the final
hash-to-exec interval is outside this slice's isolation claim; supporting that
stronger threat model would require a separately reviewed immutable executable
loader such as fs-verity or a sealed snapshot and is not implemented here.

Only return code 0 with empty stderr and one exact W6C0 record can be present.
Only return code 153 with empty stdout and the exact
`qstat: Unknown Job Id <id>\n` stderr can be absent. Timeout, incomplete EOF,
oversize, invalid UTF-8, malformed or duplicate output, job/name mismatch,
stderr, other nonzero exit, executable drift, child ambiguity, or any
cross-field contradiction is unknown. Stale evidence is effectively unknown.

## Exact result and final `/3`

`ExactQstatAcquisitionResult` is owner-issued, nonconstructible, noncopyable,
nonserializable, process/epoch/private-registry bound, fork-revoked and
single-use. Its non-authorizing projection binds L1/W5/W2 lineage, reviewed
artifact hashes, controller and server read-profile capabilities, fixed SSH
operation/request/response identities, qstat executable identity and argv,
stream hashes and sizes, timestamps and freshness.

Only the final owner may consume that exact result. It reuses W6C0's parser and
classifier and emits immutable `gaussian-job-inspection/3` scheduler evidence.
Caller bytes, a `QstatObservation`, W6C0 provisional evidence, or a portable
projection cannot be upgraded into `/3`.

All acquisition and final projections fix `authorizes_effect=false`,
`scientific_acceptance=false`, `gaussian_completion=false`, `qsub=false`,
`qdel=false`, `delete=false`, `cleanup=false`, `retry=false`, `fetch=false`,
and `materialize=false`. PBS Q/R/H/E/C/F or absence is scheduler evidence only;
it is not proof of Gaussian completion or scientific acceptance.

controller transport, server descriptor-exec, outcome/W6C0, Draft 2020-12 and
