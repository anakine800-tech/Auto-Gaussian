# Auto-G16 v2.6 owner-sealed protected invocation successor

Status: additive offline contract candidate for independent L3 review. It is
not an adapter, effect, reservation, execution approval, live validation,
deployment, migration, merge, or release record.

## Frozen scope and non-goals

This change adds `auto-g16-protected-invocation-bundle/1`, its owner, one typed
facade seal entry, and a mechanically extracted read-only legacy stage-byte
planner. It does not extend or reinterpret protected-submit `/1`, local-state
binding `/1`, execution request or authorization `/1` or `/2`, any
execution-batch version, historical CLI inputs, or stored artifacts.

No predecessor is migrated, rehashed, backfilled, or automatically promoted.
The successor has no method or scope for adapter invocation, reservation,
stage materialization, submit, status, fetch, cancel, cleanup, deletion,
retry, command execution, configuration access, or external action.

Every owner import is exact-origin and cache-restoring. Before either
predecessor owner is imported or called, PR4F no-follow stable-reads both fixed
adjacent source files and privately binds their canonical paths, full
device/inode/uid/mode/size/mtime_ns/ctime_ns identities, SHA-256 digests, and
exact source bytes. The loader executes only those captured bytes and rechecks
both disk identities after composition. The facade derives the PR4F owner only
from its own repository source layout or its deployed-package adjacent layout;
callers supply no owner path, identity, digest, bytes, clock, or verification
claim.
The composed PR4D owner isolates runtime configuration behind an intentionally
absent system-temporary placeholder. Package/source/combined relocation,
caller shadows, exceptions, concurrency, and pre-populated same-name module
caches cannot select another owner or leak a temporary cache entry or file
descriptor.

## ADR: mechanical legacy stage extraction

Decision: restore historical `stage()` source selection, copy/no-overwrite
checks, exception order, and failure-directory contents exactly. Add only a
read-only deterministic planner in `legacy_rtwin_pbs.py`; do not create a
second executable stage implementation.

The historical order remains:

1. approved Gaussian input basename and bytes;
2. same-stem `.json` when present;
3. same-stem `.xyz` when present;
4. explicit `%oldchk` when declared and owner-validated;
5. the fixed owner-rendered `<project>.pbs`;
6. `checksums.sha256` over items 1–5 in that order.

The legacy `stage()` retains its original operation order and output bytes.
The successor planner performs no stage materialization: it reads sources
no-follow in chunks, retains small bytes for the input projection, and keeps
large companions/checkpoints only in unlinked private temporary snapshots.
There is no 16 MiB stage limit and no half-finished successor bundle. A
base-vs-candidate differential loads the exact `70f1575…` source and executes
both versions against greater-than-16-MiB companion/checkpoint cases, missing
`%oldchk`, all overwrite-conflict roles, and post-copy failure contents.
Golden PBS, CLI, mocked transaction, exception-category, and stage-field
regressions remain unchanged. Exact before/after source hashes and the
behavioral test are recorded in
`tests/fixtures/rtwin_pbs/protected_invocation_mechanical_extraction.json`;
historical contract/Schema/PR4D/PR4G hashes stay frozen.

## ADR: portable versus in-process state

The portable successor stores only:

- project, attempt, scientific task, input, idempotency and scientific
  identity hashes;
- PR4D and PR4G payload hashes;
- the unique relative local directory and fixed ledger basename;
- ledger artifact hash/size, revisions, self-hash projections and a
  domain-separated file-identity hash;
- exact resources and transport digests;
- ordered relative stage names, roles, hashes, sizes and aggregate manifest
  hash;
- fixed replay/future transaction order, explicit no-effect scope/policy, and
  its own payload hash.

It stores no absolute path, raw bytes, free basename, runtime configuration,
command, argv, shell, callback, executable, backend, adapter, credential, or
executable object.

Only the unconstructible in-process capability retains canonical local Paths,
initial predecessor/source file identities, both predecessor owner source
identities and exact bytes, stable small-source/generated bytes, private
large-source snapshots, typed PR4D/PR4G evidence, and the existing owner-issued
objects. Its read-only replay stable-reads and compares both predecessor owner
files before importing either one, executes only the matched exact-origin
bytes, replays the full authority/evidence, and compares the complete
predecessor documents and identity. It then completes the existing predecessor
evidence, local-state ledger, and stage-source checks before a final stable
owner-file comparison. Atomic same-byte replacement, in-place mutation,
symlinks, short reads, and read-time replacement all fail closed. None of this
private state enters portable JSON, so serialization for the same valid seal
remains unchanged. Trusted UTC comes from the owner; the public facade exposes
no clock parameter. The capability has no effect method and acquires no
ledger lock or reservation.

The Draft 2020-12 Schema expresses all eight closed stage topologies with
`oneOf`, fixed `prefixItems`, `items: false`, exact role/order, exact item
counts, and matching `artifact_count`. The Python owner accepts the same
structural set. Cross-field digests, logical identity equality, unique
relative names, and self-hashes remain owner semantics because standard Draft
2020-12 keywords do not express those relations.

## Compatibility, migration and rollback

Compatibility is additive. Old requests, authorizations, bundles, bindings,
ledgers, CLI calls and directories continue under their historical owners.
There is no migration, rehash or backfill path into `/1`.

Before integration, rollback is deletion of only the new successor files and
the mechanical planner extraction while leaving all predecessors unchanged.
After any future artifact exists, `/1` must remain frozen; corrections require
a new successor version rather than reinterpretation.

## Residual gates

Offline evidence can support independent L3 review only. A future adapter task
must separately prove immediate replay, exact reservation transaction, byte

No result here authorizes adapter code, actual stage/submit/status/fetch/
cancel, SSH, PBS, Gaussian, deployment, Skill synchronization, push, PR,
merge, release, or live smoke.
