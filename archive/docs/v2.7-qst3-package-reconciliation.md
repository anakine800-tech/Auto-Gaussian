The smallest falsifying counterexample stages the c6 package alone and imports
`protected_qst3_adapter.py` under `python -I -S -B`. The 121-file c6 package
fails before QST3 replay because `legacy_rtwin_pbs.py` cannot resolve its
`gaussian_log` dependency. Even if that first import is masked by an ambient
path, the adapter reaches sibling TS and scientific-maturity Skills that the
c6 package did not own. Repository-layout success therefore did not prove a
self-contained named package.

The successor package selects exactly one layout: repository sources under the
repository `skills/` root, or packaged dependencies below the named Skill's
`dependencies/` root. Partial, simultaneous, or symlinked layouts fail closed.
The package supplement maps authoritative sources; it does not create a second
repository owner.

An independent package real-chain review found one narrower successor defect:
packaged `scientific_closure_lineage.py` still searched for an RTwin sibling at
`dependencies/skills/auto-g16-rtwin-pbs`, although the sole RTwin owner was the
named package itself. Both isolated `owners()` and minimum-lineage receipt
build/validate stopped at the missing sibling `gaussian_log.py`. The repaired
owner selector now accepts only these two complete source-owned layouts:

```text
repository:
  skills/auto-g16-rtwin-pbs/scripts/{gaussian_log.py,gaussian_rtwin_pbs.py}
  skills/auto-g16-ts-irc/scripts/ts_irc.py

named package:
  scripts/{gaussian_log.py,gaussian_rtwin_pbs.py}
  dependencies/skills/auto-g16-ts-irc/scripts/ts_irc.py
```

Their reviewed SHA-256 values are respectively `ae6ce8b5...e28ca`,
`3a978dbf...0cdb`, and `ce9158f2...39aff`. Selection derives only from the
executed repository or package source path. A partial layout, a second RTwin
owner, wrong reviewed bytes, a symlink or canonical-path drift is rejected
before owner use. There is no installed-Skill, environment, `PYTHONPATH`, or
caller-path fallback, and the named package does not contain a copied second
RTwin owner.

Before the approval owner is executed, its selected `gaussian_log.py` is loaded
under the canonical `gaussian_log` key. A pre-existing key is reusable only
when it is the same module object bound to the selected canonical path, origin,
source SHA-256 and current file identity. Any different preloaded module is
rejected before approval execution. The approval owner's imported log
functions must then be the functions on that exact canonical module.

## Preserved boundaries

This reconciliation adds no server provisioning, scheduler inspection,
cancellation, method selection, Gaussian execution, SSH/PBS transport, qsub,
retry, cleanup, deletion, overwrite, tag, release, or deployment authority.
The QST3 adapter still exposes zero qsub calls and refuses `submit_once`.
Receipt /5 and live approval /13 retain exact input, project, resource,
scientific-maturity, one-attempt, no-retry, no-delete, and no-overwrite gates.
Frequency count alone never accepts a TS; mode review and separately approved
bidirectional IRC remain downstream requirements.

The historical c6 successor fixture is retained byte-for-byte. A separate
additive current-line successor binds the reconciled main-line bytes; it must
not point back to mutable verifier current hashes.

## Deployment gate

Package validation and sync dry-run are offline evidence only. This task does
not apply synchronization. Only after merge may a new, separately reviewed
dry-run with `missing=0`, `changed=0`, and `extra=0` support a separate named
Skill deployment authorization.
