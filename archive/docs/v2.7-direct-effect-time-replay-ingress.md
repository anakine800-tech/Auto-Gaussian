## Effect-time order and failure semantics

The future sole direct consumer must call the ingress exactly once,
immediately before the first possible qsub operation:

1. replay the direct transaction and direct-root currentness;
2. consume `ResourceEffectTimeReplayCapability` through its owner;
3. verify the returned exact resource claim against the frozen direct scope;
4. replay direct-root currentness again;
5. replay `PreQsubLiveApprovalReplayCapability` through its owner;
6. verify the returned exact live result and approval artifact binding;
7. replay direct-root currentness once more; and
8. return one non-authorizing typed combined claim.

The ingress lock admits one consumer. It moves to terminal `failed` before
propagating any resource expiry, live approval expiry, owner/source
replacement, state drift, scope drift, or predecessor failure. There is no
retry, rollback, reconstructed capability, second consumption, cleanup, or
fallback. Because two independent sole-owner registries cannot be atomically
committed together, a failure in the live replay after resource consumption
leaves the resource capability consumed and the combined ingress terminal;
this is deliberate fail-closed behavior with zero external effect.

This is an integrity boundary for calls that enter the original owner-installed
methods. It detects the tested ordinary module-global, equal-record, public
field, helper-function, class-method, class, and source replacements before
predecessor consumption. Its machine-readable `policy` states
`arbitrary_same_process_reflection_isolated=false`,
`untrusted_arbitrary_same_process_code_allowed=false`,
`w4_process_isolation_required=true`, and `production_closure=false`.

The expected disclosed P3 limitation is exact: `inspect.getclosurevars`, direct
`function.__closure__` access, mutation of cell-contained mutable objects,
`ctypes`, or native code can obtain or modify same-process closure state. For
example, code with arbitrary same-process reflection can retrieve both the
registry and identity-anchor dictionaries and synchronously replace an original
record with an equal new record. The offline regression demonstrates that this
counterexample is expected to pass the same-process guard; it is not a security
PASS assertion. Normal production must not load or coexist with untrusted
arbitrary same-process code. W4 process isolation must close that boundary
before any production-closure or live-ready claim.
