# Auto-G16 v2.7 fixed direct one-hop transport

Status: offline production-code closure; production blocked and live not ready

This slice adds the fixed Mac controller → OpenSSH subsystem → trusted
server-local `-I -S` child → `pbs_legacy_v1` call chain. It adds no live
evidence and no authorization to connect, submit, inspect, fetch, cancel,
delete, clean up, deploy, or retry.

The controller's fixed SSH executable/options, descriptor execution, framing,
deadline and child-retirement implementation now have one owner in
`direct_shared_fixed_ssh_channel.py`; W5 consumes its sealed submit operation.
See [the shared-channel contract](v2.7-shared-fixed-ssh-channel.md). The W5
canonical submit wire and qsub semantics below remain unchanged. The Q1
successor privately joins the owner's query operation to production-shaped,
offline-validated qstat acquisition; live query remains unauthorized and fetch
remains blocked.

## Exact topology and authority

The reviewed closed transport profile is hash-bound by the existing direct
profile `/3` `transport_identity_binding_sha256`. It is the only source of the
host, user, port, identity-file policy, known-hosts policy, server allowed root,
fixed SSH subsystem, server entrypoint source hash, reviewed PBS artifact, and
fixed qsub executable/argv. CLI, environment, runtime settings, callers and
portable result documents cannot replace any of them.

The profile also carries reviewed SHA-256 identities for `/usr/bin/ssh`, the
server Python executable, the exact W5 subsystem source, and one canonical
absolute qsub executable. The qsub path is owned only by the closed profile;
it has no default, PATH lookup, CLI, environment, runtime or caller override.
Each executable is opened no-follow, hashed and identity-replayed, then executed
through that same descriptor (`fexecve` or an identity-checked `/proc/self/fd`
alias). Every absolute executable component is traversed descriptor-relatively
with `O_NOFOLLOW`; a symlink in the final path or any ancestor fails closed.
There is no verified-path exec fallback. A platform without descriptor
exec support fails closed and remains `live_not_ready`. The fixed SSH argv uses
`-F none`; the reviewed OpenSSH contract for the exact executable hash states
that this disables user and system configuration files, but does not claim
that it clears compiled defaults. The argv therefore separately fixes
`GlobalKnownHostsFile=none`, the sole profile-owned `UserKnownHostsFile`,
`StrictHostKeyChecking=yes`, `KnownHostsCommand=none`,
`VerifyHostKeyDNS=no`, and `UpdateHostKeys=no`. No global file, command, DNS
record or learned key is a second host-identity acceptance source. It also
uses `IdentityFile=none` before the sole profile-owned `-i` path and disables
the identity agent, implicit certificate file, PKCS#11 provider and security-
key provider, so compiled `~/.ssh/id_*` defaults and environment providers are
not alternate client identities. Proxy/jump/local commands, control reuse and
all forwarding remain disabled on the command line. The accompanying
canonical evidence records these closed facts and is explicitly
non-authorizing; it is not presented as currentness for a config file that
OpenSSH will not read. Offline `ssh -G` tests use only synthetic temporary
paths and prove the exact option expansion without connecting.

The shared owner maps W5's sealed submit operation to the fixed
`auto-g16-direct-one-hop-v1` SSH subsystem.
It does not send an SSH remote command and therefore does not rely on a remote
shell. The subsystem uses one canonical framed protocol. The controller owns a
fresh opaque one-use request identity whose wire commitment binds a 256-bit
nonce and the SHA-256 of every exact reviewed portable artifact byte string.
The request contains only that non-authorizing commitment and those exact
artifact bytes. The response reflects the request identity and binds the W4B
owner-issued non-authorizing readiness projection to the non-authorizing
submission receipt. Frame reads use one monotonic absolute deadline, require
EOF after the frame, and reject trailing bytes or a second frame. No multihop,
arbitrary shell, command, argv, callback or environment surface exists.
The shared owner's controller request pipe is a dedicated nonblocking
descriptor. Its complete
write, including backpressure before SSH authentication or subsystem startup,
uses one monotonic absolute deadline rather than a fresh timeout per chunk.
No-reader, partial-progress stall, peer-close and final-close failures are all
transport-unknown after the request invocation is reserved; none can hang the
controller, retry the request, signal qsub or authorize a second submission.

The subsystem composes W4B and transitions inside its fixed clean child. W4B
alone converts its opaque lease into `TrustedW5OperationSeam`, retaining the
exact W1 descriptor state, W2 started claim, W3 claimed replay result, W4
already-open project FD, direct transaction, input bytes, transport-profile
bytes, and reviewed PBS bytes. W5 neither serializes nor reconstructs those
capabilities and never reopens the project path.

## Immutable upload and qsub

W5 uploads exactly `approved-input.gjf`, `auto-g16-job.pbs`, and
`checksums.sha256` relative to the retained project FD with `O_EXCL`,
`O_NOFOLLOW`, full-write loops, fsync, readback, hash/length checks and project
FD identity replay. The project and its `scratch` directory were already
created by W4; W5 has no mkdir, overwrite, truncation, rollback, cleanup or
delete owner.

W5 does not render PBS or Gaussian semantics. `pbs_script` is exact reviewed
input. The closed `auto-g16-reviewed-direct-pbs-script/1` record binds its
bytes to the direct non-SDL allowed root, exact project/input/resources,
project-relative scratch, workdir checks and the unchanged `g16 <filename>`
execution semantics. Any drift stops before qsub. Legacy
`legacy_rtwin_pbs`, `/home/user100/SDL`, and historical profile `/1` and `/2`
bytes are never imported, migrated, rehashed or backfilled.

Immediately before the sole invocation, W5 conservatively enters
`effect_possible`. The only argv is
`<profile-owned-absolute-qsub> -- auto-g16-job.pbs`; its first element must be
byte-for-byte equal to the executable field in the same self-hashed profile.
The executable and its SHA are rechecked through the same descriptor at effect
time, with cwd changed by `fchdir` to the retained project FD and the fixed
`LANG=C`, `LC_ALL=C` environment. There is no shell wrapper and no retry.
Parent write/close/read/wait faults, timeout, EOF,
oversize output, exit ambiguity, malformed output, extra output and every
exception after `effect_possible` close W2 as `unknown`; restart is
reconciliation-only and can never issue a second qsub. Timeout and oversize
paths use only `waitpid(..., WNOHANG)` observation: no kill, qdel, retry or
blocking wait is used.

Success accepts only one ASCII PBS job ID matching the closed grammar. Raw
stdout is discarded. Before W2 `completed`, W5 creates
`submission-receipt.json` with `O_EXCL`; its owner-issued
`ExactSubmissionReceipt` binds the transport profile, W2 journal/attempt,
project, input, authorization, exact job ID, single fixed invocation hash and
outcome hash. The receipt validator independently derives `receipt_id` from
all receipt fields other than the receipt and result hashes. The controller
also joins profile/project/input/authorization/attempt to the exact current
request artifacts, and joins binding/journal to W4B readiness captured before
the sole submit. A stale or foreign receipt, a replayed whole response, or a
self-hash/receipt-id rewrite therefore fails closed. Neither readiness, the
wire request commitment nor the receipt projection is capability material;
all are non-authorizing and cannot be converted back into authority.

## Server-administrator provisioning gate

The repository package is not an installer and this document authorizes no
server change. A server administrator must not improvise an SSH `-c` wrapper,
PATH-based executable discovery, legacy bridge, or alternate root. Before a
schema-valid direct profile can be issued, a separately reviewed provisioning
manifest and post-install observation must bind all of the following:

- the exact repository commit/tree and named-Skill package inventory SHA;
- one fixed regular, non-symlink Python 3.11, 3.12 or 3.13 executable, its
  SHA-256, `-I -S` behavior and descriptor-exec support;
- exact reviewed submit and read subsystem entrypoints, their fixed argv,
  source hashes, package origins, owner/mode and sshd fragment bytes/hash;
- one profile-owned canonical absolute qsub path and SHA, plus the fixed
  `[path, "--", "auto-g16-job.pbs"]` argv;
- the fixed qstat and Gaussian executable identities required by the read and
  reviewed PBS owners;
- a newly reviewed direct root with component-by-component no-follow identity,
  the durable journal root, and the root-owned read-profile bytes/hash; and
- a dedicated Mac identity and known-hosts file after a bounded direct host-key
  handshake succeeds.

The server Python field already accepts an owner-selected canonical absolute
path and SHA; Python 3.6 is unsupported and requires no schema relaxation.
Likewise, changing the qsub path creates a new transport-profile hash and
requires newly bound direct profile/authorization artifacts. Historical bytes
are never migrated, rehashed or backfilled.

The current repository has no reviewed isolated bootstrap/sshd mapping that
can be installed merely by naming `server_subsystem_once`, and the read script
cannot rely on caller-added import paths under `-I -S`. Until exact entrypoint
ownership, Gaussian executable binding, a direct root, and Mac-direct transport
are separately closed, the administrator disposition remains **NO-GO**. A
post-install inventory may use only stat/lstat/no-follow/hash checks, `sshd -t`
and `sshd -T`, empty-frame fail-closed subsystem probes, and bounded direct
handshakes. It must not create a project, upload, invoke qsub/Gaussian, qdel,
cancel, clean up or delete.

All portable integer-like fields in the transport profile, PBS review and
receipt use canonical decimal strings. Positive values match
`^[1-9][0-9]*$`; the successful return code is exactly `"0"`. JSON numbers
(including `1.0`), booleans, leading zeroes, signs and `-0` are rejected by
both the strict owner and Draft 2020-12 schemas.

## Child retirement and the W6 gate

On completed submission the child closes the W4 project lease, writes the W2
completed terminal event, sends the non-authorizing projection, closes the
control channel and exits. On any unknown path it closes the project lease,
writes or preserves W2 unknown/started-as-unknown evidence, sends at most an
uncertain status, and exits. It never remains available as an inspect/fetch or
qdel service.

The Mac parent closes both controller pipes in `finally` and performs at most
one fixed-duration `waitpid(..., WNOHANG)` retirement observation of its local
SSH child, either after a response or from `finally` when an earlier transport
fault prevented that observation. It cannot block indefinitely and sends no
signal: it does not kill qsub, kill the SSH child, retry transport, submit
again, or convert an unknown outcome into failure or success. A child not
observed retired within the fixed bound leaves the operation transport-unknown
and reconciliation-only.

W6 may not begin from the projection, a dict, JSON, a job-ID string, or a
fabricated `rtwin_sha256`. Its only legal future start is a separately reviewed
owner that joins a fresh W1 descriptor capability, the exact durable W2
terminal journal, and the exact immutable `submission-receipt.json`, then
issues a new typed immutable submission identity. That owner and every real
read/inspect/fetch port remain absent and blocked. qdel/cancel remains a
separate exact authorization and is outside this slice.

## Offline evidence boundary

Tests use temporary POSIX directories, local pipes/socket/process fixtures and
the private deterministic driver. The production entrypoints accept no driver;
source/module/function/executable/argv rebinding fails closed. Tests never read
real SSH configuration, known-hosts files, identity files or credentials and
never connect to SSH/PBS/Gaussian. Passing tests, Schema validation and package
parity do not change `production_blocked`, `live_not_ready`, or the absence of
separately reviewed live evidence.
