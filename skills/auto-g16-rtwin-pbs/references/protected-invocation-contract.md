# Auto-G16 v2.6 protected invocation successor

`auto-g16-protected-invocation-bundle/1` is an additive, non-executable owner
closure for a future single legacy transaction. It does not reserve, stage,
submit, invoke an adapter, read live configuration, contact any external
system, or grant execution authority.

One typed seal call accepts only:

- the exact PR4D protected-submit evidence; and
- PR4G local-state evidence embedding that same PR4D evidence object.

The owner replays both predecessors, derives the unique PR4G ledger path, and
uses the read-only legacy stage planner to capture the approved input, allowed
`.json`/`.xyz` companions, explicit `%oldchk`, fixed PBS bytes and checksum
bytes in their historical order. Small sources retain bytes; large companions
or checkpoints use unlinked private streaming snapshots without a 16 MiB
limit. Historical `stage()` selection, copy/no-overwrite checks, exception
order, and failure-directory contents remain unchanged. Callers cannot
provide `local_dir`, ledger path, a stage list, basename, command, callback,
backend, adapter, configuration, owner path, or clock.

The portable JSON contains relative logical names plus hashes, sizes, order,
policy and self-hash only. Typed predecessor evidence, canonical Paths, small
source bytes, private large-source snapshots, generated bytes and initial file
identities remain only in the unconstructible in-process capability. Its
read-only `assert_current()` reloads both owners from exact origins, replays
complete authority/evidence with owner-trusted UTC, compares complete
identity, then rechecks the ledger and stage. It has no effect method.

The public Draft 2020-12 Schema closes the eight allowed stage combinations
with `oneOf`, fixed `prefixItems`, `items: false`, exact role/order/count and
matching `artifact_count`; cross-field digest and identity relations remain
owner checks.

The facade adds only:

- `seal_protected_invocation_bundle(*, evidence)`

Historical request/authorization `/1` and `/2`, protected-submit `/1`,
local-state `/1`, execution-batch owners and CLI semantics remain frozen with
no migration, rehash or backfill. Offline validation never authorizes a
future adapter or a real operation.
