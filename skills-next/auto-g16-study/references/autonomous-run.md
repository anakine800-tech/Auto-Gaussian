# 自主运行：一次唤醒短卡

首个试点的执行范围见本卡及[验收清单](autonomous-offline-walkthrough.md#首个试点验收)；[AGENTS](../../../AGENTS.md#自主运行)保留通用安全规则。接口实现不等于启用许可，研究会话不得据文档启用自主计算。下述动作只用于最终组合完成审阅、提交路径合并前真实验证和试点授权之后显式启用的轮次。

先查[接口状态](autonomous-offline-walkthrough.md#接口核验与缺口)，再读[已确认计划](autonomous-plan-template.md)；依赖入口未集成就停止该动作，不用自由 Python、SSH 或新脚本代替。首个试点不依赖 T187；自主取消、专用取消停止核验及改投路径仍关闭。取消或 UNKNOWN 只能按第 3 节由负责人显式解除，再核验新 Attempt 的资格，不能自动产生后继。

首次建计划按[模板](autonomous-plan-template.md#首次取得路由身份)取得正式路由身份，纳入提交边界；配置身份不证明资源可用或赋予提交权。配置变化不能把新哈希直接换入已确认计划。本卡处置参数已对照 T186 审阅修复后的 CLI；仍须在最终组合核对[命令表](autonomous-offline-walkthrough.md#接口核验与缺口)，不表示 main 已具备该能力。

## 1. 恢复与取得本次租约

读正式状态的 `phase`、计划哈希、当前 round、租约、本轮实际提交计数、`summary`、`pending` 及相关对象；需要时再读对应证据，避免全量重读日志。状态损坏/无法核验不能按空状态继续。

- round 已 `ended`：退出，不自动 `begin` 新轮。`finish` 只结束 wake，不能清零 round 额度。
- `paused`：不 prepare、submit、补救、改投或自主取消。需观察/取回时，只取得正式观察租约；没有对应入口就交人。暂停不会取消在跑作业。
- 可运行：正式 `start` 取得新 run/token，核对计划确认、ag/RDKit/GoodVibes、计划与规则到期及快照新鲜度。每个动作都用本次身份，不复用以前的 check 结果。
- start 返回的 `link_health` 须进入本次简报：列判定时间、各入口 relay_group、状态及 age_seconds；无字段是旧实现，不推定健康。全部 relay 失败且独立入口成功为链路中断；全部入口失败按本机断网处理。部分 relay 失败按单入口规则，缺失/过期/损坏保持未知。
- 60 分钟前保存并 `finish`；到点或失权立即停止发布。旧租约至 90 分钟才可显式接管并留原因；不能换 token 续权。接管不撤销暂停，不重置预算。

## 2. 观察、取回、保留证据

运行期间须持续运行正式 monitor watch，保持路由和核算所需的成功、新鲜快照。单入口获批示例为 `ag monitor --watch 300`；单次 `ag monitor --json` 的 `interval_seconds` 为空，不能代替 watch 供阶梯 freshness 核验。

启动前批准实际采样入口集合、逐入口间隔及持续时间/采样次数。`--watch` 接受 30–600 秒，但入口的 `monitor_interval_seconds` 可覆盖它；无覆盖时 Slurm 至少 60 秒。多入口配置会采样全部配置入口，monitor 没有 `--cluster` 筛选参数，不能把 `--watch 300` 当作只查询一个入口，也不自行改配置缩小范围或提频。监控未成功或过期时不放行依赖动作；运行 watch 本身不赋予提交、取消或恢复权限。

链路中断时不向 relay prepare/submit；本来独立路由的 SCNet 类 CREST 可继续，但不能删除候选、改入口顺序或把本应去 relay 的对象改投。全部入口失败时不发新动作；已有 running 不因本次看不到而改成 UNKNOWN。资源、暂停、计划/版本/租约及原 Attempt 不可重提规则照常有效。

需要等待恢复时只用本次 start/status 返回的 `link_recheck.next_at`，不创建新 run 或自动化。当前本机未证实 once 接口，采用同 wake 有界复测：默认 30 分钟、最多两次；next_at 必须严格早于 run_until，默认第二次恰到截止便不执行。由已授权 monitor watch 正常采样，本会话每段至多等待 60 秒且可被用户中断；每段前后读正式 autonomy status，核对 owner、暂停、计划/规则到期与运行截止，暂停或无资格立即退出等待并保存，不能为凑次数越过截止。用户要求暂停先调用正式 pause；任何动作仍走内核重新核验。

到 next_at 后使用同一身份：

```sh
ag autonomy link-recheck --study <STUDY> --run <RUN> --token <TOKEN> --plan-sha256 <PLAN_SHA256> --json
```

该命令不等待、不联网，只读取当前缓存；rechecked=false 不消费次数，返回的 next_at 为空即停止补检查。损坏/缺失/过期转为 unknown，不能称为恢复，也不凭旧成功安排继续动作。次数是上限；到截止之前预留保存和 finish 时间，不为第二次延长租约。补检查不重传原 Attempt，也不解除同 wake 的 PresubmitDeferred 对象限制。

status → 已确认结束才 fetch；运行中 Gaussian 用正式 snapshot。status、snapshot、fetch 都须携带本次 `--run`、`--token`、`--plan-sha256`，并在本地发布前重新核验，失权后不发布状态、输出或 facts。暂停或计划到期时 start 使用 `--observe-only`；仍须计划确认、版本匹配及有效租约。

CLI 错误 JSON 只有 `error` 和 `exit_code`，下表的异常名是实现分类；结合错误原因和正式状态区分，不能仅凭非零退出码把所有拒绝统一当全局暂停或可重试。

| 返回证据 / 实现分类 | 本次分支 |
| --- | --- |
| 无变化 | 不写空简报；有租约则正常 finish |
| 自动 facts 为 `written` / `unchanged` | 读事实及原卡片判据；两者均不表示科学接受 |
| `skipped` | 核对跳过原因，不当作已解析；确需解析也只走已有受保护入口 |
| `conflict` | 分支标“需要你看”，保留双方来源，不 refresh/reparse 或覆盖 |
| `failed` | 保留解析错误，标解析阻塞；不能把解析失败当作计算失败补交 |
| UNKNOWN | 正式暂停并把该对象标“需要你看”；仅合规只读核对，待第 3 节人工解除；不重提旧 Attempt |
| cancelled / 取消来源 | 该对象标“需要你看”，等待负责人显式解除；取消接受或作业消失不自动触发后继 |
| 哈希不符 / 取消不确定 | 正式暂停、保留证据与声明；仅允许合规只读核对 |
| `PresubmitDeferred` | 本次唤醒不再尝试该对象；保存原因并在下一次唤醒取得新身份后重新核验，不绕过失败上限 |
| `ObjectRefused` | 仅该对象标“需要你看”，保留原因与待办；其他分支只在无独立全局暂停条件时继续 |
| 快照缺失/过期、SSH 失败 | 当前证据不可支持新动作；按第 5 节记录和熔断，未知不填零 |

PBS 返回 `interrupted` 且没有退出回执时，先对确切 Attempt 执行一次正式 status，至少 300 秒后再次执行；每次携带当时有效的观察身份：

```sh
ag status <ATTEMPT> --run <RUN> --token <TOKEN> --plan-sha256 <PLAN_SHA256> --json
```

两次均须证明同一作业不活跃、无退出回执且声明输出保持不变；队列重现、输出变化或观察错误都不能算作成功的第二次证据。之后才用正式不完整取回，工具还会在下载前后核实确切结束证据和文件一致性：

```sh
ag fetch <ATTEMPT> --incomplete --run <RUN> --token <TOKEN> --plan-sha256 <PLAN_SHA256> --json
```

取回成功不等于科学失败已分类，也不会把不完整结果当完整结果。核对正式不完整回执、原始输出和失败来源后，才由提交路径的证据核验确定 `interrupted` 或 `walltime`，再按第 4 节有界补救；不能用迟到的观察时间推定已跑满 walltime。Slurm 按正式 status 的确切 sacct 终态处理，其 `fetch --incomplete` 准入要求 `finished`（或已核验的 cancelled），不能把 PBS 的 interrupted 标签直接套用过去。取消和 UNKNOWN 仍先走第 3 节人工解除；不得用空队列、取消接受或前端回执替代所需证据。详见[异常说明](unknown-and-failures.md)。

## 3. 取消与改投需求交人

发现需要取消或改投时，将分支标为“需要你看”，简报第一行明确提醒“请负责人在 Mac 上点击取消”，附绑定的原 Attempt、所属集群及理由；本次唤醒不调用远程取消或专用取消停止核验，不启动改投；未完成人工解除前不为取消来源准备或提交新 Attempt。已有证据不足时注明不确定性，不能仅凭文件大小不变认定停滞，也不为了取消追加远程核查。

通过本地 update 将提醒放在 `summary` 第一行，并保存到 `pending` 和该对象记录；先保留其他分支条目，再由 status 读回核对。该入口不执行取消，也不触发后继。

已是 `cancelled` 或 UNKNOWN 时，同样把该对象记为“需要你看”，等待负责人执行以下本地显式解除；逐字记录负责人对这个 Attempt 的原话，不代拟原话或自动调用：

```sh
ag autonomy resolve-attempt --study <STUDY> --attempt <ATTEMPT> --quote '<负责人逐字解除原话>' --json
```

该命令核对当前本地正式证据，不替人查询远端：cancelled 需两张相邻、新鲜、账号一致且确切作业号和作业名均缺席的 monitor 快照；UNKNOWN 需正式 status 保存的同账号、唯一作业名无匹配、远端无 start 回执且不超过 600 秒的观察。证据不足或过期就保留阻塞，不能编辑状态或制造证明。解除记录不自动恢复运行/解锁，不取消作业，不删除旧声明，不重置预算、减少实际消费或授权旧 Attempt 重提。只有明确解除且当前证据仍有效，才重新核对计划、规则、owner、额度、方法和字节等全部条件，考虑新 Attempt；已暂停还须负责人明确要求继续并通过正式 resume。

即使旧规则允许取消，或已有长时间排队、更优候选等条件，本版也只提醒。人工取消回执不自动产生后继；资源核算按正式结束/解除证据处理，释放占用不退回已消费额度。UNKNOWN、哈希不符、取消不确定等全局暂停条件仍照常处理；其他分支仅在没有全局暂停条件时继续。

Slurm 自主取消/改投移出 V4.8；PBS 自主取消/改投在试点后另行交付。这不为普通自主提交增加调度器版本门槛。取消及改投验收均为“正确提醒、零远程取消”，不是试点的前置开发依赖。

## 4. 决定下一步并准备

科学步骤按需读[阶段决策](../SKILL.md#阶段决策)、[唯一补救表](../../auto-g16-recipes/cards/failure-diagnosis.md#症状与最小补救)、[TS 搜索](../../auto-g16-recipes/cards/ts-search.md)、[IRC](../../auto-g16-recipes/cards/irc.md)。不复制诊断阶梯，不恢复类比 TS 原型或基准计算。

计划内的中间判断逐条写“待人确认”。仅对已有正式证据确认作业已结束且失败的对象，在计划与规则允许且无全局暂停条件时新建 Attempt 补救；原 Attempt 不重提、不复用声明。同对象同失败最多两次，每次一个最小改动并复验，改标签/猜测不清零。运行中、仅解析失败或未按第 3 节显式解除的取消/UNKNOWN 都不能进入新 Attempt 路径；人工解除不启用自主取消或改投。UNKNOWN 解除也不能改标为“未派发”或普通科学失败来清除旧消费。

TS 极小点、方向错误须先走最终组合的科学失败证据入口；方法、积分网格、机理变化和结构/代表集合/最终结果签字仍请人，不放宽最终 Opt/Freq 收敛。

路由选择必须与计划及规则绑定。SCNet 四个活跃自主作业和兜底两个排队自主作业按本机全部 study/轮次合计；未取得有效结束/人工解除证据的旧轮、UNKNOWN 和未观测预留保留，账号核数仍包含手动作业。CREST/xTB 沿用[现行建议顺序](../SKILL.md)，同时受实际统一额度约束；分散空闲核不能拼成 default 的 44 核单节点候选。

预算按实际提交消费，prepare 来源和旧意图不另扣。逐 Attempt 保存[完整摘要](confirmation-summary.md)、方法依据、输入/bundle 哈希及授权来源，上传后再校验。放宽输入仅在计划、规则、实现和验证均允许时使用，逐次提醒跳过项及“方法口径未核验”，不把可提交当科学支持。

## 5. 保存、暂停与结束

90% 预算、规则到期、计划/版本失效、UNKNOWN、哈希不符、取消不确定按正式接口暂停。`ObjectRefused` 本身不是全局暂停理由，`PresubmitDeferred` 也不允许在本次唤醒循环试探；先按第 2 节保存该对象的结果。

该 run 已观测 relay_outage 时，内核只豁免连续 SSH 两次暂停计数，恢复后本 wake 仍豁免；卡片不得再次把这次或其同 run 补检查计入 SSH 暂停阈值，不撤销其他原因已产生的暂停。

prepare/submit 的真实派发前 SSH 失败由内核记录：非上述链路中断豁免的首次阻断该对象本 wake 的依赖动作，连续两次唤醒失败才全局暂停；同对象每轮实际派发前失败另限两次，尚未分配 Attempt 的实际失败也计入。同一已记录失败不重复计数，不占科学补救两次额度；已经消费的实际 Attempt 不退回。消费前 `LinkDeferred` 只等待；消费后的链路拒绝保存 `failed_presubmit` / `failure_kind=link`，同样计入对象每轮两次上限、禁止同 wake 恢复后准备后继。下一 wake 才可按既有规则考虑新 Attempt，两次后交人；link 不当作科学失败或伪造 SSH 实测。派发后结果不确定仍是 UNKNOWN，立即全局暂停。

其他观察条件（连续唤醒的监控快照过期、尚未由内核聚合且不属于上述链路中断豁免的 SSH 观察失败、同 wake 多对象同类失败）按 [AGENTS](../../../AGENTS.md#自主运行) 的暂停阈值据实汇总，必要时调用正式 pause，不把对象局部拒绝当作 SSH 或科学失败。保留当前及前次不同 wake 的 ID、观察结果（含成功）、来源文件/哈希、对象、失败类别与理由，通过 update 保存、下次 status 恢复；同对象重复报错不增加对象数。首次失败/过期已阻断依赖动作，不能重复登记内核已记录的失败；来源缺失或无法确认连续性就交人，不推定恢复。

有变化才通过正式 update 保存 `summary`、`pending`、`objects`；它整体替换这三项，先保留仍有效的对象与待办，不能只送变化片段而丢掉旧分支。这些文本不替代真实消费或失败证据。简报控制在一页以内，只写完成了什么、卡在哪里、要负责人决定什么；取消/改投需求的 Mac 点击提醒置于第一行，放宽输入及全部待确认判断也须列明。详细证据放私有归档并给链接，无变化不发简报。

不直接编辑自主 state/journal。study.md 只能由唯一 owner 经已实现的受保护写入口更新；缺入口时把待写内容留在正式状态并列缺口，不能用文本编辑器旁路。目标量齐但未签字时暂停推进，列待签里程碑，不宣称 study 完成。正常 finish 释放本次租约，不取消作业；只有明确结束本轮才 end。实际定时任务与时刻另属 T198 运维授权。
