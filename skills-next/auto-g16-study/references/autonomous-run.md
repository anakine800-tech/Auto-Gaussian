# 自主运行：一次唤醒短卡

首个试点的执行范围见本卡及[验收清单](autonomous-offline-walkthrough.md#首个试点验收)；[AGENTS](../../../AGENTS.md#自主运行)保留通用安全规则。现行 main 仅有本地自主记录，提交路径尚未合并，研究会话不得据文档启用自主计算。下述动作只用于最终组合完成审阅、提交路径合并前真实验证和试点授权之后显式启用的轮次。

先查[接口状态](autonomous-offline-walkthrough.md#接口核验与缺口)，再读[已确认计划](autonomous-plan-template.md)；依赖入口未集成就停止该动作，不用自由 Python、SSH 或新脚本代替。首个试点不依赖 T187；自主取消、停止核验及取消/改投后继路径全部关闭。

首次建计划按[模板](autonomous-plan-template.md#首次取得路由身份)取得正式路由身份，纳入提交边界；配置身份不证明资源可用或赋予提交权。配置变化不能把新哈希直接换入已确认计划。实际参数已按 T186 `e2c4994` 核对，见[命令表](autonomous-offline-walkthrough.md#接口核验与缺口)，不表示 main 已具备该能力。

## 1. 恢复与取得本次租约

读正式状态的 `phase`、计划哈希、当前 round、租约、本轮实际提交计数、`summary`、`pending` 及相关对象；需要时再读对应证据，避免全量重读日志。状态损坏/无法核验不能按空状态继续。

- round 已 `ended`：退出，不自动 `begin` 新轮。`finish` 只结束 wake，不能清零 round 额度。
- `paused`：不 prepare、submit、补救、改投或自主取消。需观察/取回时，只取得正式观察租约；没有对应入口就交人。暂停不会取消在跑作业。
- 可运行：正式 `start` 取得新 run/token，核对计划确认、ag/RDKit/GoodVibes、计划与规则到期及快照新鲜度。每个动作都用本次身份，不复用以前的 check 结果。
- 60 分钟前保存并 `finish`；到点或失权立即停止发布。旧租约至 90 分钟才可显式接管并留原因；不能换 token 续权。接管不撤销暂停，不重置预算。

## 2. 观察、取回、保留证据

status → 已确认结束才 fetch；运行中 Gaussian 用正式 snapshot。status、snapshot、fetch 都须携带本次 `--run`、`--token`、`--plan-sha256`，并在本地发布前重新核验，失权后不发布状态、输出或 facts。暂停或计划到期时 start 使用 `--observe-only`；仍须计划确认、版本匹配及有效租约。

| 返回证据 | 本次分支 |
| --- | --- |
| 无变化 | 不写空简报；有租约则正常 finish |
| 自动 facts 为 `written` / `unchanged` | 读事实及原卡片判据；两者均不表示科学接受 |
| `skipped` | 核对跳过原因，不当作已解析；确需解析也只走已有受保护入口 |
| `conflict` | 分支标“需要你看”，保留双方来源，不 refresh/reparse 或覆盖 |
| `failed` | 保留解析错误，标解析阻塞；不能把解析失败当作计算失败补交 |
| UNKNOWN / 哈希不符 / 取消不确定 | 正式暂停、保留预留与声明，仅允许合规只读核对；不重试、不造替代 Attempt |
| 快照缺失/过期、SSH 失败 | 当前证据不可支持新动作；按第 5 节记录和熔断，未知不填零 |

超时等失败仍需正式结束及所需的取回证据才能诊断。取消接受、前端回执、空队列都不能证明作业已结束；遇到历史或人工取消记录时保留占用及证据，交负责人处理，不进入本版已关闭的停止核验或后继路径。详见[异常说明](unknown-and-failures.md)。

## 3. 取消与改投需求交人

发现需要取消或改投时，将分支标为“需要你看”，简报第一行明确提醒“请负责人在 Mac 上点击取消”，附绑定的原 Attempt、所属集群及理由；本次唤醒不调用远程取消，不核验取消停止，不准备或提交取消/改投后继。已有证据不足时注明不确定性，不能仅凭文件大小不变认定停滞，也不为了取消追加远程核查。

通过本地 update 将提醒放在 `summary` 第一行，并保存到 `pending` 和该对象记录；先保留其他分支条目，再由 status 读回核对。该入口不执行取消，也不触发后继。

即使旧规则允许取消，或已有长时间排队、更优候选等条件，本版也只提醒。保留原作业占用、提交声明和证据；人工取消回执不自动释放额度或触发后继。UNKNOWN、哈希不符、取消不确定等全局暂停条件仍照常处理；其他分支仅在没有全局暂停条件时继续。

Slurm 自主取消/改投移出 V4.8；PBS 自主取消/改投在试点后另行交付。这不为普通自主提交增加调度器版本门槛。取消及改投验收均为“正确提醒、零远程取消”，不是试点的前置开发依赖。

## 4. 决定下一步并准备

科学步骤按需读[阶段决策](../SKILL.md#阶段决策)、[唯一补救表](../../auto-g16-recipes/cards/failure-diagnosis.md#症状与最小补救)、[TS 搜索](../../auto-g16-recipes/cards/ts-search.md)、[IRC](../../auto-g16-recipes/cards/irc.md)。不复制诊断阶梯，不恢复类比 TS 原型或基准计算。

计划内的中间判断逐条写“待人确认”。仅对已有正式证据确认作业已结束且失败的对象，在计划与规则允许且无全局暂停条件时新建 Attempt 补救；原 Attempt 不重提、不复用声明。同对象同失败最多两次，每次一个最小改动并复验，改标签/猜测不清零。运行中、UNKNOWN、仅解析失败或取消/改投后继都不能进入这条补救路径。

TS 极小点、方向错误须先走最终组合的科学失败证据入口；方法、积分网格、机理变化和结构/代表集合/最终结果签字仍请人，不放宽最终 Opt/Freq 收敛。

路由选择必须与计划及规则绑定。SCNet 四个活跃自主作业和兜底两个排队自主作业按本机全部 study/轮次合计；旧轮、UNKNOWN 和未观测预留保留，账号核数仍包含手动作业。CREST/xTB 沿用[现行建议顺序](../SKILL.md)，同时受实际统一额度约束；分散空闲核不能拼成 default 的 44 核单节点候选。

预算按实际提交消费，prepare 来源和旧意图不另扣。逐 Attempt 保存[完整摘要](confirmation-summary.md)、方法依据、输入/bundle 哈希及授权来源，上传后再校验。放宽输入仅在计划、规则、实现和验证均允许时使用，逐次提醒跳过项及“方法口径未核验”，不把可提交当科学支持。

## 5. 保存、暂停与结束

90% 预算、规则到期、计划/版本失效、UNKNOWN、哈希不符、取消不确定按正式接口暂停。跨 wake 连续两次 SSH 失败/过期监控快照，或同 wake 达到三个不同对象同类失败，由模型按证据计数并调用正式 pause；这是卡片判断，不是内核自动聚合。每次保留当前及前次不同 wake 的 ID、观察结果（含成功）、来源文件/哈希、对象、失败类别与理由，通过 update 保存、下次 status 恢复；同对象重复报错不增加对象数。首次失败/过期已阻断依赖动作，成功观察才可据实中断连续失败；来源缺失或无法确认连续性就交人，不推定恢复。

有变化才通过正式 update 保存 `summary`、`pending`、`objects`；它整体替换这三项，先保留仍有效的对象与待办，不能只送变化片段而丢掉旧分支。这些文本不替代真实消费或失败证据。简报控制在一页以内，只写完成了什么、卡在哪里、要负责人决定什么；取消/改投需求的 Mac 点击提醒置于第一行，放宽输入及全部待确认判断也须列明。详细证据放私有归档并给链接，无变化不发简报。

不直接编辑自主 state/journal。study.md 只能由唯一 owner 经已实现的受保护写入口更新；缺入口时把待写内容留在正式状态并列缺口，不能用文本编辑器旁路。目标量齐但未签字时暂停推进，列待签里程碑，不宣称 study 完成。正常 finish 释放本次租约，不取消作业；只有明确结束本轮才 end。实际定时任务与时刻另属 T198 运维授权。
