# 不确定状态与失败

模式边界与暂停/补救权限以 [AGENTS](../../../AGENTS.md#自主运行)为准。当前工具仍按手动流程执行；自主前提未就绪时不得套用未来例外。

| 状态 | 含义 | LLM 下一步 |
|---|---|---|
| `unknown` / `UNKNOWN` | 提交期间断连、超时或响应无法解析，无法确定是否已产生作业 | 立即报告并停止；不能把“没看到作业”当作未提交，也不能 prepare 替代提交来规避不确定性 |
| `failed_presubmit` | ag 判定未成功提交，例如远程目录已存在、上传校验失败、提交程序明确报错 | 报告具体原因并保留 Attempt，原 Attempt 不再提交；哈希不符/状态损坏先暂停，其他明确失败才按适用模式处理 |
| 计算 error / incomplete 或结果不合格 | 已有输出显示失败、截断、未收敛或不满足科学判据 | 按 `failure-diagnosis` 审阅；先核实结束和失败证据，手动模式等人确认新方案，已启用自主模式仅按 AGENTS 有界补救 |

报告包含 Attempt、已记录的作业号（如有）、当前状态、最后成功动作、错误和待确定事项。不要改写状态、重传、清理或运行恢复操作。

`ag status` 的实现可以只读核对不确定提交：找到确切证据时更新为 `submitted`，找不到则保持 `unknown`。手动模式出现意外后先报告，等待人要求只读核对；已启用自主模式按 AGENTS 暂停后由唯一持锁会话只读核对。核对不授权重提或自动恢复自主运行。

排队是正常状态，不能仅因等待就另建同一计算；未来自主改投仅按 AGENTS 例外核验。手动模式或开发会话遇 SSH 报错、校验不一致或作业异常结束先停止报告；自主运行按 AGENTS 的暂停条件处理，不能把失败的查询当作无作业。当前取消仍走 `ag cancel` 系统对话框，未来自主取消例外不得用于手动提交的作业；任何取消都不授权删除数据。
