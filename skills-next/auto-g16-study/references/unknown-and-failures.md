# 不确定状态与失败

| 状态 | 含义 | LLM 下一步 |
|---|---|---|
| `unknown` / `UNKNOWN` | 提交期间断连、超时或响应无法解析，无法确定是否已产生作业 | 立即报告并停止；不能把“没看到作业”当作未提交，也不能 prepare 替代提交来规避不确定性 |
| `failed_presubmit` | ag 判定未成功提交，例如远程目录已存在、上传校验失败、提交程序明确报错 | 报告具体原因与现有证据，保留 Attempt，等待人决定；该 Attempt 不能再次提交 |
| 计算 error / incomplete 或结果不合格 | 已有输出显示失败、截断、未收敛或不满足科学判据 | 停下报告，按 `failure-diagnosis` 卡片审阅已有事实，提出新 Attempt 的修改方案，等人确认 |

报告包含 Attempt、已记录的作业号（如有）、当前状态、最后成功动作、错误和待确定事项。不要改写状态、重传、清理或运行恢复操作。

`ag status` 的实现可以只读核对不确定提交：找到确切证据时更新为 `submitted`，找不到则保持 `unknown`。这不是 Skill 自动恢复指令；出现上述意外后，先报告，等待人要求只读核对再调用。核对仍不得重提原 Attempt。

排队是正常状态，不因等待而另建同一计算。SSH 报错、校验不一致或作业异常结束也必须先停止报告。取消只走 `ag cancel` 的系统对话框，与重做或删除数据不是同一动作。
