# V31 接入前的本地工作台

本地候选 0.26.0+local.1。已有源码基线为 2ddb755；新增功能在独立 `codex/pre-v31-workbench` 分支开发。原始科学数据库、Gaussian 日志、解析结果和科学审批不由新增功能改写。

## 功能与使用

- **新计算草稿**：单帧 XYZ、普通笛卡尔 GJF/COM、单分子 SDF/MOL V2000。支持 Opt、Opt+Freq、SP；所有方法、基组、环境、电荷、多重度及资源由用户填写。检查电子数/多重度奇偶、坐标、范围、关键词冲突。SDF 仅提取坐标，不解释键级或自动生成 3D；混合基组/ECP、Z-matrix、多 Link1 输入需单独准备。生成完整 GJF，walltime 只保存为资源声明，不生成 PBS。
- **结果比较**：在初筛页勾选至少两个候选，展开相同组成、方法、基组、环境、电荷、多重度、色散及 G 的温度/压力对照。多步骤但没有结果能量绑定时条件保留未知；记录冲突阻断相对能量。缺失项要求人工核对说明。比较仅限所选集合，最低值为零，不自动计算反应能或能垒。
- **修复预览**：计算详情的报错/轨迹区导入原 GJF/COM，核对诊断来源，预览 SCF XQC/MaxCycle 或 Opt MaxCycle 差异。可主动选用当前完整优化分段的最后几何；原子顺序不一致时拒绝。保存独立修复提案，可导出 GJF。采集/解析失败不自动触发重算。
- **IRC**：导入 `autog-irc-trajectory/1` JSON 或注释包含显式元数据的多帧 XYZ。界面提供格式示例；显示分支能量曲线，选择点同步结构，支持 XYZ、CSV、独立 SVG 导出。缺步、重号、非有限数、单位或原子序列变化被拒绝。当前不直接解析任意 Gaussian IRC log，须从已核对来源转换为该格式；不会把优化轨迹冒充 IRC。人工端点标签不授予双向终止/端点验证。
- **GoodVibes 与比例**：导入单一条件的文本表或简单 CSV，保留 G(T)/qh-G(T)/SPC 等明确列。拒绝多表、重复名称、错误标记、缺列和非有限值。用户核对原表温度、方法、组成、电子态、标准态、校正与去重后，对勾选集合计算 Boltzmann 比例。不给已有自由能换温度重算，不额外乘隐含自旋/简并因子。
- **来源与报告**：结果详情导出 XYZ、能量 CSV、包含原始证据的 Markdown 报告及 JSON；可以追加人工父计算/输入版本关联，明确为未核实人工声明。原生 Core 父链与独立人工谱系分开。
- **能力与版本**：展示本机实际启用的监控、库、队列、人工模式确认及执行提供方；V31 DAG 仍未接入，执行 provider 未配置时不提供真实提交。

## 本地记录

草稿、修复提案和人工谱系使用同源 IndexedDB 独立存储。只有点击保存才追加有 UUID、浏览器生成的 UTC 时间（非认证服务器时间）、父版本、理由、输入/来源摘要及整条记录摘要的新记录；不覆盖旧版本。恢复笔记包校验摘要、重复 ID 冲突、父记录存在与循环，单个事务全成或全败。摘要用于内容一致性，不代表认证签名。

换端口/浏览器或清除网站数据不会自动迁移这些记录；通过“导出全部笔记包/恢复笔记包”转移。JSON、CSV、GJF、XYZ 和 SVG 均由浏览器下载，不发送第三方。CSV 对字符串公式前缀进行转义。所有新功能的业务数据写入止于浏览器本地；原服务已有的本地归档、队列和模式确认保留其原独立边界。

## 计算依据

GoodVibes 表列和 Hartree 单位按 [项目官方文档](https://github.com/patonlab/GoodVibes) 的单表格式读取，不重新实施准谐振校正。相对能量换算沿用现有工作台 627.509474 kcal/mol/Eh；Boltzmann 使用 R=8.31446261815324 J/mol/K、1 Eh=2625499.6394799 J/mol，并先减最小 G 保持数值稳定。

## 安装与回退

交付使用新隔离虚拟环境、已构建静态资产、18 包离线哈希锁和源码/wheel 回执。统一入口保留原生数据及本地库设置，补充轨迹 profile；原安装、启动器备份和原 profile 保留。原始日志和 Core 不迁移。

在本机切换前，记录现有库 profile 指针与来源文件指纹；切换仅更新本地库展示 profile 指针与启动器。回退时使用记录的旧 profile 和旧安装启动器，不删除草稿、科学文件或版本。
