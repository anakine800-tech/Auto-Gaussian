## Scope and non-authority

This milestone adds one narrow, non-executable consumer of the existing
`direct_root_owner_contract` capability. It models the check-to-use handoff
with a fixed in-memory synthetic helper. It does not implement SSH, remote
filesystem access, transfer, PBS, Gaussian, qsub, qdel, deployment, a live
smoke, or an arbitrary command/argv/callback surface.
It adds no direct runtime and does not claim backend support.

The existing profile-policy, stable root evidence, execution-profile `/3`,
execution-authorization `/3`, fresh receipt, and single-use descriptor
capability remain owned by `direct_root_owner_contract`. This milestone does
not copy their validators or turn a portable document into authority.

The additive W4 successor `direct_root_fixed_mutation_consumer` now closes the
previously separate physical-helper gap without changing this historical
synthetic contract: it consumes only W1 `posix_nofollow` capabilities and
passes their exact FD chain with `SCM_RIGHTS` to a fixed exec helper. See
`v2.7-direct-root-fixed-mutation-helper.md`. That successor does not turn this
synthetic transaction into production authority and does not close W2,
transport, replay-ingress, submission, inspect/fetch, or live-evidence gaps.

The existing `platform_contracts init/validate/doctor` surface remains
execution-profile `/1` only. It is not direct onboarding and this milestone
does not import or call it. Historical profile/authorization `/1` and `/2`
objects remain historical SDL-only inputs to their existing owners; they are
never migrated, rehashed, backfilled or treated as `/3`. A direct `/3`
authorization remains `live_ready=false`. Unknown, missing or unsupported
schema versions and every fallback attempt are rejected rather than routed.

## Fixed synthetic transaction

The helper accepts exactly the owner-retained opaque handle tuple plus these
symbolic, non-path operations in order:

1. `create_project_directory_exclusive` with relative label `project`;
2. `create_scratch_directory_exclusive` with relative labels `project`,
   `scratch`.

Both operations are no-follow, create-exclusive, non-overwriting and
non-deleting. The helper records only an in-memory trace. It cannot accept a
pathname, command, argv, payload, shell fragment, transport, executor or
caller callback. The result is a closed, hash-bound audit projection with
`synthetic_only=true` and `remote_effect_performed=false`; it is not a
capability. The receipt, JSON, hash, result and every synthetic object are
audit/test evidence only and are never filesystem authority.

## Production blockers

Production remains blocked until a separately reviewed owner supplies all of:

1. a real backend-owned no-follow identity observer that issues the existing
   fresh receipt and descriptor/capability for actual server objects;
2. a process-isolated fixed production helper that consumes those exact
   descriptors and implements create-exclusively without reopening paths;
3. durable cross-process single-use consumption and uncertain-outcome state;
4. exact direct-compatible composition of the existing scientific, resource,
   live-approval, idempotency and lifecycle owners; and
5. separately authorized L3 and live-smoke evidence.

No offline pass grants any of those authorities.
