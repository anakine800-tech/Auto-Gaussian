# Auto-G16 v2.7 direct fetch acquisition and closed stream seam

Status: offline synthetic/fake authority only. The descriptor-relative reader,
exact-five direct streaming session and T4 manifest-last transition are
implemented and hostile-tested. Production integration remains blocked on the separately
reviewed Q1 backend-owned read-authority exact type. No raw read profile,
caller job ID or portable projection is a production authority.

## Owner and call chain

The server transition starts with the exact live
`DirectSubmittedJobReadLease`. L1 terminalizes that lease and invokes only the
canonical `direct_fetch_acquisition` successor; it never returns the retained
project or lineage descriptors to its caller. The successor replays the full
L1 descriptor currentness and binds the W2/W5 journal, project, attempt, job,
authorization, profile, receipt and result lineage.

The current read-profile and generic T0 operation inputs are reachable only
through underscore-prefixed test-token paths. Their projections state
`production_stream_seam=false` and name
`Q1_backend_owned_reviewed_read_authority_exact_type` as the required
predecessor. A future successor must consume that exact Q1 authority; it may
not promote these fake issuers or a future type name into authorization.
The raw-profile owner creation, L1 handoff and F1 acceptance steps each require
the same exact module-private test token; a caller-provided token fails before
the L1 lease is consumed.

## Fixed terminal-minimum bundle

Only the T4-owned ordered allowlist is accepted:

1. `approved-input.gjf`;
2. `auto-g16-job.pbs`;
3. `checksums.sha256`;
4. `submission-receipt.json`;
5. `approved-input.log`.

Each entry is opened relative to the retained project FD with `O_NOFOLLOW` and
`O_CLOEXEC` after a non-following type check. It must be a single-link private
regular file owned by the project owner/group with mode `0600`. The owner binds
the file descriptor/named-entry identity, cap, size and SHA-256, then replays
all of them while reading from the same FD under one monotonic deadline.
Symlinks, directories, FIFO/socket/device entries, hard links, owner/mode
drift, descriptor reuse, replacement, truncation, growth or hash drift fail
closed.

The binary bundle contains one canonical bounded header followed by exactly
five length-delimited payloads in fixed order and exact EOF. Before emitting
the outer header, the server makes a descriptor-bound incremental prepass and
binds the complete bundle SHA-256. It then rereads the same still-current FDs
and emits fixed chunks under the same absolute deadline; it never constructs a
whole bundle or response. The shared T0 owner retains the read FD and exposes
only one exact sequential session to F1. The reviewed maximum encoded wire
size is 1,092,943,959 bytes: the exact 1,091,895,296-byte five-file payload cap
plus the 1 MiB inner-header cap and fixed framing. An outer chunk is at most
4 MiB; T4 pulls at most 1 MiB at a time. Partial, malformed, oversized,
reordered, extra or second material is terminal and never retried.

The old whole-response helpers are small-fixture tests only. Both require an
exact module-private token before consuming an operation or capability, are
underscore-prefixed and absent from `__all__`, and impose an independent 2 MiB
hard cap. The direct session path has no `bytearray(total)`, payload `join`,
temporary spool or whole-file read fallback.

## T4 transition and authority boundary

After exact outer header and inner metadata validation, the controller-side closed stream
capability is nonconstructible, noncopyable, nonserializable, PID/epoch/private-
registry bound, fork-revoked and single-use. It binds the L1 projection/result,
W2/W5 identifiers, target binding, read profile, transport operation, source
snapshots, file identities/sizes/hashes and bundle hash. Its portable
projection cannot recreate the stream.

Consuming it issues one distinct sequential reader capability; it does not
return payload bytes, a caller callback, a raw FD or a portable reconstruction.
F1 alone consumes the channel session, checks each encoded length,
incrementally rehashes each file, preserves fixed order, and finally checks the
trailer hash and exact EOF. T4 alone owns destination creation and writes each
supplied chunk through its existing descriptor-relative no-clobber path.

Descriptor-bearing server records, channel sessions, controller closed-stream
records and sequential reader records are
kept in separate closure-private registries. They store canonical projection
or profile bytes, immutable scalars/tuples and a commitment over every field;
currentness reparses and replays the commitment, full authority, capability
identity, file metadata and, on the server, descriptor identities and
deadline. There is no live-record accessor or replaceable module-global
registry. Mutating a portable projection cannot change registered authority or
file commitments.

Registry commitments are incremental and resource-bounded. They length-prefix
fixed canonical metadata and update raw owner fields directly; controller file
payloads are represented only by fixed basename/order/cap/size/SHA-256
metadata while bytes remain in the sequential channel session. Neither
commitment uses `repr`, concatenates raw payloads or canonicalizes a payload.
Projection and assertion return only fresh metadata copies. The T4 transition
transfers only the exact reader capability, not payload-sized references.

Starting a response atomically terminalizes the server capability before the
request is parsed. Malformed requests, expired deadlines, descriptor drift,
read failure and explicit abandonment all close the retained descriptors and
make every second request fail; none enters a retry path. Module binding uses a
direct fail-closed guard frozen inside both registries; it does not use the
replaceable `_require` helper to prove itself. It binds canonical/hash/schema,
descriptor/read/currentness helpers, relevant OS primitives, constants and
source identities before those transitions.

T4 accepts only that exact capability and revalidates its complete owner,
record and authority projection for the new closed-stream transition,
creates its own exact stream lease, and then uses the existing repository-
external descriptor-relative no-clobber materializer. It writes the manifest
only after all five same-FD file checks and the F1/channel trailer-plus-EOF
terminal transition succeed. A mid-file disconnect, missing trailer, extra
bytes or second frame leaves the unique directory and partial/complete files
for audit but leaves no manifest; no deletion or retry follows. The older
synthetic issuer remains explicitly test-only. The production path is issued
only by the exact terminal-grant controller join, runs through the fixed read
subsystem, and can join only the fixed production local-target owner. Its
`production_integration=true` evidence is non-authorizing and cannot be
reconstructed from portable bytes.

This in-process Python slice does not claim isolation from arbitrary
same-process reflection or native-memory access. Production composition must
keep that disclosure false and place Q1 issuance plus this fixed transition in
the separately reviewed clean-exec boundary; portable bytes and a future type
name cannot close that boundary.

F1 contains no independent SSH owner, qstat implementation, qsub, qdel,
cancel, retry, overwrite, delete, cleanup, advanced inspection, Gaussian
execution or scientific acceptance; it reuses the shared fixed SSH channel.
Tests and pressure evidence are offline. A
commit, merge, package or deployment plan does not authorize any live action.
