## CLI and import map

The historical `gaussian_rtwin_pbs.py` subcommands, options and argparse action
semantics remain byte-characterized by the PR1 golden. Imports used by
`gaussian_auto.py` and `gaussian_workflow.py` bind a facade view. Reaction
workflow and historical validator imports continue through the compatibility
module. Executable wrapper dispatch is always:

```text
gaussian_rtwin_pbs.py -> execution_facade -> LegacyRTWinPBSBackend
gaussian_auto.py      -> bound execution_facade -> compatibility CLI child
```

There is no `--backend`, backend environment variable, OS selection, fallback
or mutable module/engine selector. The facade always imports
`legacy_rtwin_pbs`; its public parser and main entry points accept no backend
module argument. The old implementation exists only as
the source history used by the offline differential; the final repository tree
contains one execution implementation owner.

reconciliation. The owner never accepts a caller-provided registry.

## PR4A / PR4B boundary

PR4A owns the backend-neutral contracts, sealed models, fixed workspace/runtime/
renderer behavior, legacy implementation extraction, compatibility wrappers and
trusted local authorization-state primitive. It does not own an operational
Stage A/Stage B connection. The typed boundary therefore has `executable=false`,
`network_performed=false` and `automatic_retry=false`. A PR3 successor is
decoded no-follow and replayed by the strict PR3 owner; only then may its exact
time window, read-only effects, profile and workspace bindings be sealed into
PR4A models. It still stops at `transport_integration_required` before staging,
reservation, authorization consumption or any external mutation. This is a
named dependency boundary, not live evidence.

The trusted state owner is implemented and covered by ordinary synthetic
concurrency and crash-stability tests, but is intentionally not wired into
production dispatch in PR4A. Production dispatch performs successor-document
validation only; it does not claim full PR3 current-state closure.

PR4B must start from the exact frozen PR4A commit on the unique branch
`codex/v26-legacy-transport-integration`. It owns PR3 current-state replay,
typed Stage A/B receipts, binding comparison, atomic consumption/reservation and
the first external-operation handoff. PR4A must not be merged independently
into `codex/v26-integration`. Complete PR4 still requires PR4B L3 review and a
separately authorized exact live smoke; PR4A offline evidence is neither.

## Migration and rollback

No historical artifact is rewritten, migrated or rehashed. New submission is
successor-only; historical validators remain available for replay. Rollback is
a reviewed revert of the wrapper/facade/backend extraction and new tests/docs.
It does not delete local uncertain records, alter server state, select a hidden
old engine or clean any remote data.
