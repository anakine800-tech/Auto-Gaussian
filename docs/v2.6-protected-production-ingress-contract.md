# Auto-G16 v2.6 protected production ingress contract

## Decision and boundary

`auto-g16-protected-production-ingress-contract/1` is the additive,
effect-free successor after the protected owner-consumer contract. Its single
owner accepts only one exact current
`SealedProtectedOwnerConsumerContract`, claims the already sealed
`ProtectedLegacyEffectPlanInputs` once, snapshots those owner-derived values,
and issues one `SealedProtectedProductionIngressCapability`. That capability
may expose one `ProtectedLegacyEffectPlanFactoryPort`.

This task does not wire production `_submit_new()`, change the legacy facade,
change the raw effect owner, or add a legacy factory consumer. It never reads
caller paths or runtime configuration, stages, reserves, writes, consumes
runtime state again, constructs `_LegacyTransactionPlan`,
`_LegacyEffectPlan` or `_LegacyRawEffectOwner`, calls a factory, adapter,
runner or transport, or performs any external effect.

## Exact gap, ownership and call-chain matrix

| Surface | Existing exact owner and current fact | Successor contract |
| --- | --- | --- |
| Production submit ingress | `execution_facade.LegacyCLICompatibilityAdapter._submit_new` recognizes successor transport authority and stops at `transport_integration_required`; it accepts no runtime or owner-consumer capability | Bind its exact module, class, method and source as the sole designated future production consumer; record `production_submit_wired=false` |
| Effect-ready local bytes | `protected_owner_consumer_contract` owns the sibling upload bundle, successor intent, replacement checksum bytes and durable uncertain receipt | Accept only its exact sealed type; replay current bytes and receipt, then claim its plan inputs once; never restage or re-reserve |
| Legacy effect-plan factory | `legacy_rtwin_pbs._legacy_effect_plan_from_transaction` is the sole current factory and accepts only CLI-owned `_LegacyTransactionPlan` | Bind its exact module, function, transaction/plan/raw-owner types and source; issue a non-executable port and record `current_factory_accepts_port=false` and `factory_invoked=false` |
| Raw effect owner | The exact legacy module privately creates and registers `_LegacyRawEffectOwner` from one factory-issued plan | Keep the implementation and source bytes frozen; never construct or invoke it |
| Receipt ordering | The predecessor already persisted `effect_started_outcome_uncertain` before it issued plan inputs | Require and replay that exact latest receipt before ingress and before factory-port claim; perform no journal write |
| Remaining production slice | No safe legacy-internal consumer of the new port exists, and `_submit_new()` has no ingress parameter | A later separately reviewed change must add the exact legacy-internal port consumer and production wiring without restoring caller authority; this contract does neither |

The implemented call chain stops after the first two effect-free capabilities:

1. a future production submit receives the owner-issued ingress capability;
2. ingress replays the exact predecessor and uncertain receipt;
3. the exact legacy module consumes the factory port once;
4. that module constructs one effect plan as sole owner;
5. that module claims one raw effect owner; and
6. that module enters one bounded effect lifecycle.

Steps 3–6 remain unimplemented and are not authorized by Schema validity or
by this contract.

## Capability and snapshot rules

The owner claims `ProtectedLegacyEffectPlanInputs` exactly once. It does not
read the original CLI namespace, runtime config, local path arguments or any
approval path. Its private snapshot contains only the 13 already sealed
effect-plan fields:

```text
project, windows_dir, remote_dir, files, expected_bindings,
upload_timeout_seconds, upload_hash_timeout_seconds, attempt_id, input_sha256,
mac_ssh_config, rtwin_alias, windows_server_config, server_alias
```

The public projection exposes basenames, ordered digests, finite timeouts,
project/attempt/input identity, the fixed remote directory and hashes of
private path/alias values. The sealed ingress and factory port retain isolated
immutable tuples. Both reject copy, deepcopy and pickle. One private lock
makes ingress-owner use single-shot; a second private lock makes factory-port
claim deterministically single-shot under concurrency.

The predecessor contract, intent and replacement checksum digests are all
bound independently. A predecessor/intent/checksum splice therefore fails
semantic replay even when the document remains structurally valid.

## Exact identity and threat-model limit

Before predecessor claim, the new owner verifies:

- its canonical module, classes, source identity and source bytes;
- the owner-consumer module, sealed/plan-input classes, registration and
  source bytes;
- the production facade module, compatibility-adapter class, `_submit_new`
  function identity and source bytes; and
- the legacy module, transaction/plan/raw-owner classes, both private factory
  functions and source bytes.

Foreign identical modules or classes, wrong import order, pre-call canonical
cache replacement and pre-call source drift fail before the predecessor plan
input is claimed. The machine-readable policy explicitly records
`post_check_direct_sys_modules_mutation_protected=false`. An arbitrary
uncooperative same-process mutation after the last check remains outside this
Python capability boundary and requires a future process-isolation design.

## Validation layers and remaining gate

Draft 2020-12 validation proves structural acceptance only. The public helper
also checks fixed booleans, hashes, ordering, cross-field identity and
deterministic IDs. Only the exact canonical owner replays live in-process
types, sources, predecessor bytes, receipt state and the single-use claim,
then issues the seal. `schema_valid_is_sealed=false` is mandatory.

The legacy source, facade source, predecessor Schema/fixture, upload bytes,
submission intent, replacement checksum bytes and predecessor hash chain are
frozen. This successor extends the chain with one new owner module, one
Schema, one fixture, offline tests and repository/deployment-package
documentation. It does not synchronize the deployed Skill copy.
