## Scope

PR6A adds only closed portable contracts, owner validators and an in-process
single-use descriptor-capability model for a future `direct_ssh_pbs` backend.
It does not implement or call SSH, PBS, Gaussian, transfer, staging, submit,
fetch, cancellation, cleanup, deployment or another external effect. It does
not make the direct backend live-ready.

Historical schemas, fixtures and legacy/protected owners remain unchanged.
The repository-owned source is
`scripts/direct_root_owner_contract.py`; the deployment successor maps that
exact source, `contracts/direct-execution` schemas and this reference through
`config/deployment-package-supplements/auto-g16-rtwin-pbs/direct-root-owner.json`.
The compatibility package API and frozen historical
`deployment-package.json` retain their exact prior file set, so no predecessor
bytes or validator are copied or changed.

## Portable integer encoding

Draft 2020-12 defines JSON numeric integers mathematically, so validators such
as `jsonschema` correctly treat `1.0` as an integer. The owner intentionally
rejects every float to preserve one canonical byte representation. Therefore
the eight public ordinal/count/duration positions use canonical decimal
strings: `0` is allowed only for component ordinals; positive quantities have
no sign, decimal point or leading zero; receipt age is additionally bounded to
`1..300`. Owner builders accept exact Python integers but publish and hash only
those canonical strings. Both public Schema and owner reject numeric integers,
integral floats and non-canonical decimal strings at those positions.

## Artifact chain

1. The owner builds a closed direct profile-policy core. Its payload hash
   covers the root-policy owner version/source, exact declared root, transport,
   runtime and resource-catalog digests, normalization/containment versions and
   all safety markers.
2. Stable evidence binds that exact policy-core hash and the expected canonical
   root/component identity chain. Its projection contains no fresh values.
3. Execution profile `/3` binds the policy-core hash and stable-evidence hash.
4. Authorization `/3` binds the final profile, stable evidence, exact root,
   workspace, input, resources, operation/task/attempt/idempotency scope and
   fresh-observation rules.
5. Immediately before a future first mutation, the same owner must create the
   fresh receipt and an exact non-copyable capability for the same retained
   component identities.
6. PR6A stops after offline capability consumption returns a sealed lease with
   `remote_effect_authorized=false`. It has no method that can perform an
   effect.

## Security and compatibility limits

The Python model rejects pre-call canonical-module replacement, foreign
same-name modules/classes, source drift, forged seals, portable-receipt
substitution, cross-profile/root/workspace reuse, expiry, clock rollback,
capability-field reset and concurrent double consumption. Consumption, clock
and authoritative snapshots are absent from capability slots and retained by a
module-owner registry. This prevents `object.__setattr__` on the capability
from reopening consumption or replacing its clock.

This is not protection against arbitrary code already executing inside the
owner module's process. Such code can introspect or mutate Python module
globals, the synthetic test clock provider, or `sys.modules` after a final
check. Production closure therefore needs process isolation or an
owner-controlled remote helper whose validation, durable consumption and
descriptor-relative mutation are one operation. PR6A does not claim that
missing boundary.

The private snapshot/test factory creates only opaque synthetic handle objects.
It is not a production ingress and cannot inspect a server. A future production
owner must not reuse it as an adapter.

## Validation contract

The candidate must pass:

- focused owner/validator and adversarial tests;
- Draft 2020-12 acceptance/rejection parity for all five new schemas on the
  pinned Python 3.11 and 3.13 environments;
- adjacent platform, execution-authorization, protected-owner and Skill
  packaging tests;
- static quality, Python contract and CI contract audits;
- final full offline suite on frozen bytes.

No passing result authorizes network access, live smoke, deployment, push,
merge or release. Production transport, server observation, durable
cross-process consumption and live compatibility remain named gaps.
