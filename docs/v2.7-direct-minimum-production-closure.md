# Auto-G16 v2.7 direct minimum production closure

This component defines the production owner chain for the minimum direct
workflow: one W5/W2 submission, explicit one-at-a-time exact Q1 queries, one
terminal-only F1 transition, and one T4 manifest-last local snapshot. The only
effectful submit entry is `submit_minimum_once(artifacts)`. The
read successor is
`resume_minimum_once(portable_receipt_bytes, artifacts)`; it
never calls qsub and has no
host, command, profile, job-ID, path, root, timeout, retry, cancel, or inspect
override. It does not add cancellation, qdel, advanced inspection, retry,
cleanup, deletion, Gaussian completion, or scientific acceptance.

The two explicit invocations are deliberately separate:

```python
import direct_minimum_production_closure as minimum

receipt_bytes = minimum.submit_minimum_once(reviewed_artifacts)

# Persist or pass these exact completed-receipt bytes. A later invocation
# performs one read transition only and can never route to qsub.
result = minimum.resume_minimum_once(
    receipt_bytes,
    reviewed_artifacts,
)
```

`submission_uncertain` has no completed receipt to encode and therefore
cannot enter the read invocation. It remains reconciliation-only and never
authorizes a second submission.

## Exact owner chain

1. W5 and W2 remain the sole owners of the one qsub outcome and durable
   completed journal. L1 revalidates that exact receipt/journal/project
   lineage before Q1.
2. Q1 consumes its exact acquisition into a private-registry
   `GaussianJobInspection3`. The final inspection is PID/process-epoch bound,
   nonconstructible, noncopyable, nonserializable, fork-revoked, and terminal
   after its only successor handoff.
3. `direct_minimum_production_closure` consumes that exact object. It issues a
   single-use terminal fetch grant only for fresh `present` evidence with PBS
   state `C` or `F`, or fresh exact `absent` evidence. `Q`, `R`, `H`, `E`,
   unknown, malformed, timed-out, and stale evidence issue no grant.
4. The grant binds the exact W5 result, W2 journal, L1 lineage, authorization,
   transport profile, Q1 acquisition, final inspection and source identities.
   Its portable projection explicitly grants no authority. Consuming the
   private grant requires the exact canonical W5 receipt bytes, exact server
   artifact object, and a fresh exact reviewed read-profile capability. It
   can create only one fixed F1 fetch operation.
5. The fixed read subsystem reads one complete canonical request plus EOF and
   dispatches a closed union of exactly Q1 qstat or F1 terminal fetch. The
   fetch request carries bounded canonical portable W5 receipt and reviewed
   artifacts as evidence inputs; the clean-exec server process reissues the
   exact reviewed read profile and L1 capability. A private PID/epoch-bound,
   fork-revoked single-use dispatch budget binds the exact request frame and
   operation; Q1/F1 can only shorten its one absolute deadline and cannot
   reset it. No capability is serialized.
6. F1 remains the sole descriptor-relative five-file reader and bounded stream
   codec. Immediately before opening the five artifacts, the server clean-exec
   process reuses Q1 to acquire fresh terminal/absent scheduler eligibility for
   the exact L1 job. The controller grant hash is only a splice commitment and
   is never server authority. The first file pass binds exact per-file
   identity/size/hash metadata; the second pass streams bytes once. The header
   commits metadata, while the trailer carries the actual streamed bundle
   hash. T4 remains the sole local creator/writer and retains a partial unique
   leaf on any failure; it writes no manifest unless all five files and the
   stream trailer are exact and durable.

One L1 capability can still choose only one immediate successor. An unknown or
stale query returns `query_unknown`; a fresh Q/R/H/E query returns
`query_nonterminal`. Both carry
`this_call_qsub_calls=0` and
`explicit_future_query_required=true`. A later explicit
call consumes the same canonical completed receipt and performs only another
read; it never routes back through submit. Query and
fetch use separate clean-exec server-local revalidation sessions; capabilities
are never serialized or reconstructed. A restart starts a fresh query from
the exact W5/W2 artifacts. It never resumes or upgrades a portable query or
grant projection.

## Fixed local target policy

The production target owner has no arguments and reads only:

`/Library/Application Support/Auto-G16/direct-local-fetch-target-v1.json`

The canonical policy fixes a reviewed repo-external target root. The owner
opens `/` and traverses every policy ancestor descriptor-relatively with
`O_DIRECTORY|O_NOFOLLOW`, requires root-owned non-group/world-writable
ancestors, then opens the capped policy leaf with `O_NOFOLLOW`. It requires a
root-owned single-link regular file, replays descriptor identity and canonical
bytes, and then opens the target root component by component with no-follow.
Neither CLI, environment, runtime configuration, caller bytes, job data, nor
portable projections can select or replace the policy path or target root.
The target capability creates one owner-derived fresh empty leaf, never
overwrites, and has no delete/cleanup/retry API.

## Offline evidence and remaining operational gates

The adversarial suite covers the real owner transitions, rich request codec,
closed-union dispatcher, fixed channel state machines and production API
surface using only synthetic scheduler bytes, fake descriptors and local
temporary directories. The fake-descriptor end-to-end case is test evidence,
not a production transport claim. It proves one pre-existing qsub receipt,
terminal Q1 classification, one F1 bounded stream, and a T4 five-file
manifest-last snapshot. It also proves zero fetch for nonterminal, unknown or
stale states and rejects object forgery, copy, pickle, fork use, second use,
request truncation/extra bytes and receipt/profile splicing.

This is not live-readiness evidence. The fixed dispatcher must be installed as
the reviewed `auto-g16-direct-one-hop-read-v1` server subsystem, the root-owned
fixed production target policy must exist, named-Skill deployment requires a
separate decision, and real SSH/PBS/qstat/fetch requires a separately
authorized live smoke. No test or commit authorizes those actions. A
nonterminal result stops after the one query; there is no polling or automatic
retry. Cancel and advanced inspect remain deferred.
