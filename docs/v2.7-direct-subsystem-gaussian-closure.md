# Auto-G16 v2.7 fixed subsystem and Gaussian identity closure

This additive repository contract closes two Phase 1A gaps only. It does not
install a package, modify sshd, connect to SSH/PBS, submit Gaussian, select a
scientific method, retry, cancel, fetch, delete, clean up, or grant live use.

## Owners and order

The source-inventory bootstrap is the sole selector of either the reviewed
repository layout or the pure `auto-g16-rtwin-pbs` named-package layout. A
partial, dual, symlinked, hash-drifted, or preloaded-module shape stops before
the submit W2 journal or any read dispatcher. The submit entry has empty argv
and calls only `direct_one_hop_transport.server_subsystem_once()`. The read
entry also has empty argv and calls only the fixed read dispatcher; it has no
qsub path. Entry import, reload, rebind, fork, or copied-function shapes fail
before the bootstrap. Both require Python `-I -S -B`, cwd `/`, and `LANG=C`,
`LC_ALL=C`.
For the repository layout, the bootstrap fixes the repository script-root set
to exactly `scripts/` and `skills/auto-g16-rtwin-pbs/scripts/`. The parent
directories reverse-derived from every inventory `repository_path` must equal
that binary set; a third root fails closed. Both roots are recursively scanned
by descriptor-relative no-follow traversal. Their exact regular-file map is
inventory-bound, and any symlink, special object, unbound extra source,
`__pycache__`, `.pyc`, or `.pyo` stops before a reviewed dependency executes.
Repository tests therefore use a newly staged, cache-free tree; ignored caches
in a developer worktree are neither trusted nor silently removed.

The W4B clean-exec entry does not make the package scripts directory a
`sys.path` first-import authority or repeat ordinary module selection. The
reviewed meta-loader remains ahead of the historical session bootstrap while
that bootstrap temporarily exposes its fixed dependency directories. The
parent passes the
reviewed bootstrap source and an already-open no-follow package-root
descriptor. The same bootstrap owner loads the complete submit dependency
closure from frozen inventory bytes, while a parent-frozen attestation binds
every module path, source SHA, and descriptor identity across `exec`. A forged
preload, valid `.pyc`, rehashed inventory, partial/dual layout, source change,
or same-byte ancestor copy is rejected before W2, file writes, or qsub.

The Gaussian runtime identity owner records one canonical absolute safe path,
nonzero SHA-256, uid/gid, exact executable mode, link count, and a no-follow
component identity chain. The direct profile hash, transport `/2`, reviewed
PBS `/2`, and the unique PBS execution line bind the same document. Immediately
before qsub, W5 replays the chain and final executable identity through already
open descriptor-relative components. The descriptor is then closed: it is not
claimed to survive qsub. The PBS contract therefore also requires an
administrator execution-time and post-install re-observation before physical
endpoint use.

The root/profile owner retains `build_profile_policy()` for historical and
general `/1` replay compatibility. The direct production successor uses the
currentness-bound `build_profile_policy_with_gaussian_runtime()` helper, which
derives the profile field from the validated Gaussian owner document rather
than accepting a caller-supplied derived hash. The production chain is exactly
profile policy `/2`, stable evidence `/2`, direct profile `/4`, and direct
authorization `/4`; W3, W4, W4B, and W5 each reject the valid historical
`/1,/1,/3,/3` chain before their mutation/effect seam. W5 then requires the
full Gaussian document and derived hash to equal the transport `/2` document
before the trusted session starts. Q1 and F1 independently reject a valid
transport `/1` before qstat/fetch capability use.

The reviewed PBS `/2` owner constructs one exact script from owner fields: a
fixed `#!/bin/sh`, `set -eu`, exact physical/project cwd checks, exact scratch
directory/no-symlink checks, and one final `exec <reviewed-absolute-gaussian>
approved-input.gjf` line. Any extra export, loader variable, comment, module
setup, wrapper, alternate invocation, or byte is a different script and is
rejected. This is exact-byte allowlisting, not a token blacklist.

Historical transport `/1` and reviewed PBS `/1` schemas remain unchanged and
have replay-only validators. New production submit/query/fetch issuance rejects
them before an effect. Raw JSON, a rehashed copy, PATH, environment, CLI,
caller path, shell wrapper, module setup, alternate argv, or cwd cannot select
the Gaussian executable.

Draft 2020-12 schemas close every locally expressible type, required field,
constant, nonzero SHA, canonical absolute Gaussian path, and nested structure.
JSON Schema does not mint cross-document authority and does not by itself
prove that a duplicated hash equals the embedded Gaussian document. Those
cross-field joins, canonical bytes, current source/function bindings, and
historical-generation rejection remain sole-owner runtime contracts with
hostile parity tests.

The hash graph deliberately avoids both cycles and self-authorization. The
source inventory and named-package projection use one bootstrap-fixed
exclusion set containing exactly the inventory itself, the bootstrap, and the
submit/read entrypoints. The bootstrap embeds and no-follow verifies the exact
inventory-file SHA; each entrypoint embeds the exact bootstrap SHA. The
inventory still binds every reviewed dependency source, the repository-scripts
projection binds every non-outer file in both fixed repository roots, and the
package projection binds every other package target. Neither inventory JSON
nor a caller can add a root or exclusion. Rehashing a dependency, its inventory
row, both projections, and the inventory self-hash therefore still fails at
the unchanged bootstrap anchor before dependency execution.

Phase C must externally bind all three outer code anchors, the inventory
bytes, and the full package projection as distinct provisioning inputs,
together with Python identity and the sshd fragment. Until that non-authorizing
manifest exists and an administrator independently re-observes the installed
objects, this repository closure is not a physical endpoint approval. None of
these repository files can self-mint apply, effect, or live authority.

## Provisioning boundary

`config/examples/auto-g16-direct-subsystems.conf.template` is sanitized and
contains unresolved package/Python tokens. It declares `authorizes_apply=false`
and must not be copied to a real sshd configuration. A later administrator must
obtain current no-follow identities for Python, package inventory, sshd bytes,
qsub, qstat, Gaussian, direct root, journal, root-owned read profile, and local
fetch policy; separately review installation and activation; and re-observe
all identities after installation. Repository acceptance is not physical
endpoint readiness.
