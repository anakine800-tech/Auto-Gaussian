## Ordering and receipts

The only permitted order is Stage A first-hop attestation, Stage B nested
hash-only identity-source attestation, then the second-hop host-key/identity
handshake. Each operation has a distinct nonce, an active at-most-five-minute
window, single attempt, zero retry and mutation disabled. The handshake receipt
binds the profile `/2` hash, two-hop identity binding, transport-config binding,
Stage A and Stage B receipt hashes, second-hop identity digest, observed
fingerprint-evidence digest, nonce/time/version and its canonical self-hash.

All owner functions are offline validators/builders. They import no network,
SSH, PBS, Gaussian, subprocess or command-construction surface. PR4A only
recognizes the successor and still stops at `transport_integration_required`;
full PR3 current-state replay, trusted consumption, Stage A/B execution,
handshake execution and receipt comparison remain PR4B work.

## Compatibility, migration and rollback

There is no automatic migration. A new submission needs newly reviewed `/2`
profile and authorization overlay artifacts. Historical `/1` artifacts remain
byte-for-byte replayable but gain no new authority. Rollback is a reviewed
revert of this additive owner, schemas, model recognition, tests and docs. It
does not delete artifacts, consumption/uncertain state or remote data.

Offline success is not live compatibility evidence. This patch must stop for
independent L3 review and does not authorize integration, PR4B resumption,
deployment, Skill synchronization, SSH, RTwin, PBS, Gaussian or live smoke.
