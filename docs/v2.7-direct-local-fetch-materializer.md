# Auto-G16 v2.7 repo-external direct local fetch materializer

## Status and authority

This T4 slice is the local owner/state machine, validated offline. It can prove that
exact synthetic bytes or one exact closed-acquisition sequential reader was
materialized safely in one new repository-external local
snapshot. It does not implement or authorize SSH, qstat, remote fetch,
cancellation, advanced inspection, Gaussian/PBS work, deployment, a live
smoke, retry, resume, overwrite, deletion, cleanup, or scientific acceptance.

The module-owned `offline_synthetic` stream issuer remains test-only. T4 also consumes the exact
single-use `ClosedDirectFetchStreamCapability` from the reviewed fetch
acquisition module and converts it to its own lease plus exact reader without
accepting raw bytes, dictionaries, caller FDs or callbacks. The production
variant requires both the fixed production target policy owner and the exact
terminal-grant F1 stream; offline and production authority shapes cannot be
cross-spliced. Portable bytes,
dictionaries, JSON, iterators, callbacks, paths or projections cannot
reconstruct that authority.

## Fixed artifact and cap contract

The only accepted basenames, in exact order, are:

1. `approved-input.gjf` — 16 MiB;
2. `auto-g16-job.pbs` — 1 MiB;
3. `checksums.sha256` — 64 KiB;
4. `submission-receipt.json` — 256 KiB;
5. `approved-input.log` — 1 GiB.

The file count is exactly five. The declared total is the exact sum of those
five sizes and cannot exceed 1,091,895,296 bytes. The maximum stream chunk is
1 MiB. Scheduler `.out`, checkpoint, scratch, optional, globbed, nested, and
all other names are excluded. Counts, orders, sizes, caps, PID and totals use
canonical decimal strings in portable artifacts.

## No-clobber write sequence

1. Replay exact module/type/source/private-registry/PID/epoch/capability/lease
   bindings and consume both capabilities once.
2. Recheck the retained target-root FD identity. Create only the owner-derived
   unpredictable leaf with descriptor-relative `mkdir`, mode `0700`.
3. Open that leaf with `O_DIRECTORY|O_NOFOLLOW`; compare the pre-open, opened,
   and descriptor-relative named identities.
4. In fixed order, create each file with
   `O_CREAT|O_EXCL|O_NOFOLLOW`, mode `0600`; perform full descriptor writes,
   enforce chunk/file/total limits, fsync, and verify size/hash/type/mode/link
   count and same-FD/named identity.
5. Fsync the directory after all five files. Require F1 to complete the exact
   trailer-hash and EOF transition, then build a closed canonical manifest with
   `authorizes_effect=false` and `scientific_acceptance=false`.
6. Create `direct-fetch-manifest.json` last with the same exclusive private
   file rules, write fully, fsync it, verify its identity, then fsync the
   directory again.

Any failure is terminal for both consumed capabilities. Existing objects,
symlinks, identity drift, FIFO/device/hardlink substitution, short/no-progress
writes, ENOSPC, disconnect, size/hash/order/count mismatch or fsync failure
stops. Partial content remains for audit and no manifest is written unless the
entire remote stream reaches its exact terminal transition. The module has no unlink, rmdir,
delete, cleanup, overwrite, rename-replace, resume, or retry implementation.

The module has no public production policy builder or policy-bytes/root owner
factory. Its underscore-prefixed builder exists only for offline fixtures.
`LocalFetchTargetOwner.production()` takes no arguments and reads only the
root-owned fixed policy at
`/Library/Application Support/Auto-G16/direct-local-fetch-target-v1.json`.
It cannot expose the root, final path, policy bytes, caller FD, environment
variable, or CLI override as a caller argument. Portable policy/schema
evidence always has `authorizes_effect=false`; its integration boolean records
which exact owner chain produced it but never recreates authority.

## Portable evidence boundary

The closed schemas are
`contracts/rtwin-pbs/direct-local-fetch-target-policy.schema.json` and
`contracts/rtwin-pbs/direct-fetch-manifest.schema.json` in the named-Skill
package. A valid manifest proves only that the fixed bytes passed the local
no-clobber and durability checks. Schema validity, hashes, portable stream
projection, and manifest bytes are never an in-process capability and cannot
be promoted into the future T3 lease.

## Validation and residual blockers

FD reuse/drift; existing directory/file/symlink; mkdir/open replacement;

consumption; manifest absence/partial retention; absence of delete/overwrite/
rename calls; copy, pickle, fork, reload, subclass and rebind rejection; real
Draft 2020-12 parity; packaging and static CI-contract audits.

The minimum Q1/F1/T4 production owner chain is implemented but only
offline-validated; deployment and live query/fetch remain blocked. This T4 candidate needs an
independent L3 review before a local commit. A commit, PR, CI pass, merge,
package or release does not authorize deployment or any live operation.
