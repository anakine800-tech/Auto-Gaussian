# Auto-G16 v2.7 fixed trusted server-local session composition

Status: W4B fixed clean-exec foundation; W5 successor present;
production closure false and live evidence absent

## Outcome and authority boundary

This seam composes the existing W1, resource, live-approval, W2, W3, and W4
owners inside one fixed clean-exec, trusted server-local process. The caller may
provide only the exact bytes of already reviewed, hash-bound portable source
artifacts. Those bytes are evidence inputs, never capability or effect
authority. The session accepts no module, command, path, root, environment,
callback, transport, backend, qsub, retry, cleanup, or fallback override.

The W5 successor is documented in `v2.7-direct-one-hop-transport.md`. It may
consume this lease only through the W4B-owned typed same-process seam. Its
presence does not change this readiness document's non-authorizing meaning or
delete W3's P3 reflection disclosure.

The portable readiness response is permanently non-authorizing:
`authorizes_effect=false`, `transport_connected=false`,
`backend_supported=false`, `live_ready=false`, `external_effects=0`,
`qsub_calls=0`, and `production_closure=false`.

The public session module owns its dependency bootstrap. A clean supported
interpreter needs only the repository `scripts` directory to import the
production entry. Before W2 or any session effect surface is loaded, the module
temporarily exposes only its owner-derived repository and named-Skill script
directories, loads the existing owner chain in one fixed order, and removes
those temporary entries. Every dependency is bound to a fixed canonical path,
full reviewed source SHA-256, inode metadata, exact module origin, and its
existing owner-chain currentness checks. Caller/test preload, path, environment,
command, and module selection are not inputs. Wrong-order or fake preloads fail
before W2 journal creation or session issuance. W2's narrow canonical W3
activation remains unchanged; the session executes or validates W3 from its
fixed reviewed source before asking W2 to bind the completed real owner.

The only production entry is
`compose_production_in_fixed_clean_exec_once(exact_artifact_bytes)`. It opens
owner-bound source descriptors and starts the owner-bound Python executable at
the `/dev/fd/<helper-fd>` entrypoint with fixed `-I -S`, a closed fixed argv,
empty input stream, fixed `LANG=C`/`LC_ALL=C`, cwd `/`, and `close_fds=True`. The child
closes both source descriptors before activation and requires its only open
descriptors to be `0`, `1`, `2`, and the private control socket. It attests the
executable identity, exact helper/session source hashes, entrypoint, argv,
isolated/no-site interpreter flags, environment, cwd, and FD allowlist before
the parent sends any artifact bytes.
After composition, the child sends `ready_for_w5`, retains every exact object
and descriptor, removes its socket timeout, and accepts exactly one fixed W5
transition frame. The returned parent-side child-lifetime handle exposes only
`readiness()` and argument-free `transition_to_w5_once()`; it is not the
session or W5 capability. The transition frame is canonical and binds the
fixed protocol, operation, session id and readiness payload hash. In the same
child process, the exact session capability produces one opaque W5 lease, which
remains held by the child's lexical state and owner-private lease registry. The
child returns only a non-authorizing `w5_lease_ready` acknowledgement and keeps
running. Neither readiness nor transition appends a W2 terminal event, closes
the project/root descriptors, serializes the lease, or performs qsub.

The fixed production owner has no arguments and cannot be issued outside that
activated child. Its durable-journal parent is the owner-captured object for
the literal `/var/lib/auto-g16/direct-session-journal`; this is local
coordination state, not a selectable server workspace. A runtime rebind of the
public name, frozen source/executable/launcher bindings, entrypoint, argv,
interpreter flags, environment, cwd, or FD policy is rejected before artifact transfer, write, or
W1/W3/W2/W4 entry. The directory must already exist as a non-symlink. The
offline fake-local owner changes only that state parent for repository-external
temporary-filesystem tests and calls the same `compose_once()` implementation;
it is not reachable from the production launcher or child call chain.

## Exact production call chain

The only production composition order is:

1. The fixed parent/child clean-exec handshake validates the executable,
   helper and session source bytes, entrypoint, argv, environment, cwd and
   closed-FD allowlist. Only then are the exact portable bytes transferred over
   the private local socket.
2. `FixedTrustedServerLocalSessionOwner.production()` rechecks those bindings
   and the owner-captured state root in the child.
3. `DirectRootOwnerContractOwner.for_posix_backend()` revalidates exact profile
   policy, stable evidence, profile `/3`, authorization `/3`, and current
   filesystem identities, then issues the real retained POSIX W1 capability.
4. `DirectServerSessionTransactionOwner.production().issue_once()` binds that
   exact capability and exact input bytes into one registered, noncopyable
   transaction without a synthetic mutation transaction or fake transport.
5. The existing resource owner validates the exact ledger/policy/gate/scheduler
   artifacts, reserves the exact attempt, and issues its registered replay
   capability.
6. `LiveApprovalEffectTimeReplayOwner.production()` revalidates the exact live
   approval bytes against the direct transaction and issues its registered
   replay capability.
7. `DirectEffectTimeReplayIngressOwner.production().seal_server_session_once()`
   issues one still-unconsumed W3 capability for the exact owner objects.
8. `direct_durable_submission_journal.consume_for_server_session_replay_once()`
   uses W2's no-argument, owner-private canonical W3 activation. A missing W3 is
   executed only from the fixed reviewed full-source hash through a no-follow
   descriptor, bypassing import finders; an already-loaded W3 must have completed
   its real owner registration. Exact module/type/descriptor/source and fixed
   `sys.meta_path` identities are checked before and after the predecessor call.
   Only then does W2 durably record `started` without consuming W3.
9. Only after W2 `started`, W3 `consume_once()` performs its exact predecessor
   currentness replay and issues the real W3 claim. Failure here appends W2
   `unknown`; the existing journal prevents a second claim.
10. `DirectRootFixedMutationOwner.issue_session_once()` consumes the same W1,
   W2, and direct-binding identities; its fixed helper exclusively creates
   project and `scratch`, then returns the exact open project FD with
   `SCM_RIGHTS`.
11. The session parent checks the canonical frame, request hash,
   inode/device/mode
   identity, root-relative name identity, and `FD_CLOEXEC`, and issues one
   nonportable session capability joining W1/W2/W3/W4 by exact object identity.
12. That capability exposes only `assert_current()` and the atomic single-use
   `consume_for_w5_once()`. The latter changes only the owner-private registry
   state and returns an opaque same-PID W5 lease. It does not consume or close
   W4, append W2 terminal state, expose a raw FD/path, or perform W5/qsub work.
13. The parent handle's fixed argument-free transition sends only the canonical
   protocol/session/readiness-hash frame. The child invokes the exact step-12
   method in its original process, retains the opaque lease locally, returns a
   non-authorizing `w5_lease_ready` ack, and continues running for future W5.
   W4B implements no qsub or W5 effect consumer.

The production path never calls `_for_testing`, `ClosedFakeTransport`,
`SyntheticTransaction`, a synthetic mutation owner, `object.__new__` to rebuild
W1/W2/W3 objects, field-copy reconstruction, capability serialization, or
caller-computed capability hashes. The seam's own owner and final session
capability are private-registry objects; they do not reconstruct an upstream
capability.

## Failure, lifecycle, and reconciliation

Before W2 `started`, all validation failures have zero W4 filesystem effect.
Every exception after W2 `started`, including W3 replay failure, helper EOF, crash,
timeout, missing/extra/truncated FD rights, identity drift, or terminal-report
loss, is `unknown` and reconciliation-only. This seam contains no code path
that records `completed`. A missing project FD is never recovered by reopening
a path and never causes retry, overwrite, rollback, deletion, or cleanup.

Session, W5 lease, and upstream capabilities remain process-local and
owner-registered.
Copy, deepcopy, pickle, serialization, subclassing, fork-child use, module
reload, owner rebinding, path replacement, FD close, FD-number reuse, duplicate
or concurrent consumption, and session restart fail closed. After restart, W2
`reconcile_read_only()` is the only supported view; `started` without a
terminal event is interpreted as `unknown`, and no effect capability is
reissued.

A malformed, foreign or duplicate transition frame, repeated parent transition
call, parent EOF, or child death cannot be retried. A live child records
`unknown`, closes retained descriptors and exits nonzero; a dead child leaves
started-only durable state, which reconciles as unknown. No path reopens or
reconstructs a capability.

The explicit fake-local test retirement harness appends `unknown` and closes
descriptors only to release synthetic temporary resources. It is token-gated,
is absent from the production call chain, and is not no-effect production
consumption. Production parent EOF is instead a failure path: the child records
`unknown`, closes retained descriptors, and exits nonzero for reconciliation.

W3 deliberately retains
`arbitrary_same_process_reflection_isolated=false` and
`production_closure=false`. The fixed session is valid only in a reviewed clean
exec that never loads untrusted arbitrary same-process code. Python reflection
is not a sandbox or a production-closure proof.
