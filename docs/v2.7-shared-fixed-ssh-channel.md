# Auto-G16 v2.7 shared fixed-SSH channel owner

Status: production-shaped and offline-validated; live query and fetch remain
blocked and unauthorized

This slice makes `direct_shared_fixed_ssh_channel.py` the sole owner of the
direct backend's fixed OpenSSH executable, option vector, subsystem mapping,
descriptor execution, framed controller I/O, absolute monotonic deadline and
bounded local-child retirement. W5 consumes that owner through the exact
sealed `SubmitChannelOperation`. The existing canonical W5 submit request and
response bytes, W5 typed submission seam, immutable upload, qsub argv and
at-most-once uncertainty rules are unchanged.

## Closed operations and transport mapping

The owner alone issues three exact same-process operation types:
`SubmitChannelOperation`, `QueryExactJobOperation`, and
`FetchTerminalMinimumBundleOperation`. Their constructors, copying,
serialization, reconstruction, cross-process reuse, post-fork reuse and
post-reload reuse fail closed. A private registry binds exact object identity,
current PID, one operation type, exact W5 transport-profile bytes and, for read
operations, the exact read-profile bytes and PBS job ID.

The registry is closure-private and never returns a live record. Effect and
codec paths receive only frozen typed snapshots after the owner replays the
record commitment under its lock. Portable projections are fresh deep copies,
remain non-authorizing, and cannot mutate the bound frame, status, job ID,
read profile or transport profile. Terminal records retained for diagnostics
have a fixed bound; evicted objects and weakly reclaimed abandoned objects can
never become current again. A process epoch plus a monotonic sequence prevents
operation-ID reuse within an owner lifetime, and fork clears the registry,
terminal queue, epoch, sequence, seals, locks and cached W5 binding.

Submit issuance additionally requires W5's exact private request join. W5
replays the current registry entry, exact `DirectServerSessionArtifacts`, all
artifact hashes and transport bytes, then regenerates the canonical control
frame from that owner state. Only an exact byte match is accepted. The shared
operation record binds those approved frame bytes, their SHA-256 and the exact
W5 request ID; the runner rejects a cross-request, cross-artifact, different
nonce or recomputed frame before descriptor execution or fork.

There is no generic submit registrar. The only submit issuer performs the W5
source/module/currentness checks and consumes the exact private W5 join in the
same path that creates the shared operation. A valid submit operation is
atomically claimed before descriptor acquisition; every later descriptor,
pipe, fork, transport, response or exit success/failure finishes it terminal.
An attempted hostile frame also makes that exact operation terminal before
descriptor acquisition, so a later approved frame cannot reuse it.

The caller cannot supply an operation string, subsystem, argv, host, user,
port, identity path, known-hosts path, environment or callback. The owner maps
submit to `auto-g16-direct-one-hop-v1` and both read operation types to
`auto-g16-direct-one-hop-read-v1`. Both mappings use the same reviewed W5
transport-profile bytes and the same fixed SSH executable/options. The submit
operation remains the only effect-capable operation. The Q1 successor owns the
exact private issuance and operation/frame joins for the query runner; fetch
has no production runner. Neither read operation can reach qsub.

Every portable operation projection is explicitly non-authorizing. Query and
fetch projections and wire requests record `authorizes_effect=false` and
`qsub_calls="0"`. The submit projection cannot replace W5's exact private
request join: it states that submit authority remains `typed_w5_seam_only`.
`project_query_request_frame_for_review` and
`project_fetch_request_frame_for_review` are repeatable review projections;
they neither claim nor consume an operation and are not acquisition APIs.

## Read profile and successor-owned query execution

The closed `auto-g16-direct-shared-fixed-ssh-read-profile/1` document contains
no host, user, port, identity-file or known-hosts fields. It binds the SHA-256
of the exact canonical W5 transport-profile bytes and that profile's payload
hash, then adds only the reviewed shared-owner server source hash, fixed qstat
executable hash, exact root-owner/mode-0755 policy and bounded qstat/fetch limits. A
read profile made for one byte-identical transport profile cannot be spliced
onto another. Q1 additionally requires a live backend-owned reviewed-profile
capability; raw profile bytes or hashes are not authority.

This shared-owner slice does not itself issue L1 lineage or final evidence. The
Q1 successor consumes exact L1 authority and supplies the production-shaped
qstat query path and final scheduler-only `/3`; all validation remains offline
and no live SSH/PBS/qstat is authorized. Fetch, materialization,
reconciliation, cancel, qdel and advanced inspect remain blocked.

## Framing and uncertainty

The shared submit path preserves W5's canonical one-frame control protocol.
Query has one canonical JSON response followed by mandatory EOF. Fetch is a
pure state machine: canonical control header, an exact positive number of
bounded non-empty binary chunks, canonical digest trailer, then mandatory EOF.
Zero sizes, bound violations, truncation, inconsistent counts or totals,
digest drift, trailing bytes and second frames fail closed.

Each read acquisition first checks the exact query/fetch operation class, then
atomically changes that exact operation from `issued` to `running` before the
first descriptor read. Its `finally` transition is terminal for success,
malformed data, partial data, EOF, timeout or any other exception. Duplicate,
failure-then-valid, cross-type and post-terminal reuse therefore fail closed;
cross-type calls are rejected before reading the supplied descriptor.

All partial reads and writes in one operation receive the same absolute
monotonic deadline; progress never resets it. The submit controller uses one
deadline across request write, response read/EOF and child exit observation.
After fork, any request write/close, response, EOF or exit ambiguity is
`ControllerTransportUnknown`, reconciliation-only, with no retry or second
qsub. Bounded retirement observes the local SSH child with
`waitpid(..., WNOHANG)` only and never signals it; that submit behavior is
unchanged. Q1's read-only query runner has a separate query-only retirement:
after the query is already terminal unknown/no-retry, it consumes an exact
closure-private child handle and requires its active Query operation ID,
issuing PID/thread, epoch, nonce, and default `SIGCHLD` to remain current.
There is no module-level raw-PID issuer: a single closure-private transition
checks the exact running Query operation, forks, and registers that parent's
returned PID atomically. An immediate
`waitpid(WNOHANG)` must prove the recorded PID is still this process's
unreaped child before `SIGTERM` and again before a possible `SIGKILL`; foreign
numeric PIDs, `ECHILD`, PID-reuse ambiguity, and unproved `ESRCH` never become
signal authority. A successful path ends in an exact bounded reap. It never
targets a process group and does not authorize PBS `qdel`, job
cancellation, cleanup or another query.

## Source and descriptor boundary

W4B opens the shared-owner source no-follow and passes that additional exact
descriptor into the fixed `-I -S` child. The child reads and replays source
identity/hash, installs that exact module before executing W5, closes every
source/executable descriptor, and still requires the post-activation FD
allowlist to be exactly standard descriptors plus the private control FD.
Path re-import, source replacement and extra inherited descriptors are not
accepted.

The clean child environment is an owner-fixed exact mapping. It binds
`HOME=/proc/auto-g16-disabled-home` and
`AUTO_G16_RUNTIME_CONFIG=/proc/auto-g16-disabled-runtime-config`, plus
`LANG=C` and `LC_ALL=C`. These kernel-namespace deny sentinels are never
inherited from the caller or host account and are not runtime-configuration
paths or authority. The legacy dependency loader can only perform its
descriptor-relative missing-path probe under `/proc`; the helper verifies that
the fixed runtime-config path is absent both before and after dependency import
and that the source-, origin-, identity-, and hash-bound exact loader reports
the fixed path with an empty value set. The exact loader module and its
`setting` function are included in the session's static currentness checks
before shared-channel or W5 loading. It therefore cannot load caller or host
runtime-configuration bytes. This also keeps dependency import deterministic
when the local account directory service is unavailable.

Closure privacy prevents ordinary callers from receiving or mutating a live
operation record, but it is not isolation from arbitrary same-process
`__closure__` introspection, native-memory access, debugger takeover, or code
replacement. Those capabilities remain outside this owner's threat boundary.
The fixed clean-exec process excludes untrusted arbitrary same-process code,
and `production_closure` remains false until the later read/query/fetch owners
and their exact composition are reviewed.

Tests are synthetic and offline. They use local pipes and child processes only;
they never connect to SSH, execute qstat/fetch/qsub, access a server project, or
grant deployment/live authority.
