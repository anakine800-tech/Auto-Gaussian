# Auto-G16 v2.6 protected legacy effect handoff

## Decision

PR4N adds `auto-g16-protected-legacy-effect-handoff/1` as an additive,
non-executable successor. It binds one exact current PR4L
`SealedProtectedLocalMaterialization` to a read-only PR4M lifecycle readiness
witness issued by the exact legacy module.

The handoff proves only that the protected materialization and the bounded
terminal-retirement lifecycle implementation can be held together as exact
typed values. It does not create `_LegacyTransactionPlan`,
`_LegacyEffectPlan`, `_LegacyRawEffectOwner`, or a lifecycle registry entry.
It does not call an adapter, runner, transfer, qsub, reconciliation, retry,
cancel, cleanup, or deletion path.

## Owner and source binding

The facade fixes the repository-source or deployed-package owner layout and
binds one exact PR4L module and one exact legacy module. The handoff owner
requires the exact bound PR4L sealed class, calls its `assert_current()`, and
obtains the PR4M witness internally. Stable no-follow reads bind both owner
files by identity, bytes, and SHA-256. Foreign classes, same-path reloads,
cache replacements, and post-seal source drift fail closed.

The portable projection contains only immutable identifiers, hashes, the fixed
six-step lifecycle topology, fixed false effect flags, and self-hashes. It
contains no path, configuration value, credential, command, callback, backend,
runner, raw bytes, or caller-provided verification assertion.

## Compatibility

PR4D, PR4G, PR4F, PR4K, and PR4L contracts, Schemas, owners, records, and
historical fixtures remain unchanged. There is no migration, rehash, backfill,
or automatic conversion. The old integration path remains fail closed and is
not a consumer of PR4N.

## Remaining gate

PR4N does not make `adapter_connected`,
`qsub_invocation_started`, or `runtime_transport_binding_complete` true. A
future runtime-binding/adapter slice must independently prove the exact
effect-time call chain and retain all operational approval gates.
