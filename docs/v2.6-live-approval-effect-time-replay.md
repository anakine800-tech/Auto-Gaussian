# Auto-G16 v2.6 live-approval effect-time replay owner

## Decision and boundary

`auto-g16-live-approval-effect-time-replay/1` is an additive, offline
predecessor for a future separately reviewed legacy factory consumer and
production wiring task. The owner accepts one exact current
`SealedProtectedProductionIngressCapability` and uses one approval pathname
only as a locator for a descriptor-bound regular-file capture. Authority comes
from the predecessor's live-approval ID and artifact SHA-256, not from that
pathname.

The owner issues one in-process
`PreQsubLiveApprovalReplayCapability`. The capability permits exactly one
effect-time replay through the existing
`legacy_rtwin_pbs.validate_live_approval_binding()` owner. It does not
authorize submission and exposes no effect plan, raw owner, runner, adapter,
transport, qsub, retry, reconciliation, cancellation, cleanup or deletion
method.

The v2.7 fixed server-local session adds
`issue_direct_server_session_once()`. That production-owner entry accepts only
the exact real `DirectServerSessionTransaction`, derives its predecessor IDs
and hashes from that owner-bound transaction, captures the same exact approval
artifact, and delegates approval semantics to the same historical validator.
It does not call a test factory, fake transport, synthetic transaction, or
synthetic mutation owner, and it does not duplicate live-approval logic.

## Exact capability closure

The portable projection binds:

- production-ingress, owner-consumer, protected-submit and protected
  consumption identities;
- approval schema, one-time ID, exact file bytes/hash/size/identity, complete
  scope hash, approver, approved/expires timestamps and active revocation;
- batch ID, review hash, scientific task, attempt, idempotency-key hash,
  project, input hash and policy/gate/resource tuple;
- exact source bytes for this owner, the production-ingress owner and the
  existing live-approval owner; and
- the fixed `immediately_before_qsub` phase, single-use registry/lock policy,
  trusted wall plus monotonic-lower-bound policy, and zero-effect boundary.

The capability and completed replay result reject construction, shallow copy,
deep copy and pickle. Registry identity is authoritative, so changing object
attributes does not mint a valid capability. Draft 2020-12 Schema acceptance
is structural only and never issues or consumes an in-process capability.

## Fail-closed behavior

Before issue and replay, the owner rechecks canonical module identity, owner
registration, exact callable identity and source file identity/bytes for the
production-ingress and live-approval owners. It also replays the complete
sealed predecessor. A foreign identical module or class, canonical cache
replacement, source replacement, predecessor drift, approval path replacement,
file identity/bytes/hash drift, scope splice, revocation, expiry, wall-clock
rollback, monotonic rollback or second replay fails before any effect.

The capability attempt becomes terminal before the replay begins. A failed
replay cannot be retried automatically. The completed result remains
`non_authorizing: true`; a future effect owner must separately consume it
together with the still-missing legacy-internal factory consumer and
production call-chain wiring.

## Compatibility and packaging

Historical live approvals, fixtures, protected-submit owners, legacy
transaction/factory/raw-owner code and production ingress remain unchanged.
The closed replay Schema additively permits the exact direct-server predecessor
variant; unknown or mixed predecessors remain rejected. The base named-Skill
package contents and manifest are also frozen.
The additive deployment-package supplement explicitly maps this new owner,
Schema and document from their independent repository sources to their named
package targets. No deployed Skill copy is synchronized by this change.

Offline tests must replace every effect surface with recorders and prove
factory, runner, qsub and adapter calls remain zero. Offline PASS is not
transport, PBS, Gaussian, deployment, live-smoke, merge or release authority.
