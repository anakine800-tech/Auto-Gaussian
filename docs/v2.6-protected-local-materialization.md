# Auto-G16 v2.6 protected local materialization

PR4L is the additive
`auto-g16-protected-local-materialization/1` successor. It implements only
the first mutable prefix recorded by PR4K:

1. seal and replay exact typed PR4K evidence;
2. reserve the nested PR4D authority once and enter
   `submission_uncertain`;
3. write the already sealed PR4F stage bytes into the PR4G-derived local
   directory with `O_EXCL` and `O_NOFOLLOW`;
4. fsync the materialized files and directory; and
5. publish `protected-local-materialization-v1.json` last with the same
   no-clobber rule.

The public owner accepts one value only: exact typed PR4K evidence. It accepts
no caller path, byte payload, artifact list, clock, state root, adapter,
backend, runner, callback, command, retry, cleanup, or migration instruction.
Production reservation time and state remain owned by the existing PR4D
trusted state owner.

PR4L binds the already loaded canonical PR4K module, its exact evidence,
owner, and sealed classes, and one stable no-follow source snapshot when the
PR4L owner loads. PR4K must therefore load first in the same owner process.
Before reservation, PR4L holds its module/import lock while it rejects a
foreign class, a missing or replaced canonical cache entry, a same-path second
module load, class replacement, source replacement, and an import-order
mismatch. Path equality, the canonical cache name, and re-executed
same-source classes grant no authority. The binding and source snapshot are
checked again after PR4K replay, before reservation, after materialization,
and by the returned sealed state.

## State and failure semantics

The published record binds:

- PR4K lifecycle ID and structural projection hash;
- PR4F invocation payload, stage manifest, ordered artifact metadata, exact
  hashes, sizes, and resulting local file identities;
- PR4D bundle, trusted consumption hash/time, and
  `submission_uncertain`;
- PR4G binding, derived layout, path digests, initial ledger identity, and
  unchanged ledger bytes;
- the exact directory topology, with the state record last; and
- false effect, qsub-start, adapter, reconciliation, live-validation, and
  long-process-gate status.

Any failure is a clean stop. The owner does not delete, truncate, overwrite,
roll back, retry, cancel, clean up, migrate, rehash, or backfill. A crash after
reservation may leave exact partial stage files and a consumed
`submission_uncertain` reservation. A second call cannot resume it
automatically because PR4D single-use reservation fails closed.

`SealedProtectedLocalMaterialization.assert_current()` replays the final
directory and every file identity and byte hash. It verifies only this bounded
local state. It does not reopen PR4G `/1`, whose ledger-only precondition is
intentionally a pre-materialization contract.

## Compatibility and remaining gate

PR4D, PR4G, PR4F, PR4I, PR4J, PR4K, their Schemas and historical artifacts,
`legacy_rtwin_pbs.py`, and the existing effect owner remain unchanged. There
is no adapter connection, transfer, SSH, PBS, Gaussian, qsub/qdel, status,
fetch, cancellation, cleanup, deployment, or live smoke in PR4L.

The PR4J long-process strong-reference/bounded-lifetime gate remains closed.
PR4L success therefore does not authorize or implement
`LegacyTransportAdapter.invoke_reserved_once`, a raw-effect owner, or any
external effect.
