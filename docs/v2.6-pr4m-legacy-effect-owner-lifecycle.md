## Closed local lifecycle gap

The existing PR4J plan and raw-effect owner registries hold exact strong
references while the six-step legacy transaction is active. Before PR4M,
successful completion, an effect failure, a post-transfer resource or approval
failure, an uncertain qsub observation, and later local failures left both
registry entries allocated for the process lifetime.

PR4M issues one private lifecycle scope immediately after the transaction
creates its exact raw-effect owner. One scope is bound to the exact
plan, plan state, plan lock, owner, effect state, and effect lock. The existing
transaction body runs inside that scope, so its single `finally` retirement
covers:

- all six fixed effects completing;
- an ordinary exception or `BaseException` at any effect;
- resource or approval replay failing after the fifth effect;
- qsub uncertainty or classification failure; and
- receipt, ledger-reconciliation, job-state, or other local failure after the
  qsub invocation.

Retirement uses the fixed lock order plan lock, effect lock, then registry
lock. It first marks retirement requested, causing an already-waiting dispatch
to fail before `run`. Under the registry lock it replays the exact
bidirectional object identities, atomically removes both entries, marks the
states `retired`, and breaks their reverse reference cycles. A repeated
retirement verifies the retained object-local terminal record and does
nothing. There is no weak-reference-only cleanup, GC dependency, or unbounded
global tombstone table.

## Replay and concurrency boundary

After retirement, the plan factory, every owner method, an exchanged plan or
state, a forged lifecycle, and a replaced lock all fail before the sole
runner. If retirement races one effect already inside `run`, that effect may
finish, but every waiter observes the retirement request or missing registry
and no second runner call begins.

These private Python objects and tokens protect the repository's internal call
graph; they are not a hostile in-process isolation boundary.
