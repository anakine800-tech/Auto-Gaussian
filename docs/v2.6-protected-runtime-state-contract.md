# Auto-G16 v2.6 protected runtime/state successor

## Decision and boundary

`auto-g16-protected-runtime-state-contract/1` is an additive local successor
after PR4N. It closes the runtime/path and append-only state ownership gaps
without connecting `LegacyTransportAdapter`, constructing a legacy effect
plan/raw owner, invoking a runner, or performing transport, PBS, Gaussian,
status, fetch, cancellation, cleanup, deletion, deployment, or live
validation.

PR4D/PR4G/PR4F/PR4J/PR4K/PR4L/PR4M/PR4N Schemas, fixtures, references,
owners, and replay bytes remain frozen. Historical `/1` records are not
migrated, rehashed, or backfilled.

## Runtime and path owner

The owner accepts only one exact current PR4N sealed capability. Production
selects the normal machine-local runtime-config path; the public seal method
does not accept a caller path or runtime mapping. It reads the runtime config
and first-hop SSH config using stable no-follow regular-file snapshots.
The successor also binds its own canonical module object, exact source origin,
and exact issued classes. Cache replacement, foreign-name loading, or a
same-source foreign class cannot issue or recover a canonical capability.

The runtime values remain private to the sealed in-process capability. The
portable projection contains hashes and sizes only. The owner recomputes the
two adapter-private config-reference hashes and the exact transport-binding
payload and compares them with the already sealed PR4D transport authority.
It rejects a mismatched first-hop config path, second-hop config reference,
target alias, source replacement, or noncanonical Windows root.

The Windows project root and second-hop config reference are restricted to
canonical drive-absolute backslash paths. Reserved device components are
rejected; the second-hop path may retain an exact hidden component such as
`.ssh`. The case-folded root and derived project-directory identities are
hash-bound. The remote policy remains exactly `/home/user100/SDL/<project>`
with no override.

## Append-only state and receipts

The owner derives a sibling state journal from the exact PR4L local directory:

```text
<PR4L-local-dir-parent>/.auto-g16-protected-runtime-state-v1/<attempt-id>/
```

This keeps every PR4L directory byte and topology unchanged. The initial ready
receipt is first completed and fsync-backed in a hidden, non-authoritative
staging file. Only a complete staged inode is hard-linked no-clobber into the
authority journal. A clock, write, fsync, or crash-equivalent interruption can
therefore leave an absent/empty journal or an ignored staging file, never a
partially published ready authority. Explicit recovery may complete only that
definitely-not-started initialization; an invalid published receipt remains a
typed fail-closed error and is never deleted or overwritten. Later journal
files use the same no-clobber, no-follow, fsync-backed write policy:

1. `ready`: PR4N and runtime binding are current, not consumed.
2. `effect_not_started`: one consumption occurred after the final
   `assert_current()`; no external effect may have started.
3. `effect_started_outcome_uncertain`: this receipt must be durable before a
   future adapter enters the external-effect boundary.
4. `accepted_terminal`: an exact typed read-only reconciliation handoff was
   accepted.

Every receipt binds the contract, journal, handoff, materialization, attempt,
runtime payload, sequence, prior receipt payload, timestamp, state flags, and
policy. Recovery replays only the exact journal. A recovered not-started state
may advance to the uncertain boundary without a second consumption. A
recovered uncertain state cannot retry and may proceed only through typed
read-only reconciliation.

## Reconciliation and validation layers

The reconciliation owner validates a typed observation, terminal
classification, job-ID cardinality, and exact uncertain receipt. It does not
obtain remote evidence. Its projection explicitly records
`observation_acquired_by_this_contract=false`, performs no remote read, and
authorizes no effect or retry.

Draft 2020-12 Schemas prove structural acceptance only. Public validators add
cross-field/hash semantics. The semantic owner additionally replays exact
typed predecessors, module/class/source identity, runtime sources, path
identity, and journal bytes. Only the non-copyable in-process seal can append
a transition. Schema validity or public validation never substitutes for that
capability.

## Remaining gate

The future adapter slice must independently bind this exact capability to the
legacy effect plan/raw owner, persist the uncertain receipt before the first
effect, and obtain real read-only reconciliation evidence. This successor does
not prove that mapping and does not change the existing fail-closed adapter.
Its in-process lock and repeated file identity checks also do not claim an
atomic cross-process topology snapshot; that stronger boundary remains a
separate integration gate.
