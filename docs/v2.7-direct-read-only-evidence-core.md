# Auto-G16 v2.7 direct read-only evidence core

Status: W6C0 offline core only; production blocked; live not ready

Task class: feature development / L3 scheduler and evidence boundary

## Scope and non-authority

This additive core parses and classifies already-collected `pbs_legacy_v1`
single-job qstat bytes for the fixed `direct_one_hop` / `direct_ssh_pbs`
topology. It emits closed provisional
`gaussian-direct-qstat-evidence-core/1` projections and, only for a fresh
explicit PBS `C` or `F` record, a
`gaussian-scheduler-terminal-evidence-receipt/1` projection.

The core has no transport, SSH, network, shell, command, argv, callback,
retry, PBS invocation, Gaussian invocation, inspect acquisition, fetch,
materialization, cancellation, qdel, deletion, or cleanup implementation. It
does not read configuration or credentials. Caller-supplied bytes are not
proof that a transport ran. Both projections fix `authorizes_effect=false`,
`scientific_acceptance=false`, `production_supported=false`,
`transport_implemented=false`, and `remote_effect_performed=false`.

The scheduler-terminal receipt is deliberately not named a Gaussian terminal
inspection receipt. PBS `C` or `F` proves only fresh scheduler-terminal
read-only evidence under this grammar. It does not prove a complete Gaussian
log, successful fetch, result materialization, scientific completion, or
scientific acceptance. PBS `E` remains `exiting` and is not receipt-eligible;
this core does not change the historical legacy active-cancel behavior.

## Closed parser and classifier

The pure parser accepts one `bytes` object no larger than 64 KiB, strict UTF-8
without BOM, CR, NUL, blank lines, wrapping, or continuation lines, and exactly
one block headed by `Job Id: <exact-id>`. The independent PBS ID grammar is
`<1..20 nonzero-leading digits>.<server>`; the suffix is mandatory and matches
the current W5 independent-PBS stdout grammar. W5 integration must retain a
cross-owner parity test or consume one shared frozen grammar owner before
integration.

Every field is unique and belongs to the versioned closed allowlist in
`direct_read_only_evidence.py`. `Job_Name` and `job_state` are mandatory. The
supported state set is exactly `Q`, `R`, `H`, `E`, `C`, and `F`; a new server
field, wrapped value, duplicate key, duplicate block, different ID, different
job name, malformed value, or other state is unknown evidence until separately
reviewed.

Classification is fail closed:

- return code 0, empty stderr, and one exact parsed block is `present`;
- only return code 153, empty stdout, and the exact stderr bytes
  `qstat: Unknown Job Id <exact-id>\n` are `absent`;
- every other return code/output combination, timeout, incomplete EOF,
  oversize output, invalid UTF-8, parse failure, or mismatch is `unknown`.

The state projection maps fresh `Q/R/H/E/C/F` to
`queued/running/held/exiting/terminal/terminal`. Exact absence maps to
`absent`. Stale or chronologically invalid evidence maps to `unknown` even if
its raw qstat classification was present. Freshness compares the exact
microsecond duration against the limit; the portable whole-second age is
rounded upward so a fractional excess cannot be represented as fresh.

## Binding and compatibility

Each qstat evidence projection binds the project, exact PBS job ID, attempt ID, input SHA-256,
current direct binding SHA-256, direct topology, parser version, per-stream
hashes/sizes, request/collection/receipt times, freshness, and its own canonical
hash. A scheduler-terminal receipt repeats the exact topology and job binding
and binds the qstat evidence hash. A legacy nested-SSH or RTwin-shaped projection
cannot be spliced into either owner. There is no `rtwin_sha256` field.

Every integer-like portable field (hop count, return code, byte count, and age
or freshness limit) uses a closed canonical decimal string. This deliberately
avoids the Draft 2020-12 mathematical-integer rule under which JSON `1` and
`1.0` have the same Schema value while Python runtime types differ. Owner and
Schema both reject floats, booleans, signs where not allowed, leading zeroes,
and non-canonical decimal text.

Historical `gaussian-job-inspection/1`, `gaussian-job-inspection/2`, and
`gaussian-terminal-inspection-receipt/1` records are unchanged and are not
migrated. Their legacy owner is not imported or called.

This pre-W5 contract deliberately does not claim the final
`gaussian-job-inspection/3` identity. It lacks the future owner-issued W5
submission receipt, direct transport profile/invocation, and W2 journal joins
needed for final anti-splice closure. W6A must own that final identity only
after those exact typed predecessors receive L3 approval; this provisional
portable projection cannot be upgraded by relabeling or rehashing it.

## Integration dependency and blocked boundary

W6C0 supplies only parser/classifier and portable evidence validation. It does
not define or issue a W5 typed job, qsub receipt, transport/session capability,
or lifecycle capability. Integration must bind the exact final W5 job/receipt
owner and retain job-ID grammar parity; this branch cannot substitute its
portable direct binding for that capability.

Real W5/W6 transport, SSH, upload, qsub, inspect acquisition, process/log
collection, fetch, materialization, lifecycle reconciliation, and live-smoke
evidence remain absent and `live_not_ready`. Offline tests, Schema validation,
packaging, review, a commit, CI, or merge cannot authorize those operations.
