## 3. 要做的

### 3.1 B01：重复节点

1. 在 `parse_nodes` 汇总前检查节点记录的完整名称是否重复；相同内容的重复记录也拒绝，不取首条、不取末条、不叠加。
2. 复用现有 `pbs_hardware` 的局部失败通道：节点列表为空、硬件容量未知并带脱敏错误；本人作业、额度和队列的独立成功结果仍保留。
3. 不因硬件不可用把未知容量写成零或成功空闲；核对既有前端对该表示的兼容性。
4. `strict_nodes` 原有更严格校验不放宽；重复节点仍不能获得可提交候选。其异常文案变化可调整测试，但不能仅删除断言。

### 3.2 B02：时区不可信

1. 保留现行触发条件与严格边界：已配置调度器时区；开始时间在未来超过 120 秒，或推算耗时比 walltime 少超过 120 秒 / 多超过 3600 秒。120、3600 的等值边界不扩大。
2. 记录字段的内部来源：无时区文本经配置时区转换，或 epoch / 带偏移 ISO。不要依据转换后的字符串猜来源，不向公开快照增加不必要的原始文本。
3. 任一作业触发后，本入口本轮所有依赖该配置时区的 `start_time`、`qtime` 置 null，包括排队作业。清空开始时间的作业，其 `elapsed_seconds` 退回可用 walltime，缺失则 null，`elapsed_source` 同步。
4. 对直接触发异常的开始时间，即使来源为 epoch / 带偏移 ISO，也不继续展示该异常值，耗时仍退回 walltime。其他未触发异常的显式绝对时间保留；显式绝对 `qtime` 不因文本时区可疑而连带清空。
5. 没有配置时区、没有异常、不可解析或夏令时歧义等已有行为保持。每入口每轮仍最多一条匿名 `timezone-mismatch`，说明哪些时间转为未知及耗时回退。
6. 先处理可信度，再排序和截断；own.jobs 与 cluster.jobs 一致。未知时间复用既有作业号排序。只改新观察结果，不改历史快照、原始输出或时间戳。

### 3.3 B03：内存归属

1. 只在 Torque 按作业申请内存回退的“是否跨节点”判断中比较名称；输出节点名称、作业号、CPU 分配统计和具名节点身份保持原语义。
2. 完整名称精确匹配优先。短名与 FQDN 的对应，仅在本轮节点记录与 exec_host 的联合名称集合中唯一、没有同短名的多个域名或多个节点记录竞争时使用；不能简单把所有名称按第一个点截断。
3. 有歧义则内存未知并给匿名 notes，不分摊、不猜零；缺作业、精确作业号不一致、真跨节点、无内存申请等既有未知规则保留。PBS Pro 的显式已分配内存优先级保持。
4. 不用 DNS、SSH 或额外远程查询解析名称；不把显示辅助映射传入 `strict_nodes`、prepare 或 submit。精确身份不匹配的定向候选仍不可用。
