## 要做的

1. **输入校验：** 允许最多两条 `S` 行（`F` 行照旧）。两条扫描坐标不能相同，不能共用全部原子；每维步数 1–20；总点数 `(n1+1)×(n2+1)` 不超过 **144**。超出时报错并给出点数。xTB 仍只允许一行。
2. **确认摘要：** 分别列出两个坐标的起点、步数、步长、终点和单位，以及总点数；提醒“每个点都是一次约束优化，耗时约为一维扫描的点数倍”。一维扫描的摘要文字不变。
3. **`science['scan']` 的二维格式：** 一维保持原样。二维新增 `dimensions: 2`、`coordinates`（两个定义，各自起点、步数、步长、终点）、`expected_points`。具体字段写进 `ag/README.md` 扫描一节，并在 PR 里列出。
4. **取回后的解析（最关键）：**
   - **不假设** Gaussian 遍历两个坐标的先后顺序。对每个已完成的点，用该点几何**实测**两个坐标的值，各自对到最近的目标值（偏差须小于该维步长的一半），由此确定网格编号 `[i, j]`。
   - 对不上、两个点对到同一格、或点数超过声明时，**整个扫描报错**，不猜测；缺失的点保持 `null`（unknown）。
   - 每个点记录：网格编号、两个目标值、两个实测值、能量、是否收敛、几何帧号。
   - 在 PR 里写明真实输出中实际观察到的遍历顺序（只作记录，代码不依赖它）。
5. **鞍点提示：** 在 facts 的扫描部分（或 Markdown 摘要）列出“鞍点候选”：自身及上下左右四个相邻点都存在且收敛，并且沿一个方向是严格局部极大、沿另一个方向是严格局部极小的网格点。只是提示，不是 TS 判定；边界上的点不列出。
6. **`ag scan-peak`：** 一维行为不变。二维扫描时必须给 `--point i,j`（从 1 开始的网格编号），且该点必须是鞍点候选，否则拒绝并列出全部候选；不自动选点。导出的几何和报告格式与一维一致，报告里注明是二维网格点。
7. **卡片 `ts.md`：** 补二维扫描一小节：何时用（两个坐标明显耦合时）；先用较粗网格；点数和耗时；鞍点候选只是初猜，仍需 TS 优化、频率方向审阅和双向 IRC。

## 测试

- 合成 Gaussian 输出：3×3 网格，两种遍历顺序各一份，网格编号都正确；中间缺一点 → 该格为 `null`；一个点实测值偏离超过半个步长 → 报错；点数多于声明 → 报错。
- 鞍点提示：合成能量面（例如 `E = x² − y²` 的网格）只在中心给出一个候选；边界点不列出；相邻点缺失或未收敛时不列出。
- `scan-peak`：二维不给 `--point` 时拒绝并列出候选；指定非候选点拒绝；指定候选点导出正确几何。
- 校验：三条 `S` 行、相同坐标、超过 144 点、xTB 两行都报错。
- 一维回归：现有扫描夹具的 facts 和 `scan-peak` 输出与 main 一致。
- 开发中只跑扫描相关测试；推送前本地跑一次全量 `PYTHONPATH=ag/src python -m pytest ag/tests skills-next -q -rs`，之后以 CI 为准。敏感扫描与 `git diff --cached --check`。
