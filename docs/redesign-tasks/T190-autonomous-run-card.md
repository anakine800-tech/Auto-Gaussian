## 卡片必须表达

1. 读当前计划与有界状态摘要；结束即退出，暂停不启动新 prepare/submit/补救/改投/自主取消。仍需观察或取回时只使用正式允许的观察租约，由唯一有效 owner 推进。区分运行结束（本次 wake）与整个 round 结束，不能误清零额度。
2. 正式获取当次 run/token，核对 ag/RDKit/GoodVibes、计划确认、规则到期及快照新鲜度；最多 60 分钟，90 分钟后才可接管旧租约。所有状态/取回/快照等命令使用最终 CLI 的 owner 参数，失权后停止发布，不能复用前次 check 结果或改 token 续权。
3. status→已确认结束才 fetch；分别处理自动 facts 的 written/unchanged/skipped/conflict/failed。冲突分支标“需要你看”，不 refresh/reparse，不覆盖已有证据。UNKNOWN 只核对，绝不新建替代或重提同一 Attempt。
4. 在跑 Gaussian 按正式快照入口观察；两次连续不同 wake 的证据和模型理由才进入无进展取消资格核验。每 wake 取消最多两次；只碰本轮真实自主归属，取消接受不等于停止。不确定则暂停，不重试。
5. 改投按取消前正式观察核验从未运行、排队至少六小时、无 chk 依赖与当下更高优先候选；取消后另核验同实例停止及运行历史，不满足就拒绝替代提交。本版保留自动改投；描述实际前置证据及实现局限，不宣称原子排队保护。负责人风险决定及私有交接只留仓库外，不复制到公开卡片或任务单。每原作业/谱系一次，新 Attempt 仍消耗预算。不支持的调度器证据只禁改投，不新增普通提交版本门槛。
6. 下一步科学判断由模型在已确认计划内作临时判断并逐条标“待人确认”；方法/机理变更、结构/代表集合/最终结果签字仍请人。TS 极小点、方向错误、超时与确认取消后的补救使用正式证据接口；同对象同失败最多两次，不能靠改名或换猜测清零。
7. 使用同一实际路由选择与计划绑定规则；SCNet 四个活跃自主作业、兜底两个排队自主作业按本机所有 study/轮次合计，旧轮和 UNKNOWN/未观测预留保留；账号全部核数仍包含手动作业。CREST/xTB 保留既有建议顺序，同时受统一实际额度限制。
8. Attempt 预算依 W2 按实际提交消费计数，prepare 的来源记录不另扣预算；预算 90%、规则/计划/版本失效、UNKNOWN、哈希不符、取消不确定等按正式接口暂停；跨 wake SSH 失败、过期快照和同 wake 多对象同类失败，读取并留存可追溯计数证据。具体熔断必须使用最终已有接口，不把模型文本宣称成内核已强制。
9. 发生变化才写简报，首行列需要负责人处理的事项（放宽输入、需要人看、取消/改投、暂停）；无变化不发空简报。总结列计算、补救、取消/改投、资源及待确认判断。study.md 的更新必须遵守唯一 owner 和实际受保护写入能力；不得直接编辑自主状态/journal。
10. 正常完成当次 wake 正式释放租约，不取消已在跑作业；有变化的状态须已安全保存。实际定时任务和具体时刻属于 W6/T198 的独立运维授权，本卡不创建或启用。

计划模板须与最终 T184/T186 实际字段一致：目标、比较组、方法口径、主/小体系、各类作业预估耗时、Attempt 上限、到期、工具版本、试点或研究标记及受审阅的 submission_policy。目标不枚举所有对象；新增对象记状态，不能每补构象就改已确认计划。
