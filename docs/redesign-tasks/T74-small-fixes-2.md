## 要做的

### 1. SSH 本地日志写不进去时，警告刷屏

- 现状：`_log_call` 在日志目录或它的任一上级目录是符号链接时直接放弃写入，并且**每一次** ssh/scp 调用都打印一次 `Warning: could not write local SSH log`。配置目录位于带符号链接的路径下（例如 macOS 的 `/var → /private/var`，或用户把配置目录链接到别处）时，每次调用都失败，`ag monitor` 等会刷屏。
- **先复现**，在 PR 里写明实际触发的原因（不写具体路径）。如果原因不是上级目录的符号链接，停下汇报。
- 修改：
  - 配置目录本身按真实路径解析一次（用户自己选的配置位置，配置文件本来就从那里读）；只拒绝 `ssh-log` 目录**本身**是符号链接，以及日志文件是符号链接或非普通文件的情况（保留现有的 `O_NOFOLLOW`、`O_DIRECTORY`、普通文件检查和 0600 权限）。
  - 同一进程内警告**最多打印一次**，附错误类别（如 `symlink`、`permission`、`not_regular`），不打印路径。
  - 日志写入失败仍然不影响 ssh/scp 操作本身。

### 3. 清单把正文里的命令示例当成缺失的证据引用

- 现状：`_references` 把反引号里的内容当成可能的路径，只要以 `.json`、`.md` 等结尾就算“明确引用”。正文里写的命令示例（例如 `` `ag thermo … --out analyses/….json` ``）整段被当成一个路径，在清单里列为 `missing`，签字时只能用 `--accept-unresolved` 放过。
- **先找到实际例子**：在 L1–L3 的复扫记录、T64 以来的 PR 评论或模板中，找出被列为 `missing` / `unqualified_name` 的命令示例。**找不到实际例子，本项不做**，在 PR 里说明。
- 修改：反引号内容能按原解析规则找到真实存在的文件时照旧收录，不论是否含空格；仅在含空白且原解析结果为 missing / unqualified_name 时当作命令示例忽略。不从命令里拆出路径。目录展开、越界、链接及歧义等既有处理保持不变。
- **硬性要求：** 用新版本对 L1–L3 和测试夹具复扫（输出到 study 以外），已收录的文件及哈希必须与原清单完全一致；`unresolved_references` 只允许减少，减少的每一条都应是命令示例。逐条列在 PR 里。
