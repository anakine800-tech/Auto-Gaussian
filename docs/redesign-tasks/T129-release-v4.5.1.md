## 要做的

### 1. CHANGELOG v4.5.1

**后端，升级须知**（放在本节最前面）：
1. **常驻监控改为直接运行 `ag monitor`**（T127）：认证失败和主机指纹失败的检测已进入后端，不再需要本机包装脚本。LaunchAgent 样例见 `docs/ops/launchd/local.autogaussian.monitor.plist.example`。升级步骤见 `docs/OPERATIONS.md`。
2. **监控行为变化**（T127）：
   - 同一入口连续失败 3 次后开始退避，间隔逐次翻倍，最长 600 秒，成功一次就恢复；
   - 认证失败或主机指纹失败只暂停该入口，其他入口照常采样。恢复方式有三种：改该入口的配置、重启监控、修复后手动重试并确认；
   - stdout 默认每个采样循环输出一行摘要，加 `--json` 才输出完整快照；
   - 新增 `ag monitor --retry <入口> [--auth-fixed]`：在本机登记一次立即采样，由运行中的监控执行；
   - 入口可选配置 `monitor_interval_seconds`（30–600）。经转发等慢链路时，PBS 入口建议设为 60。
3. **快照字段只做加法**（`ag-monitor/1`）：新增 `sampling`、`cluster.scheduler`（PBS 也写）、`cluster.hardware.notes`。异构内存这类局限说明从 `hardware.error` 移到 `notes`。v4.5.0 的前端可以读新快照。
4. **Torque 节点内存**：总内存取 `physmem`（不含 swap）；已分配内存只在节点上所有作业都申请了内存时按申请值加总，否则为 null 并附说明。
5. **本机控制文件**：`.ag-monitor/` 根下新增 `watch.json`、`watch.lock`，入口目录下可能出现 `retry-request.json`。同一个缓存目录不允许同时运行两个 `ag monitor --watch`。

**后端，按类别列出的改动**（附 PR 链接）：监控（T127 #329：退避、暂停、手动重试、按入口间隔、一行摘要、Torque 内存、notes；#330：重试被拒时不创建任何文件）；运维（plist 样例、`docs/OPERATIONS.md`）。

**前端，升级须知**：
1. 推荐每台电脑只运行一个操作模式服务；只读模式保留为可选。LaunchAgent 样例见 `docs/ops/launchd/local.autogaussian.frontend.plist.example`。
2. 服务器页：
   - 核数和内存分开判断，局限说明显示为灰色提示、不计入警告；
   - 调度器标签可以从快照内容推断；
   - 显示退避、暂停和下次采样时间；
   - 操作模式下可以“立即重新采样”，认证暂停时须先确认。

   需要配合 ag 4.5.1 使用：ag 4.5.0 没有 `--retry`，会被判为无效输出。
3. 重新构建前端，重启服务；操作版令牌会更换，已打开的页面要刷新。

**前端，内容汇总**：T128 #38。

**两份 CHANGELOG 都写明**：各项的真实验证结果见对应 PR；发版不等于部署完成，部署结果另行记录。

**已知问题**（两边按实际情况写，至少包括）：
- 监控仍是串行采样。经转发时单条 SSH 约 10–20 秒，一轮可达 100–150 秒，手动重试最多要等当前那一个入口采完。
- 电脑睡眠期间不采样；刚醒来的一两轮可能因网络未就绪而失败，并进入退避。
- 睡眠醒来后 `next_sample_at` 可能显示为已过去的时间（前端，后续修正）。
- 核数和内存都未知时，硬件说明会重复显示一次（前端，后续修正）。
- 前端 `autog_frontend/__init__.py` 的 `__version__` 仍为 4.0.0。
- 沿用 v4.5.0 的已知问题中仍然存在的条目。

### 2. 新建 `docs/OPERATIONS.md`（公开；全部用占位符）

读者是负责人和运维会话。至少包括以下各节，写成可以照着执行的步骤：

1. **标准更新步骤**：
   - 确认没有 `ag submit`、`ag fetch`、reparse、catalog 写入正在进行；
   - 备份（第 2 项）；
   - 两个检出同步到目标 tag；
   - 按 README 更新依赖、构建前端；
   - 修改配置（如有）；
   - 按第 3 项替换或重启 LaunchAgent；
   - 逐入口 `ag doctor`；
   - 按第 4 项观察。
2. **备份规则**：带日期的私有目录（0700）；每个文件记 SHA-256；先备份后改；写本地变更记录（日期、原因、负责人原话、改动、备份位置）；旧文件移入备份目录，不直接删除。
3. **常驻服务**：
   - 监控、前端各一个 LaunchAgent，按两个 plist 样例填写占位符；
   - 加载、卸载、查看状态的通用命令；
   - 日志位置为占位符；
   - **回退步骤**：卸载新服务 → 从备份恢复旧 plist → 重新加载。
4. **部署观察标准**（R3）：
   - 记录每步耗时；
   - 首轮所有入口快照写出限 180 秒；
   - 心跳（`watch.json`）不超过 90 秒；
   - 判定“停更”之前先查睡眠记录（`pmset -g log` 的 Sleep/Wake），睡眠导致的空档不算故障；
   - 每台观察 30 分钟；观察期间保持接电源、开盖。
5. **停止条件**：
   - 任一入口进入 `paused`（认证或主机指纹）；
   - 监控进程退出或反复重启；
   - 排除睡眠后心跳仍超时；
   - 快照字段异常；
   - PBS 入口在非睡眠时段连续失败 ≥5 次。

   以下情况**不是**停止条件：Slurm 入口偶发普通失败并正常退避；醒来后的首轮失败。
6. **采样间隔建议**（R1），以及“经转发时一轮可能 100–150 秒”的说明。
7. **连接方式切换（通用）**：
   - 直连不可用时：确认没有 `ag submit` 正在运行；把受影响入口的 `ssh.host` 改为预先配置好的转发别名（`<HOST>` → `<HOST_FORWARD_ALIAS>`）；先跑 `ag doctor`，确认快照恢复后再做其他操作；
   - 直连恢复后改回原值；
   - 转发别名必须沿用原服务器已核对的主机密钥（例如 `HostKeyAlias`），保持严格校验、非交互认证；出现指纹提示或变化就停下。
   - **不写工具名、别名后缀、端口和中转方式。**
8. **两台电脑的差异怎么记**：仓库只记“允许存在哪些差异”（检出位置、连接方式、词表行数），具体值只记在各自本机的变更记录和私用交接里。
9. **公开仓库保护**：hook 与本机词表（引用 `DEVELOPING.md`），扫描时要指定检出和 HEAD。
10. **手动重试与暂停恢复**：`ag monitor --retry` 和 `--auth-fixed` 的用法；暂停后先修复密钥、隧道或 known_hosts，再重试。

**不得出现**：主机名、IP、用户名、本机或服务器路径、队列和分区名、研究内容、转发工具名和别名。
