# T217B — UNKNOWN 开始回执晚到绑定

## 目标与事故

提交已发生但响应丢失，随后唯一作业名查询无匹配时，现有 UNKNOWN 路径可能遗漏该 Attempt 的开始回执。仅在固定只读接口取得合法且可证明属于该入口的 `ag-start.json` 作业身份后，复用一次性晚到绑定，再走原状态观察；不重传或重提同一 Attempt。

## 范围

- 可改：`ag/src/ag/status.py`、`submission.py`、`pbs.py`、`slurm.py`、`remote.py`、`transport.py`、`node_targeting.py`（仅必要证明复用，保持 T215 语义）；相关 `ag/tests/test_*`。
- 文档：本任务卡、`docs/DEVELOPING.md` 的对应状态说明、`ag/README.md` 的对应 UNKNOWN 说明、`docs/LESSONS.md`。
- 不改模板、autonomy/CLI 或 T217A/T217C 逻辑；不新增提交或授权绕过。不触及真实配置、研究 study、SSH、提交、取消或部署。

## 实现边界

保留 manifest、冻结脚本/远程目录、调度身份/入口、claim、账号/唯一作业名/编号验证及最终本地写入围栏。已有绑定不覆盖；重复字段、无效字节、链接、矛盾、错入口、错误作业号和竞态均拒绝。PBS/Slurm 作业号不能只检查非空。Torque 不依赖 `qstat -x`，不虚构未支持的历史证据。现有证据无法证明入口归属时，提出具体范围内选项后等待决定，不降低核验标准。

无匹配作业且无开始回执时仍 UNKNOWN，由人按已有 `resolve-attempt` 处理；已绑定运行中作业未观测不改记 UNKNOWN；正常队列匹配保留原路径。

协调方已采用“冻结提交来源证明”作为负责人第 5 项的实现解释：完整冻结 bundle/脚本与配置、
原 claim/摘要/授权/journal、固定目录回执构成入口来源链；自主另核原 reservation 账号和 dispatch。
有精确调度记录时交叉核验，没有时不要求 Torque 历史记录重新出现。这不是新增负责人原话。
`start_reconciliation.source=frozen-submission+ag-start.json` 明示来源推导；回执本身只有时间与号码，
不含账号/名称/队列。手动账号来源为当前 SSH 身份，自主为交叉核验后的不可变 reservation。
信任受控 Attempt 目录的回执来自已提交脚本；没有其他矛盾的人为植入合法外来 ID，现有模板不能
独立辨识，不声称覆盖这种拒绝。该局限在敏感送审中显著保留。

生产仅修改 `status.py` 与 `submission.py`，复用已有安全读取与一次性绑定，不新增远程命令。

## 离线验收

- 手动及自主：qsub 已发生但响应丢失，队列无匹配而合法开始回执存在，允许一次绑定并继续状态判断，全流程 qsub 次数为 1。
- 无作业无回执保持 UNKNOWN、不重提；正常队列结果走原路径。
- 非法/错入口/既有绑定冲突/文件竞态/失效租约均拒绝。
- 隔离 HOME、假 Transport，局部定向回归；全量单元测试由当前 head 的 CI 执行，不本地反复全量。
