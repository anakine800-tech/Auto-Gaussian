## 要做的

1. 去掉“已有作业/已分配核数/已分配内存/具名排队请求即一概拒绝”的策略。保留精确节点身份、allow/deny/restricted、合法状态、总slots与档位映射、总内存规格和现有一致性核验。
2. 必须把正常的占用状态与离线、故障、未知状态分开。按已支持 PBS 输出核对可调度状态，不把删除 state==free 检查变成任意字符串放行。对读数矛盾不能猜可用。
3. 每节点申请仍按注册总slots的1/2或1/4映射，不按剩余核数缩减。当前不足但总规格合法可排队；已有本人和其他用户任务同等处理，具名排队请求不构成独占预约。
4. 候选增量提供 `selectable` 布尔值及原因，并附 T156 的容量结果；保留既有 status 的显示含义，不把 occupied 重标成“空闲”。旧前端可以继续保守禁选，新前端 T158 使用 selectable；没有该字段时沿旧逻辑。
5. candidates、prepare、确认后及上传后 fresh_check 采用同一策略。两次实时复查仍须进行；出现新占用本身不再失败，但总规格变化、目标消失/歧义、禁用或真实错误仍按既有规则停止。复查失效不自动换节点或重提。
6. 新增展示所需的分配内存未知只影响容量提示，不新增提交禁令；本来就必需的总规格、确切身份等检查保持，不能借“未知只提示”绕过旧检查。
7. 保留一个批次只提交一个 targeted Attempt、启动 PBS_NODEFILE 守卫、提交后 placement 核验、每Attempt至多提交一次以及所有账号/共享入口限额。
8. 不改变既有 manifest/node_target 结构、已保存脚本或bundle；不编辑旧Attempt。
