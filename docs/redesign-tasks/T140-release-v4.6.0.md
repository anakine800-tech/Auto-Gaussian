## 要做的

### 1. CHANGELOG v4.6.0

**后端，升级须知**（放在本节最前面）：

1. **catalog v2（T131）不能降级。** 第一次写入 v2 事件的命令必须带 `--upgrade-catalog`；升级后，ag 4.5.x 会拒绝该 study 的 journal，前端 4.5.x 会把它显示为未登记。所以：
   - ag 和前端必须同时升到 4.6.0；
   - 已升级的 study 不能再用 4.5.x 打开或写入，也不能靠删行降级；
   - 两台电脑都部署完成、并在研究用计算机上完成一次合成试写之前，真实研究 study 不写 v2 事件（R6）。
2. **SSH 连接超时（T130）。** 入口级 `ssh.connect_timeout_seconds`，整数 15–60，默认 15；命令总超时、上传超时和下载无进展阈值自动顺延（值 − 15）秒。经转发的 PBS 入口建议设为 40。回退到 4.5.1 时，必须一并恢复旧配置。
3. **新命令和新输出只做加法：**
   - `ag scan-path`（T136）：一维扫描沿程的成键、二面角和接触变化；`ag scan-peak` 并入同一份诊断，峰附近有问题时在输出最前面警告；
   - `ag scan-peak --gaussian-ts --route`（T133）：从扫描峰生成 TS 输入草稿，可选 `--register-candidate`；
   - `ag qst-endpoints`（T134）：两个已取回的端点 + 人给的完整映射 → QST2 草稿，对称歧义时报错；
   - `ag g0`（T137、T138）：DFT 之前的本地诊断，只有输入完整性和几何损坏两类硬拒绝，其余是标记和排序；可选模式投影；`--record` 写入 diagnosed 结果；
   - `ag profile`（T135）：新增 `lowest_ts` 和最低 TS / 系综 / 差值三个数。
   - 所有草稿都不含 Link0；prepare 仍要求先补匹配档位的 `%nprocshared`。
4. **卡片（T139）。** ts、irc、profile、kinetics、crest-screen 五张卡修订了 TS 初猜的口径，ts 卡新增“TS 初猜工作流”。Skills 通过软链接指向检出，检出更新后卡片随之更新；研究会话须重新读取卡片。
5. G0、scan-path、catalog 状态都是登记和诊断，**不是门禁，也不是科学验收**；提交审批规则不变。

**后端，按类别列出的改动**（附 PR 链接）：连接（T130 #332）；catalog v2（T131 #334）；TS 初猜输入（T133 #335、T134 #336）；扫描诊断（T136 #337）；G0（T137 #338、T138 #339）；profile（T135 #333）；卡片（T139 #340）。

**前端，升级须知：**
1. **通道与候选面板（T132）：** 展开 v2 登记对象时显示通道状态、候选台账、负责人声明原话和整体稳定声明；只读，不写 catalog，不调用 ag。v1 对象显示不变。
2. **必须配合 ag 4.6.0：** 前端 4.5.x 会把 v2 catalog 显示为未登记。
3. studies 根目录中以 `_` 或 `.` 开头的目录按容器处理，不再列为 study。
4. 重新构建前端并重启服务；操作版令牌会更换，已打开的页面要刷新。

**前端，内容汇总**：T132 #40。

**两份 CHANGELOG 都写明**：各项的真实验证结果见对应 PR；发版不等于部署完成，部署结果另行记录。

**已知问题**（两边按实际情况写，至少包括）：
- catalog v2 升级后不能降级（见升级须知第 1 条）。
- `ag g0` 的原子顺序检查只比较元素序列，同种元素互换查不出来；立体标签必须针对与候选完全相同的几何生成；批量诊断时，频率段有歧义会使整批报错而不是跳过。
