# T184：自主运行的计划、状态、日志与运行锁

## 分支与目标

- 分支 `codex/t184-autonomy-state`，最新 main；对应 V4.8 W4 及 W11 的版本记录。
- 目标：用纯本地 ag 命令保存可确认的计划、运行状态、可恢复的互斥锁和追加日志。科学推断及远端动作不进入本模块。
- 事故依据：定时会话崩溃后无法续接、重复会话并发推进同一 study、过期锁被接管后旧会话恢复继续写入、计划改变却继续使用原批准。
- 依赖：可并行开发，合并前承接 T182 的规则；T183 的固定版本记录在实际版本中，不硬编码历史版本。

## 允许改动的路径

- `ag/src/ag/autonomy.py`、`ag/src/ag/_autonomy_store.py`（需要时新增）：纯本地命令和文件操作。
- `ag/src/ag/cli.py`：挂载本地子命令及 local_only 配置选择。
- `ag/tests/test_autonomy.py`（新增）、`ag/tests/test_cli.py`（存在且需要时）：合成测试。
- `ag/README.md`、`docs/DEVELOPING.md`：实际命令、数据字段和不覆盖旧证据的说明。
- `docs/redesign-tasks/T184-autonomy-state.md`：本单。

## 要做的

1. 先核对既有 study 路径、原子写入、锁、journal 和 CLI 注册模式，复用其适用部分；不新造调度框架。新子命令入口统一为 `ag autonomy`，具体子命令由实现确定并写实际帮助与 README。
2. 在 study 的 `autonomy/` 下管理计划、状态、追加日志三类记录及运行锁。计划经确认后字节不可变，保存 SHA-256；修订用新计划，须重新确认。动态对象不写回计划，写在状态/日志。
3. 计划须表达目标、比较组/方法口径与机理范围、主/小体系判定规则、耗时预估、Attempt 总数/有效期以及实际 ag 提交和 RDKit/GoodVibes 版本；不得凭创建计划即伪造负责人确认或提交批准。
4. 状态包含本轮身份、运行/暂停/结束、当前计划哈希、版本、简短摘要、待人决定、动态对象与补救/取消/改投/Attempt 计数。不同轮次可追溯；损坏、不一致或无法核验的记录拒绝继续，绝不按零计数。
5. 日志只追加；状态可原子更新。崩溃留下的不一致必须可被识别，不静默丢日志或把已执行动作退回未执行。接管要记录证据；不要擅自重写旧日志。
6. study 级跨命令锁记录唯一运行持有者、开始/过期时间，单次最多 60 分钟，锁 90 分钟过期。并发开始只有一个成功；过期接管必须使旧持有者失效。每次写入核验当前持有者与期限，旧持有者不能续写、解别人的锁或恢复提交资格。保留短操作的 OS 互斥来封住检查/写入竞争，不能仅依赖可覆盖的时间戳文件。
7. 暂停不等待持锁会话完成：在任意会话请求暂停应可安全发布，并立即阻止后续准备/提交/补救动作。暂停后只允许唯一拥有当前锁的会话观察、取回和整理结果；结束退出。恢复须明确请求，不由超时或无回复推定。
8. 提供给后续 submit/cancel 的确定性读取/校验接口，涵盖计划哈希、版本一致性、状态与锁所有权。当前单不接 submit/cancel、不过早宣称已强制所有计算入口；集成由后续敏感工单完成。
9. 暴露只读 JSON 状态/摘要供前端与后续卡片使用；保存的私有正文不进入公开夹具。实际文件布局/字段及行为在 ag README 中说明，协调方依据最终实现编写后续工单，不另建 schema 合同文档。
10. 计数更新必须可追溯且不能任意重置；区分对象、失败类别和本轮。真实提交次数最终以不可变声明/绑定证据核对，不靠模型随手递增声明完成；本单只提供本地接口，后续提交集成负责实际消费。

## 不允许

- 不连接 SSH、初始化 Transport、加载不必要的凭据、提交/取消、运行量化程序或创建定时任务。
- 不修改旧 Attempt、facts、签字、catalog、study.md，不给科研判断打通过标签。
- 不在本单修改本机配置或建立真实运行计划。所有验证使用临时合成 study。
- 不实施未来的通用调度器，不把 run/lease 变成新的项目治理制度。

## 测试

- 合成真实本地并发/进程测试：同时抢锁、崩溃、过期接管、旧持有者恢复、陈旧释放、暂停与准备资格检查竞争；模拟时钟测试60/90分钟边界。
- 计划字节篡改、版本不符、状态截断、追加失败、计数重复请求、符号链接与越界必须拒绝且不破坏既有证据；只读命令不写文件。

## 实施细化（协调审阅）

- 授权轮次与单次唤醒分开：`begin` 记录明确的新轮确认，`start` 获取唤醒租约，`finish` 只结束唤醒，`end --round` 绑定预期轮次并明确结束整轮。整轮结束后普通 `start` 拒绝；两次正常唤醒沿用同一轮，旧轮的延迟结束请求不能结束新轮。
- study 历史累计计数不可重置；同轮跨唤醒、接管和计划修订累计消费不清零。明确 `begin` 新轮才有新的轮内预算，保留旧轮及全局历史。
- 计划或版本不符的当前校验只拒绝，不宣称已自动暂停。T186 须在动作事务持有同一互斥时追加并发布暂停，再结束拒绝路径；本单没有接入真实动作。
- 补充两次唤醒延续、整轮结束后拒绝自动唤醒、显式新轮预算、结束事件崩溃恢复的测试及临时合成 CLI 证据。
