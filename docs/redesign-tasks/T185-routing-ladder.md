# T185：提交阶梯选格与整节点资源

## 分支与目标

后端 `codex/t185-routing-ladder`，一单一PR，最新main；V4.8 W3。输出可复核的下一个资源位置，支持批准的整节点切分；提交时最终规则与阶梯核验由T186完成。
防范事故：将分散空闲核相加、把旧快照当空闲、同轮第一份任务提交后误选第二份位置、chk跨集群、资源已超规格仍排队。

- `ag/tests/test_route.py`、`ag/tests/test_node_targeting.py`、`ag/tests/test_core.py`、`ag/tests/test_routing_ladder.py`（新）：合成回归。
- `README.md`、`ag/README.md`、`docs/DEVELOPING.md`、`docs/redesign-tasks/T185-routing-ladder.md`。

## 要做的

1. 先对照现有route/capacity/node_targeting及T184的最终本轮身份/占用接口。无需把T184整个实现复制进本单；共享接口不稳定时先独立完成纯选格函数与合成测试，协调集成后再接实际记录。
2. 阶梯由本机配置表达入口、顺序节点组、全空/至少空闲核数/作业数条件、资源档位、批次最多放置数、作业类别；不在代码或公开材料硬编码实际节点。真实配置仅由后续运维写入。
3. 扩展只读route入口，依据新鲜快照、作业主/小体系类别、父chk绑定、本轮真实提交占用和等待唤醒历史输出候选与理由。只读命令不SSH、不创建目录或写文件。设计最小的可复核输出供prepare与T186复算使用，记录配置/快照身份，不能依赖模型手写的“已通过”标志。
4. 已部署的route快照要求成功、有效采样间隔及三倍间隔以内；保留过期/缺失/未知拒绝。额度复用全部本人作业与同实际集群入口合并规则，包含未读回的本地预留，不重复叠加已出现在快照中的作业。
5. 同轮两个半节点位置按一次合格批次的剩余容量判断，不因第一份使全空条件变假而意外跳过第二份；也不能在新占用已使第二份不适用时继续放行。案例覆盖监控已/未读回、外来占用与重复命令。
6. 主体系按配置阶梯；SCNet类末级候选须该对象已等待至少一次真实唤醒且本轮运行加排队不足配置作业数上限。兜底每节点/入口至多排一个、全轮至多两个；不能把不同入口同一实际资源当两个排队名额。
7. 父chk作业只在父集群候选中选择，没空位只可在该集群合规排队；不得把没候选解释为允许跨集群复制。小体系优先已占用但可容纳的节点，保留全空位置；不支持的模板/入口仍排除。multiwfn目前能力过滤不得因路由顺序而放宽。
8. 增加整节点切分。资源核/内存仍严格对应档位、max_cores与节点总规格，不能借整节点绕过上限；保留半/四分之一节点的渲染字节兼容和既有共享排队准入。旧manifest/bundle不改。
9. 路由选择必须在prepare前完成；prepare后入口/节点/核数不可变。提供给T186的最终核验接口使用同一选格算法、同一张配置表及可核实的新鲜快照，不另造第二套规则。
10. Gaussian版本只读本地现有facts的核查已完成：可识别值均为G16 A.03，部分历史记录未知；不据此声称服务器当前版本实测，不新增版本路由限制或放宽profile版本核验。
