# T225 PBS 他人作业占用时的具名节点准入

## 分支与目标

从最新 `origin/main` 建独立工作树与 `codex/t225-pbs-occupied-node-admission` 分支。先读 AGENTS.md、本任务单、docs/DEVELOPING.md 和 docs/LESSONS.md。

现场反馈涉及同一 PBS 入口多个节点：目标有他人作业时提交失败，全空且策略允许时可用。节点视图列出占用而作业查询缺少对应记录时，现有具名提交前核验的拒绝可离线复现；该现象不能单独确定调度器配置或所有现场拒绝的原因。承接 T214 的离线设计，原分支无已提交实现。

- ag/tests/：PBS/节点、容量、路由、监控和提交边界的直接回归。
- ag/README.md、docs/DEVELOPING.md、docs/LESSONS.md：可复核语义与限制。
- `docs/redesign-tasks/T225-pbs-occupied-node-admission.md`：本单及实施、验证摘要。

## 验收标准

1. 先从正式现有证据区分准备拒绝、两次提交前核验拒绝、PBS 明确拒绝、已接单排队和程序启动。以脱敏样例保持节点表、可见作业表、CPU/内存证据的对应关系。
2. 覆盖全空允许节点、本人占用、他人占用且证据完整、他人占用但作业表受限、满载及已有具名请求。测试真实节点名之外的任意合成节点，不能按实际节点或入口写死规则。
3. nodes、prepare、两次 fresh_check 和路由使用一致的准入结论，另行表达是否具备即时容量；在证据支持时允许已获站点许可的共享或排队，否则报告具体未知或站点限制。不能从不可见作业推断无人排队，也不能由 CPU 推断可用内存。
4. 证据陈旧、冲突、核位重复、身份或作业归属不清、禁用/限制节点、资源越限均有反例；保留本人账号核算、所有入口共同预留、每次确认、哈希及单次提交。Slurm 行为保持原样。
5. 不得仅以 nodes 显示可选、离线用例为绿或本人作业并行，作为他人占用现场已修复的证明。若站点本身禁止共享，验收为正确反映其限制和可选择的空节点；管理员策略变更另行决定。
6. 对有真实核位占用、他人作业详情受限的场景，区分安全排队所需的本站策略、本账号完整额度与节点总规格，和立即启动需要的其余证据。若只能补足一部分，应逐项保留未知并指出阻断；实现须提供材料齐备时的正例，及材料不完整的反例。

## 实现与未决站点事实

- 允许名单、节点规格与已配置档位之外，受限明细的正例需要同服务器、队列、目标节点的站点投递许可；同时要求按实际登录账号独立枚举的活动作业号与可见本人明细对应。聚合队列数没有逐账号信息，原监控的 own 直接派生自同一份作业表。两者均无法独立补全本人明细。
- 受限视图仅使用现有节点核位和固定的本人 `qselect` 查询。核验还包括运行、排队和挂起的本人申请、可核实的各入口本地预留、共同限额。明确只准投空节点的策略由 `empty_only` 表达。旧占用快照缺逐作业核位核验时等待新采样。
- 无站点许可、独立查询不可用、数组或完整作业号有歧义、本人集合互不相符、预留无法核算时，显示相应阻断原因。CPU 余量不能补足缺失的分配内存；可申请排队、物理容量、调度器接单及程序启动分别有证据。
- 本次没有同入口允许跨账号占用期间投递的站点记录，也没有该站点 `qselect -u` 的完整性样本。真实入口继续以既有配置工作。增加许可前须取得站点对目标队列、节点和本账号查询覆盖范围的确认；站点允许排队和允许同时运行须分别核实。

## 离线验证

依赖安装在临时虚拟环境中，命令从本工作树导入 ag 源码，沿用仓库的 HOME 隔离和假 Transport。具名节点测试文件 227 项通过。受限明细正例经过一次监控、两次新鲜本人查询、一次假派发，取得确切排队绑定。共享入口反例计入 24 核未观测预留和 4 核可见本人作业，在 48 核共同上限下拒绝再申请 24 核，允许 12 核档位。

### 空节点限定与已有具名排队作业

确认后、上传后才出现该等待时，两个阶段均为 0 次目标假 qsub。
完全空节点以及获准排队节点各有一次假接单正例。相关定向 6 项通过。
