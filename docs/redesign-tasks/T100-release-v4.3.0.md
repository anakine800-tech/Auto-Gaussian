## 要做的

### 1. 后端 CHANGELOG v4.3.0

按类别写清改了什么、对使用者有什么影响，附 PR 链接：

- **结构与开题：** T80 开题物种核验；T93 开题完整性检查、study.md 骨架与首批准备（止于准备，不提交）；T86 按显式内坐标构建复合物；T90 按约束组枚举复合物候选；T91 TS 产物立体标签与通道归属建议（建议须人确认）。
- **审阅与分析：** T79 `ag irc-review` 逐方向 IRC 审阅与路径导出；T88 IRC 路径 XYZ 哈希；T89 拓扑比较识别固定编号下的共振等价；T84 `ag snapshot` 运行中日志快照（不是结果）；T92 `multiwfn` 模板（IGM / IGMH）与 `ag nci-report`（`ag-nci/1`）。
- **一致性与正确性修复（使用者须注意）：**
  - T82：thermo / profile 现在拒绝口径不一致的输入（方法、基组、色散、溶剂、基函数形式、程序版本、组成、电荷、多重度），以及缺少正常终止或有虚频的结构。以前能生成的部分报告，升级后可能被拒绝，这是有意的。
  - T83：prepare 对笛卡尔输入做更严格的检查，并在卡片中写明数值设置。
  - T99：Gaussian route 被换行截断（如 `Fre`/`q`）时，旧版本会把 Opt+Freq 的顶层终止状态误判为 `incomplete`。现已修复：热化学来源绑定到产生频率的子任务；由 chk 继承的溶剂只认本段打印的参数；方法前缀按多重度补全后比较。
- **规则与文档：** T81 卡片要点与出处；T85 逐条授权的只读远程查看例外。

**升级须知（单独一小节，放在最前）：**
1. 升级后，用旧版本生成的 Opt+Freq facts 可能有 T99 所述的误判。建议先运行 `ag facts <Attempt> --reparse --dry-run --out <study 外的新 JSON>` 查看差异，确认后再正式执行；正式执行会把旧 facts 归档到 `facts-history/`，并列出 study 中引用旧哈希的文件，涉及已签内容的须由负责人重新确认。
2. T82 之后，thermo / profile 可能拒绝以前能通过的输入，按报错信息核对口径，不要绕过。
3. Multiwfn 为可选：只有使用 `multiwfn` 模板时才需要在本机配置 `programs.multiwfn`。目前只支持 default（PBS）集群。

**已知问题：**
- 取回时单个文件有固定 60 秒上限，网速慢时较大文件（例如 cube）可能超时；已列入后续修复。
- 前端快速比较尚未同步 R/U 前缀规则：单重态下 `M062X` 与 `RM062X` 会被判为口径不同而拒绝比较；已列入后续修复。正式结论以 ag 报告为准，不受影响。
- 组里集群上作业结束后，PBS 有时仍短暂显示 R（观察到约 6 分钟后自行消失），ag 会把它计入已占用核数（只会多算）。

**写明：** 各项真实验证结果见各 PR 评论；发布不等于科学验收。
