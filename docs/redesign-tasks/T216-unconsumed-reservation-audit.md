# T216：未消费手动预留兼容与只读全量核算体检

## 问题与目标

自主 prepare 曾在创建 Attempt、提交之前被历史手动 prepared 记录阻断：旧 journal
不能通过新审计，而 fallback 只接受非终态已提交记录。本单用合成样本修复核算判断，
不读取或修改真实历史 study，不恢复任何运行授权。

冻结基线：`b929163ca3a05c7df2a549dd8f2d9691fb6e68ee`。
分支：`codex/t216-unconsumed-reservation-audit`；一个 Draft PR，由人合并。

## 已确认口径

- 手动历史记录只有同时满足无 `.submit-claim`、status 为 `prepared`、无
  `submission.json`、status 无作业号，且无 summary 等矛盾文件，才作为未消费排除。
  不依赖旧 journal 能否通过新 audit；返回警告，不改历史文件。
- 正常审计、已消费及自主归属仍保留原约束；status/manifest 重复 JSON key、
  坏状态、符号链接、文件替换和矛盾证据继续拒绝。兼容分支不能绕过自主归属。
- 按上述负责人决定落实：四项硬证据满足且没有矛盾时，旧 journal 坏 JSON、重复 key 或
  非对象条目只记警告，不独立否定未消费；可读条目中已发现的提交授权或非 prepared
  状态冲突仍拒绝。journal 文件链接/替换仍拒绝，不能用坏行掩盖已读到的冲突。
- 提供只读全量核算体检，覆盖真正核算扫描的全部登记与 study/Attempt；局部错误
  不吞后续记录，无法枚举时明确 coverage 不完整。记录可取得的身份、资源、状态、
  分类及拒绝/警告原因，未知保持未知。失败汇总后非零退出。
- 体检只报告，不形成放行凭据，不连接远程，不写文件、目录、锁、登记、journal 或 pyc，
  不修复。负责人补充允许已有 `ssh -G` 本地配置展开，与提交共用核算判定及账号身份，
  避免体检和实际提交口径漂移；这不授权真实环境体检或远程访问。

## 只读体检命令

```sh
python -B -m ag.cli autonomy audit-reservations --json
```

从解释器启动前用 `-B` 禁止 pyc；裸 `ag` 首次导入不保证零字节码写入。
本入口不取得锁，不创建目录或登记，不写状态、journal，不远程连接；仅允许
`ssh -G` 本地展开账号配置。逐条报告失败和警告，局部错误不丢后续记录；无法
枚举/核实的范围明确标 `coverage.complete=false`，拒绝项汇总后非零退出。
结果不构成行动凭据，不自动修复、不恢复旧计划或自主权限。
