## 要做的

### 1. AGENTS.md 第 3.9 条（负责人 10-22 授权）

### 2. 单作业上限与档位（N4）

- PBS 和 Slurm 都按配置的正整数 `max_cores` 校验单作业上限和各档位，不再有 44 的硬编码。
- 写进 README 和配置示例：default 要明确写 44；单作业上限不得超过单台节点的核数（Gaussian 不支持跨节点）。

### 3. 总上限与排队上限（N2）

- `max_committed_cores` 不得小于 `max_cores`，**没有**四倍上限。
- 新增可选的排队上限（字段名以实现为准）：在提交前和确认后都要核对。排队核数包括挂起的作业和适用的未观测预留。同一集群有多个入口时，取各入口设定值中的最小值，和 T101 的总上限规则一致。
- 同时运行上限（72 核）只作为说明性字段记录，ag 不检查。确认框和 doctor 要写明"由调度器执行，ag 未核实"。
- 确认框显示：单作业上限、排队数 / 排队上限、运行加排队数 / 总上限。

### 4. 独立 CREST 路径（N5）

- 可选配置项 `programs.crest.executable`。设了就用它，没设就沿用原来"从 xTB 根目录推导"的方式。配置校验、doctor、模板三处解析路径的规则必须一致。
- 没有配置该项时，旧 PBS / Slurm 模板渲染出的字节**完全不变**，用回归测试锁定。

## 测试

在 `ec6a3c7` 已有的离线回归（汇报为 242 项相关测试，全量 4181 通过 / 19 跳过）基础上，确认覆盖以下场景：

| 场景 | 预期 |
|---|---|
| PBS 单作业 48 核，档位最高 36 核 | 通过 |
| 某档位核数超过 `max_cores` | 拒绝 |
| `max_committed_cores` < `max_cores` | 拒绝配置 |
| `max_committed_cores` = 6 × `max_cores` | 允许（四倍限制已取消） |
| 排队数 + 本次申请 > 排队上限 | 拒绝；确认后重新核对时同样会拒绝 |
| 同集群多个入口的排队上限不同 | 取最小值 |
| 排队数包含挂起作业、非 ag 作业、未观测预留 | 都计入 |
| 未配置排队上限 | 行为与 T101 时一致 |
| default 写 44 | 行为与旧版一致；超过 44 的档位被拒绝 |
| 配置了 `programs.crest.executable` | 配置校验、doctor、模板三处用的是同一个路径 |
| 未配置该项 | 旧 CREST 模板渲染字节不变 |
| 配置的 CREST 路径不存在或不可执行 | doctor 失败，prepare 拒绝，**不回退**到 xTB 根目录推导 |
