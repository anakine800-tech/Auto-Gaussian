# T63：`ag dedup` 局部构象判别（二面角分组、关键距离、接触指纹）

## 分支与目标

- 分支：`codex/t63-dedup-local-descriptors`；基于最新 main，一张任务单一个 PR。开发机做。
- **目标：** 给 `ag dedup` 增加**可选**的局部判别。整体 RMSD 很小、但关键二面角落在不同分组的构象**不合并**；同时为每个构象报告关键距离和接触指纹，供审阅。
- **要防的事故：** 大分子（M1 约 84 原子、TS 同量级）里，决定选择性的局部构象差异（一个转子转 120°、酰基 s-cis/s-trans 翻转）会被整体 RMSD 稀释。两个家族的 TS 一旦被合并成一个，就会少算一个通道内的家族，有效能垒和选择性都会偏。N2 用约束 CREST 采 TS 构象时就会遇到。
- **典型用法（写进文档，示例用通用编号，不写研究 A 分子）：** 酰基二面角 a–b–c–d 按 s-cis / s-trans 分两组（分界 ±90°）；新键转子二面角 e–f–g–h 按三组分（中心 0°、+120°、−120°，分界 ±60°、180°）；报告某个配位原子对（如 B···O）的距离。
- 资料：`ag/src/ag/dedup.py`、`ag/src/ag/geometry.py`；v2.7 的 `archive/skills/auto-g16-conformer-search/scripts/conformer_core.py`（周期二面角差、关键距离、接触指纹），只提取算法，不移植旧合同和命令。

## 要做的

1. **新参数（都可选，可重复）：**
   - `--dihedral-bins A,B,C,D:b1,b2,...`：四个原子编号（从 1 开始，与 XYZ 行号一致），后面是分界角（度，−180 到 180，升序）。分组按周期处理：分界之间是一组，最后一个分界到第一个分界（跨 ±180°）是一组。可选写成 `A,B,C,D:b1,b2@名称1,名称2,...` 给组命名；不命名时用 `bin1`、`bin2`……
   - `--report-distance I,J`：只报告距离，不影响合并。
   - `--contact-atoms I,J,K,...` 加 `--contact-cutoff X`（Å，默认 3.0）：对这组原子与其他所有原子，记录距离小于阈值的原子对集合（接触指纹），只报告，不影响合并。
2. **合并规则：** 给了 `--dihedral-bins` 时，两个构象的分组组合（所有指定二面角的组号元组）不同，就**一定不合并**，不管 RMSD 和能量差多小。分组相同时，按原有的 RMSD、能量差规则判断。
3. **边界处理：** 二面角离任一分界不到 5° 时，在该构象上标 `near_boundary: true`；分组照常分配，但在输出里列出来，供人工看。不自动改变分组。
4. **输出（只新增字段）：**
   - 顶层：`descriptors`，记录所有二面角定义、分界、组名、距离对、接触原子和阈值；
   - 每个保留构象和每个被合并成员：`dihedrals`（度）、`bins`、`near_boundary`、`distances`、`contacts`（排序后的原子对列表）；
   - 被合并成员额外记录：与代表构象的**周期二面角差**最大值（度），方便审阅是否合并得太粗；
   - 因为分组不同而没有合并的“近重复”构象对（RMSD 低于阈值但分组不同）：在顶层 `kept_by_bins` 里列出，写明 RMSD 和各自的分组。
5. **不给新参数时，输出逐字节不变**（对现有测试夹具，与 main 的输出对比哈希）。
6. **校验：** 原子编号越界、四个原子有重复、二面角未定义（共线）时报错并指明是哪一个定义。

## 测试

- 正丁烷：gauche+ 与 gauche− 的 RMSD 可能很小，但按 C–C–C–C 二面角三组分时不合并；不加分组参数时行为与 main 相同。
- 周期边界：+179° 与 −179° 落在同一组（跨 ±180° 的那组）；分界附近 ±4° 标 `near_boundary`。
- 多个二面角组合；组名写法；参数格式错误、编号越界、共线二面角报错。
- 被合并成员的最大周期二面角差计算正确（如 350° 与 10° 的差为 20°）。
- 距离、接触指纹与独立计算一致。
- `--source` 多路线模式下同样生效；`kept_by_bins` 列表正确。
- 不加新参数时，现有夹具输出的哈希与 main 一致。
- `PYTHONPATH=ag/src python -m pytest ag/tests skills-next -q -rs`；敏感扫描与 `git diff --cached --check`。
