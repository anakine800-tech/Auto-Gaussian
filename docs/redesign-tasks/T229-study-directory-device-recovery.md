# T229 设备号变化后的研究目录核验

## 目标

同一研究目录跨挂载后，临时设备号可能变化。已有登记会使 PBS 账号核算在准备新作业前停止。为能够独立证明连续性的目录恢复正式核算，同时保留无法核准的目录及作业原始记录。首次验证使用已有本地材料和隔离测试环境。

## 允许改动的路径

本任务单、`ag/src/ag/autonomy_submission.py`、`ag/src/ag/autonomy.py` 和必要的现有本地文件读取模块 `ag/src/ag/_autonomy_store.py`，以及直接相关的 `ag/tests/`、`docs/DEVELOPING.md`、`docs/LESSONS.md`。若需要新的本地证据读取模块，可以在 `ag/src/ag/` 增加一个专门处理目录身份的模块。实际方案先从现有身份及核算入口收窄。运行版安装、现场配置、账户资料及真实作业均不进公开仓库。

## 验收

1. 在两个不同历史设备号的合成场景重现现状。只有能够认证历史与当前是同一文件系统和目录，或有独立可核的完整核算依据时，才恢复正式 PBS 核算。相同路径、inode、同名文件、已结束的写入动作、两个实时作业数相同均不能单独证明连续性。旧格式仍可读，同设备的正常行为保持。
2. 用同一账号的外机作业、跨研究根已提交未回显的预留和无登记的早期同级目录测试。账号额度取已有口径，真实在途逐笔计入，已回显作业只计一次。换卷、目录替换、链接、缺失证据和相互矛盾的来源应停止；捕获读入过程中的目录变化。
3. 权限只覆盖身份核验所需的读取。不能用命令参数、环境变量、人工给出的核数或一份自填 UUID 让提交通过。每个旧 Attempt 的声明、不可变记录、输入和绑定仍保留，不能因此重提、取消或获得自主写权限。
4. 对本机历史材料优先尝试由可信生产者保留下来的同期卷标识或等效独立证据。若关键证明缺失，说明覆盖到哪个时间段和哪些登记，保持旧记录拒绝，不宣称原账号已恢复。若有更简单、能覆盖同一风险的现有入口，优先复用。公开部分只用合成数据。
5. 先在隔离目录用正式入口复验正反例、账号限额、确认与派发前刷新。合并前用开发机单独的非研究目录和经核验的受审代码验证适用的本地读操作，留存输入摘要、前后结果和未覆盖的理由。生产登记、部署和新实投各按各自授权办理。原账号上线和实际 PBS 接单仍由独立部署验收单跟踪。

## 交付

独立分支和一个 PR，第一行 `Task: T229`；说明采用的证据、当前历史格式可恢复的范围、源码级反例、真实验证边界和测试。公开前完成暂存扫描，按仓库要求复跑回归。
