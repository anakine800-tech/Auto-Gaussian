## 要做的

1. 从 xTB 官方文档、官方源码及可取得的公开小分子样例核对实际文件，而不是只凭二手说明。每项记录官方 URL、所对应版本或 commit、访问日期及精确相关章节/源码位置。
2. 建立有限来源表：程序/版本、Hessian 生成命令来源、计算方法与溶剂、原子数及原子序、几何、质量/同位素、文件格式与单位、计算结束证据、可核验的文件哈希。未知项明确未知，不把文件名当来源。
3. 明确要导入的是 Cartesian Hessian 还是已求出的 normal modes；逐项说明矩阵布局、对称性、原子/分量次序、坐标单位、能量单位、质量加权约定、特征值到频率的转换、平动/转动处理及零值/负值约定。每一步有来源；不从 Gaussian 的位移惯例直接类推 xTB。
4. 用最小合成矩阵在临时内存/目录检验单位、维数、对称性和已知特征值；这些只是转换推演。若取得格式可靠的公开小分子原始文件，再做只读格式核验，并分别标记“合成推演”和“真实格式样例”。不为补样例提交计算。
5. 本地导入规格应绑定几何文件、原子对应声明、Hessian/模式文件的原始字节哈希，并引用 T162 的映射方向与未知处理。明确导入的是新的分析记录，不修改原 Attempt、候选或历史 evidence。
6. 给出输入不足时的行为：缺几何/单位/版本来源、维数不一致、非有限数、格式歧义、哈希变化、原子对应缺失时不生成貌似可信的模式；说明哪些应为导入错误、哪些仅标为未核实。不能因此禁止 DFT 提交。
7. 规格列出后续最小实施路径、拟新增的本地入口、旧 Gaussian 模式兼容方式和合成验收场景。若官方证据不足以定稿某格式，列出准确缺项和可接受的最小补充资料；不得把未证实的格式写成可支持。
8. 把“新增 xTB Hessian 生成模板/远程命令”明确留作另一张后续单，需另核对模板白名单和真实验证。此处不得顺带承诺、选择或运行科学方法。
