### 1. 替换规则（逐条应用，在 PR 清单里写明每处用了哪一条）

| 原内容 | 替换为 |
|---|---|
| 未发表课题的名称、缩写、体系描述、反应类型 | "研究 study"或"某研究课题"；需要区分时用"研究 A / 研究 B" |

### 2. 通用扫描（P5，进仓库）

- `scripts/scan_public.py` 只查**通用模式**：IPv4/IPv6 地址（排除 127.0.0.1、0.0.0.0、文档保留段）、`/Users/<名字>/`、`/home/<名字>/`、`C:\Users\`、非 noreply 的邮箱、`BEGIN … PRIVATE KEY`、常见令牌前缀。每个模式附一个合成示例做自测。
- 允许用 `# scan-public: allow <原因>` 逐行豁免，豁免必须写原因。
- CI 中对整个仓库跑一次扫描，有命中就失败；`archive/` 的命中在 P4 授权之前只告警，不判失败。

### 3. 本地词表检查（P5，不进仓库）

- `.githooks/pre-commit` 先跑通用扫描，再读取本地词表 `~/.config/auto-gaussian/sensitive-terms.txt`（每行一个词，可以写正则；文件不存在就跳过并提示）。命中暂存区的内容就拒绝提交。
- `docs/DEVELOPING.md` 写明启用方法（`git config core.hooksPath .githooks`）和词表的位置。**词表内容由负责人和 Codex 在开发机上维护，不出现在任何仓库文件、工单或 PR 里。**
- 研究用计算机同步后，也照此启用一次。

### 4. 以后写东西的规矩

- `docs/LESSONS.md` 加一条：仓库是公开的；工单、PR、评论、提交说明、夹具里不写研究课题的名称、编号、结构、数值，也不写主机、账号、队列和路径。需要指向具体研究对象时，只在私下转发的消息里写。
