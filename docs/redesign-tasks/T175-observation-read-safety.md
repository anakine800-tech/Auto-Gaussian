## 要做的

### 1. 先确定兼容的最小实现

1. 在代码和已保存的非敏感环境证据中核对各目标平台实际可用的 shell/工具能力；不能把开发机能力直接当作集群能力。
2. 当前 receipt/output 使用 shell 和 GNU 风格 stat；`log_snapshot` 已使用固定描述符及 Linux procfs 身份检查，`parent_chk_remote` 使用 Python 3.6 及以上的 descriptor-relative/no-follow 打开。但 doctor 中父 chk 能力不可用并不阻止其他基础操作，因此父 chk 的可选依赖不等于所有 status 路径已有 Python/procfs 前提。
3. 选定能拒绝链接、保留路径边界、限制读取字节且有目标兼容依据的方案。可以借鉴现有实现，但不得直接调用父 chk 的写入分支、扩大其 API 或复制通用远程执行框架。
4. 不预定必须新增 Python、procfs、第三方包或服务器安装。如果方案确实需要把原先可选能力变成普通观察的必要能力，先提交具体兼容影响和替代方案，取得决定后再落实；不能静默改变普通 status 的环境门槛。
5. 在本单验证说明中写清“哪些错误能确认缺失、哪些只能拒绝/无法核实”和“何时固定文件身份”。只增加一次 `test ! -L` 或仅比较大小不算关闭读取窗口。

### 2. 缺失分类

1. 仅在能确认目标确实不存在时输出原有 absent 语义。EACCES、ENOTDIR、I/O 错误、身份变化及无法核实的工具错误均不得降级成 absent；不靠人类语言错误文本的英文后缀判断 errno。
2. 区分目标文件缺失、祖先确实缺失、祖先不可进入、中间组件不是目录、静态或悬空链接、目录/FIFO 等非普通对象。普通观察对“祖先真实缺失”的兼容策略须明确；不能把严格不完整取回的父目录要求放宽。
3. 对同一个声明文件列表，普通模板与 Multiwfn 批量循环采用同一分类语义。保留 Multiwfn 的命令长度上限和固定输出列表，不恢复逐文件展开导致的 SSH 参数过长问题。
4. output 只观察大小/mtime 时，不能把“文件不可读取内容”与“无法取得元数据”混为一谈；本单不把全部 output 观察升级成内容读取。
5. 失败保留受限的阶段/类别说明，经现有脱敏路径输出。不得吞掉所有原因后只留下无信息 unreadable，也不得把私有绝对路径、账号或原始敏感 stderr 放进公开测试/PR。

### 3. 回执身份及有界读取

1. 仅允许 `ag-start.json`、`ag-exit.json`，保留白名单、配置根目录、Attempt 相对路径和每级非链接检查；不开放任意文件读取入口。
2. 读取必须来自已检查的同一普通文件。对检查后等长普通文件替换、链接替换、父目录替换分别有明确拒绝行为；不能先读替换对象内容再仅靠 JSON/大小判断它可信。
3. 保留 4096 字节上限，覆盖读取过程中增长、缩短、失败及非普通对象。FIFO 等对象不能造成无限等待；读取失败不能留下可被接受的部分 JSON。
4. 保持合法原有回执原始文本的解析兼容：PBS/Slurm 确切作业绑定、带时区时间、重复 JSON 键拒绝、返回码范围不变；不修改回执格式、manifest 或已提交绑定。
5. 不必为修复引入新的用户可配置开关、状态或自动重试。无法安全观察时停止该观察并说明原因；不自动转用较弱命令。

### 4. 错误不得成为状态证据

1. receipt、任一声明 output 或完成标记后的二次 output 观察失败，均不得追加缺失/稳定证据，不得据此推进 stalled、finished、interrupted 或不完整取回资格。
2. 对本单正常已绑定作业的失败分支，核对 status.json 原始字节、observation、unchanged_since、incomplete_observations 等没有因失败观察被改写；允许现有本地诊断日志追加，不伪造成功状态。UNKNOWN 既有只读核对机制不改。
3. `incomplete_output_observation` 保留可进入父目录、非链接、声明文件和必要读取权限检查；无法核实时仍拒绝。父目录不存在不能被本单普通观察的兼容路径错误接受。
4. 不修改全局 state.TRANSITIONS、计时规则、提交/取消/重提行为、transport 重试策略或输入输出发布协议。

## 测试

- 使用隔离本地临时目录和非研究合成 manifest，先复现当前两个缺陷，再验证修复版。保留可确定触发检查/打开窗口的注入，不用概率性并发循环代替最小复现。
- 文件系统矩阵至少包含：普通可读文件、仅目标缺失、文件 mode 000、父目录 mode 000、祖先 mode 000、父目录真实缺失、ENOTDIR、普通链接、悬空链接、父目录链接、目录、FIFO。
- 权限用例必须在非 root 环境真实成立，独立核对实际可进入性与 errno；root/ACL/宿主环境使条件不成立时标明跳过原因，并在可成立的 Linux CI 环境补上。不得用伪造 Permission denied 文本冒充权限验证。
- 对两个回执名称测试：等长合法 JSON 替换、检查后链接替换、父目录替换、4096 边界及超限/增长/缩短、部分读取失败。记录替换前后身份；没有读出替换内容是必要断言。
- 对合法、absent、无法核实、非零返回及“stdout 看似合法但 rc 非零”测试三路解析；对 PBS 和 Slurm 实际调用路径分别验证，不能假定两个调度器调用完全相同。
- Multiwfn 用真实 layout 生成声明列表，覆盖单文件、展开后的多文件及最大允许布局；一个文件无法核实不能返回可接受的部分观察。保留命令大小限制。
- 覆盖首次状态观察、旧 PBS 完成判定的第二次观察、cancelled 的不完整取回拒绝，以及已有 finished/fetched 结果不得因错误被覆盖。既有状态机语义不变。
- 覆盖固定命令参数注入、越界及符号链接拒绝、SSH 255 和响应失败；使用已有假 Transport，禁止测试创建真实 SSH 连接。
- macOS 的 stat 适配只能证明其实际测试范围。Linux CI 必须执行真实目标格式工具与完整生成命令；有 procfs/Python 分支时单独证明依赖和兼容，不把 skip 当通过。
- 开发时先跑本单及受影响回归；推送前一次 `PYTHONPATH=ag/src python -m pytest ag/tests skills-next -q -rs`，记录通过数和跳过原因。随后依当前 head 的 CI 结果；只有新修改或未解疑点才扩大重复测试。
- 提交前逐个暂存本单文件，执行 `git diff --cached --check` 和现行敏感信息扫描；核对提交身份与 PR 正文，不提交实际路径、账号、主机、作业号或研究材料。
