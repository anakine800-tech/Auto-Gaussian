## 要做的

1. 新增可选 `ag route --walltime HH:MM:SS`；`--tier` 保持显式必填。未传 walltime 的旧调用仍可运行，但必须写明未核对任务时限，不显示已全部匹配。
2. 提供 walltime 时使用现有合法正时长解析；每入口有 `resources.max_walltime` 时比较。超限是规格不适用，不能在“所有入口都要排队”的回退中重新选中；不影响其它合法入口。
3. 配置未设上限只表示 ag 不知道调度器时限，不等于无限制；给明确说明，不增加全局提交禁令。来源仅为现行本机配置，不新增远端调度预测/查询。
4. prepare_hint 使用已保存 manifest 的 walltime 和实际 tier，不能改准备成功结果、原 manifest 或绑定入口。提示计算失败仍仅影响提示，不把已成功 prepare 变为失败。
5. 节点容量判断复用 T156；具名候选复用 T157 的最终策略。保留本人全部作业额度、共享账号取最小限额、现有路由顺序与研究级顺序覆盖；不按分区内存总和声称单节点足够。
6. 统一描述为快照下的容量/排队建议，并写“不保证实际启动时间”；不新增预计等待时间。保留已有 JSON 字段，新增时限结果采用可选字段并在 README 说明；不要为此另造 schema 合同。
7. 建议资格区分：规格不合法（模板/档位/时限等）不能进入排队回退；当前容量不足但规格合法可以建议排队；未知按已定提示与原检查处理。
