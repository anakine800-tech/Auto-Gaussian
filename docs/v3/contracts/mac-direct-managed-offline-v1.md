## Concrete prototype boundary

- R4 C: closed typed CHNO, neutral singlet, vacuum xTB single-point material;
  explicit gfn1/gfn2; integer microangstrom encoding and exact XYZ roundtrip;
  immutable intent/input/program semantic join. This restriction and the
  non-restart lifetime apply only to this first offline prototype.
- R5: one root initialized before intake, 1024 preallocated slots, exactly
  three cells per allocated slot, monotonic allocation and bounded generation;
  reserve before Core/material writes. No eviction, recovery or reset of
  registry associations. Incomplete slots remain occupied. Missing root,
  slot, cell, index, or changed identity poisons the lifetime.
- Use original Core APIs for local Task/plan/resource/Attempt creation and
  original SQLiteApprovalStore for decisions. No second approval/submit DB.
  Store CHOSEN plus original candidate IDs/payload hashes before any write;
  no repeat write after ambiguity. Decided view eviction never loses ID links.
  Batch/operational/consume reread the same slot's original records.
- R4 A: exact bounded canonical frame codecs and three review operations;
  one complete pending display, TTL 600 seconds, two candidate IDs, one
  explicit decision per Gate. Human relay consumes only an explicitly supplied
  current user event matching the complete view; no transcript mining or
  default approval. Same-UID source authenticity remains an accepted trust
  assumption, not a cryptographic or native Codex attestation.
- R4 B G/C/M ordering and STOP/launch linearization are implemented as a
  closed offline state model. A sealed in-process fake native adapter records
  normal/recovery launch shapes without executing commands. It is never
  injected into production driver type checks. Production construction and
  activation always reject; there is no flag that enables real process launch.
- Operational preparation has no live entry. Missing real Project physical
  binding/snapshot dependencies remains explicitly blocked. Tests alone may
  use existing privileged synthetic provisioning/snapshot owners. Those
  objects are never used to claim Direct or native qualification.

The offline model does not install sockets, getpeereid, cross-UID protection,
OS flock, marker fsync/F_FULLFSYNC, crash persistence, production Popen,
child supervision or driver exception cleanup. These are deferred native
qualification and implementation, not mock-proven properties. Recovery and
collection continuation UI creation stays disabled. Original Core observations
own intent/START/raw/receipt; ProgramTransportStore owns physical authority.
