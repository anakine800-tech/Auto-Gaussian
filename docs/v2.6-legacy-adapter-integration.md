## Scope and order

The public production integration entry accepts only already loaded contract
objects plus the existing attempt ID and idempotency digest. It accepts no
caller time or `consumed_at`, and adds no CLI option, backend selector, host,
path, command, retry, cleanup or root override. Production construction has a
fixed local timezone-aware UTC clock; only an explicitly private, token-gated
test factory can inject a clock for placeholder-only offline tests.

Before the first fixed-adapter invocation it:

1. uses the current `transport_authority_closure.py` owner to replay the exact
   historical `/1` request and authorization, successor `/2` request and
   authorization, profile and identity binding;
2. consumes the owner-issued sealed successor closure while validating the
   actual Stage A and Stage B request/receipt artifacts and the third-stage
   observation/receipt binding;
3. under the existing trusted state lock, obtains the current timezone-aware
   UTC immediately before the final replay, uses that exact canonical time for
   the final expiration gate, and publishes it as `consumed_at` in one
   single-use `submission_uncertain` reservation; and
4. passes one owner-sealed handoff to the sole `legacy_rtwin_pbs` adapter.

The pre-lock replay is only an early fail-closed check; its time cannot decide
the final gate. Any missing, expired, spliced or inconsistent artifact stops
before the reservation and before the adapter. A concurrent duplicate stops
in the existing state owner. An adapter exception is not retried: the
reservation remains `submission_uncertain`, no cleanup occurs, and only the
existing read-only reconciliation workflow may continue.

## Compatibility and limits

The historical CLI, `/1` replay, scientific input/method review, resource
policy, execution-batch and result-acceptance owners are unchanged. No
historical artifact is migrated, rehashed or backfilled. PR4A typed models,
the current successor owner and their schemas remain the sole validators; the
integration layer only composes them.

The real adapter entry intentionally remains fail closed. Local placeholder
fixtures and mocks demonstrate ordering, single invocation, concurrency,
expiration at the final owner time, reservation-time identity, exception and
uncertain-state preservation, compatibility and relocated package imports.
They do not approve or verify an actual connection, transfer, submission,
cancellation, fetch, deployment or scientific result.

PR4 therefore remains blocked from merge. A new independent L3 code review is
required for this candidate. Actual adapter verification remains a separate
exact approval gate and would invalidate the current offline-only claim if its
bytes or behavior changed.
