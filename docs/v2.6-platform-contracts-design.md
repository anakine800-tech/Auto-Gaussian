# Auto-G16 v2.6 PR2 platform-contract ownership map

Status: implementation design for independent L3 review

Task class: feature development / L3 target-identity and configuration boundary

Base commit: `e2589c0c4198ebb8b873658293f500cfe192462f`

Branch: `codex/v26-platform-contracts`

This PR implements only the offline platform contracts assigned to PR2 by the
accepted [platform portability RFC](v2.6-platform-portability-rfc.md). It does
not implement an execution backend, an authorizing successor, a live identity
handshake, SSH/PBS/Gaussian access, deployment, migration apply, or scientific
acceptance.

## Source ownership

| Surface | Single source owner in this PR | Reused owner / compatibility boundary |
| --- | --- | --- |
| Strict JSON, canonical bytes, self-hash, models, validation, legacy mapping, and offline CLI | `scripts/platform_contracts.py` | Does not add validators to legacy execution modules |
| ExecutionProfile, TransportIdentityBinding, attestation receipt, CapabilityReport, and ResourceCatalog schemas | `contracts/execution/*.schema.json` | New `/1` contracts only; no historical schema is edited |
| Legacy runtime `/1` parsing | Existing `scripts/runtime_config.py` in the repository, or its existing self-contained deployed counterpart | PR2 consumes the validated nine-field result and does not reinterpret the old schema |
| Legacy resource tuples and limits | Existing `skills/auto-g16-rtwin-pbs/scripts/resource_efficiency.py` | PR2 adds a pure catalog-facts view; policy/gate/approval behavior stays with the existing owner |
| Deployment mapping | `skills/auto-g16-rtwin-pbs/deployment-package.json` | Maps the root owner module and `contracts/execution`; no repository duplicate is created inside the Skill |

`scripts/platform_contracts.py` is both the repository CLI and the only Python
implementation owner. The named-Skill package maps that exact file to its
installed `scripts/` path. Schema files are declarative interoperability
contracts; executable validation remains in the single Python owner.

## Closed model boundary

The owner provides closed models for ExecutionProfile,
TransportIdentityBinding, FirstHopIdentityReceipt,
NestedHopIdentityReceipt, CapabilityReport, ResourceCatalog, and a deterministic
LegacyMappingResult. Receipt request models are typed and closed as well. All
loaders reject duplicate or unknown keys, BOM, malformed UTF-8, non-standard
numeric constants, floats/exponents, booleans in integer positions, blank
strings, unsafe paths, symlinks, and secret-like identity material where the
model forbids it.

Canonical JSON is implemented once and shared by all new contracts: recursive
Unicode scalar key ordering, array-order preservation, minimal JSON escapes,
direct UTF-8 for non-ASCII scalars, no optional whitespace, and exactly one
terminal LF. Each payload digest excludes only its declared self-hash field;
validation recomputes the digest and compares it in constant time.

TransportIdentityBinding stores ordered hop digests only. It never stores
alias, host, IP, user, port, SSH option, config/known-hosts/identity path, host
key, or fingerprint plaintext. Config-source bundle hashing uses a versioned,
length-prefixed byte framing so different source sequences cannot collide by
concatenation ambiguity. It operates only on caller-supplied synthetic/local
bytes and never reads user SSH configuration.

Typed attestation in PR2 is contract validation only. It has no connector,
subprocess, socket, command, argv, shell, PowerShell, script, or caller path
fragment surface. Unknown, partial, expired, inverted, nonce/profile/
first-hop/version mismatch classifications fail closed with zero retry.

The offline validator is intentionally stateless and idempotent: validating
the same still-valid request or receipt twice returns the same non-authorizing
result. PR2 does not consume nonces or claim single-use/replay suppression.
PR3 authorization and the future PR4/PR6 trusted live owner must bind and
enforce single use before any mutation.

For a nested receipt, `host_key_evidence_sha256` is the digest of the approved
second-hop host-key evidence projection already bound into the identity hop;
it is not an observed handshake fingerprint. The RFC places the second-hop
handshake after validation of this hash-only receipt. Comparing the later
observed fingerprint is therefore a future live-adapter responsibility, not a
PR2 field or a meaning of `classification=verified`.

## Resource and capability boundaries

The legacy catalog is derived from the existing resource owner and must freeze
exactly `simple=8/12`, `general=22/50`, and `complex=44/120`, with capacity
`44/120`. `custom_reviewed` is only expressible when its explicit policy flag
is true and its positive integer tuple is within that capacity; PR2 creates no
approval or gate. Walltime remains explicitly reviewed and is not a tier
default. Every backend remains fixed to `/home/user100/SDL`.

CapabilityReport is built only from a fully validated profile. It reports
configured expressibility with `offline_only=true`, never reachability,
license/Gaussian availability, or live authority. Local Gaussian, Slurm, and
MCP are always listed as unsupported and never trigger fallback.

## Offline CLI and compatibility

The owner exposes explicit `init`, `validate`, and `doctor` subcommands.
`validate`, `doctor`, and `init --dry-run` are read-only and contain no network
or subprocess implementation. A real `init` is the only write path: it is
user-invoked, names the exact destination, requires an absolute no-symlink
path, publishes with no-clobber atomic semantics, and leaves owner-only file
permissions. It never writes the legacy runtime.

Legacy mapping reads runtime `/1` through its existing validator and emits a
deterministic derived profile/catalog summary plus sanitized field-name-only
conflict diagnostics. It never modifies either input, silently selects a
backend, or treats a legacy approval as authority for profile-mode or direct
execution. For nested legacy transport, offline doctor reports only
`live_attestation_required` for the second hop.

## Validation and rollback

Tests use synthetic placeholders only. Focused and adversarial coverage owns
strict decoding, canonical bytes, self-hash forgery, identity redaction,
source framing, typed receipt mismatch/time checks, unsupported backends,
no-follow/no-clobber init, legacy mapping, packaging, and source/archive
determinism. Adjacent legacy golden, runtime, resource, execution-batch,
safety, bridge, and packaging suites must remain unchanged.

Rollback is a normal reviewed revert of this PR. No historical object is
rewritten or migrated, and no remote or local runtime state requires cleanup.
