## P1 and corrected factory rule

The blocked concurrency candidate serialized calls made through one raw owner,
but the same effect plan could be passed to the private owner factory more than
once. Each factory call created a distinct owner, state and lock, so both
owners could execute the first fixed effect.

Each module-issued effect plan now has module-created one-shot factory state
and its original lock. The module records exact object references rather than
integer identities. Under that lock, the first factory call moves the plan
from `unclaimed` through `claiming` to `claimed` and binds one exact owner.
Every later sequential or concurrent factory call fails before an effect. If
owner construction or binding validation raises any `BaseException`, the plan
becomes terminal `failed`; it cannot be retried into another owner.

The module also records the exact owner, effect state, original effect lock,
plan and plan-factory state. Every dispatch replays that bidirectional identity
inside the effect lock before advancing the fixed cursor. Swapped plans,
cross-owner states, cross-plan factory states, replacement locks, subclasses,
unregistered exact objects, copies and serialized replays fail before the sole
runner call.

These Python-private names and tokens are not an isolation or hostile-code
security boundary. The binding closes accidental internal replay in the real
legacy call graph; code with arbitrary in-process mutation can still rewrite
Python module state.
