## Scope and non-authority

This successor adds a fixed-root evidence and capability model for the sole
`legacy_rtwin_pbs` backend. The backend and root are constants:
`legacy_rtwin_pbs` and `/home/user100/SDL`. No CLI flag, environment value,
runtime setting, caller path, backend selector, fallback or advanced override
can select or replace either value.

The implementation is offline and effect-free. It does not modify or call the
legacy adapter, facade, integrator, factory, raw owner or main entry point. It
does not implement transport, SSH, PBS, Gaussian, stage, submit, fetch,
cancel, cleanup, deletion, deployment or network access. Portable documents
and the private synthetic observation factory explicitly authorize no remote
effect.

Historical manifests, schemas, owners and package bytes remain unchanged. The
new source, Schemas and this reference enter the named Skill only through
`config/deployment-package-supplements/auto-g16-rtwin-pbs/legacy-root-authority.json`.

## Stable, fresh and consumption order

1. The canonical legacy-root owner loads only after the exact protected
   production-ingress owner and captures the exact transitive source bindings.
2. Its private synthetic factory models the three fixed SDL component
   identities and issues stable evidence. Stable bytes contain no observation
   time, expiry, nonce, receipt ID, project, attempt, input or operation value.
3. An additive authorization binds the exact legacy profile `/2` hash, stable
   evidence hash and every exact sealed production-ingress identity field.
4. Immediately before the modeled consumption, one fresh observation must
   match the stable root; the authorization, operation, observation and ingress
   projects must all agree with the fixed workspace derivation and every
   no-follow safety marker.
5. The owner issues a fresh time-bounded receipt and non-copyable capability.
   A portable or copied receipt cannot construct that capability.
6. Historical `consume_once()` still returns one non-authorizing lease. The
   additive `SingleUseLegacyDescriptorRelativeMutationCapability` instead
   retains the same owner-owned opaque handles and the exact owner-registered
   production factory result, coordinator claim and root lease. Its portable
   factory/coordinator fields are evidence only; authority remains the retained
   exact objects and exact owner-issued operation class/module/method/callback.
7. `consume_and_invoke_once()` locks the workspace and mutation registries,
   replays all bindings and first irreversibly changes the authoritative
   owner-registry outcome to `effect_started_outcome_uncertain`, before calling
   the durability recorder or invoking the exact operation. Tests supply only
   fake recorders; the operation receives opaque handles and fixed relative
   component labels, never a path string. A durability-recorder exception is a
   durability failure, not proof that persistence succeeded: the owner remains
   non-retryable and uncertain and requires manual read-only reconciliation.
   A normal operation return records `completed`; any exception remains
   uncertain and a second attempt is rejected.

## Fail-closed conditions

Unknown or changed backend/root/profile/stable/ingress/workspace identity;
source or class drift; foreign or replaced module/object/descriptor; missing,
expired or replayed receipt; clock rollback; symlink or reparse point;
containment or root escape; non-fresh project; path reopen; duplicate or
concurrent second consumption all fail before the offline consumption bit is
set. There is no fallback, retry, overwrite, cleanup or deletion path.

The cooperative in-process model does not protect against arbitrary code
already executing inside the owner process. This candidate supplies the
missing owner/registry capability contract and a fake-recorder invocation
model only. It does not wire the adapter, transport, factory, coordinator or a
remote helper and authorizes no live action.
