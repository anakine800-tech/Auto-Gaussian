# Auto-G16 v2.7 process-isolated direct-root fixed mutation helper

## Scope and authority

This closure consumes the exact POSIX no-follow descriptors retained by
`direct_root_owner_contract`; it does not copy that owner.  The parent replays
and consumes the exact W1 capability, then passes the retained root/component
FD chain over one private Unix control socket with `SCM_RIGHTS` to a fixed
helper entrypoint in a clean exec'd Python interpreter.  The helper never
accepts a root, path, command, environment selector, label, callback, shell,
transport, retry, cleanup, deletion, rename, PBS, Gaussian, `qsub`, or `qdel`
override.

The only fixed operations are:

1. replay every retained existing component through `O_NOFOLLOW | O_DIRECTORY`
   and the W1 identity tuple;
2. create the approval-bound project basename exclusively under the retained
   root FD;
3. open the new project no-follow and create the literal `scratch` directory
   exclusively beneath it.

The project basename comes only from the canonical W1 authorization `/3` and
fresh receipt.  Absolute paths are not sent to the helper.  The final retained
root FD is used for `mkdirat` semantics, and the new project FD is used for the
scratch mutation; no absolute path is reopened after the check.

This is a production implementation of the fixed local descriptor mutation
primitive, but it still carries `remote_effect_authorized=false`.  It performs
no SSH, transport, PBS, Gaussian, upload, submission, inspection, fetch,
deployment, or live smoke.  A schema-valid result is not a capability.

## Process and FD lifecycle

The fixed protocol is `auto-g16-direct-root-fixed-helper/1`.  `Popen` uses an
absolute captured Python executable plus the same `O_NOFOLLOW`-opened and
hash/identity-verified helper-source FD through fixed `/dev/fd` ingress,
`close_fds=true`, and an empty environment.  Only that source FD and the
private control FD survive exec; the helper closes its source FD before READY
and reports that no unrelated low FD remains. Received `SCM_RIGHTS` FDs are
marked `FD_CLOEXEC` immediately. Parent and child own different descriptor copies:
the child closes every received FD on every exit; the parent closes the W1
bundle once through the W1 owner after the child becomes terminal.

The child validates the complete canonical request and descriptor chain before
returning `validated_no_effect`.  It cannot mutate until the parent sends the
fixed `begin_project` frame.  Spawn/exec failure, malformed or oversized
frames, missing/foreign rights, descriptor drift, duplicate pre-effect frames,
or capability failure therefore has zero filesystem effect.

After `begin_project`, the parent records `outcome_uncertain` in its local
transaction before waiting for another IPC event.  EOF, timeout, signal,
crash, malformed response, project-only partial mutation, scratch failure, or
terminal-report loss remains `outcome_uncertain`.  The implementation never
retries, rolls back, deletes, renames, cleans up, or reconstructs a capability.

## W2 typed seam

`DurableJournalSeamDocument` is a closed, exact-builtin projection for the
separately owned W2 journal claim.  It binds the journal/binding hashes to the
W1 receipt, authorization scope, workspace and descriptor set, and it must say
`outcome=started` and `authorizes_effect=false`.  This W4 branch does not import,
issue, persist, close, or reproduce W2's claim owner.  Consequently results
state `durable_journal_owner_integrated=false`; the integration successor must
adapt and replay the exact W2 claim type before calling this consumer.

## Evidence and remaining gaps

Hostile tests use only repository-external temporary filesystems.  They cover
exclusive success, existing directories and symlinks, component drift,
SCM_RIGHTS/CLOEXEC, unrelated-FD exclusion, parent/child close ownership, FD
reuse, concurrency/duplicates, malformed/oversized/bool-as-int frames,
module/function rebinding, child termination before effect, crash/EOF after
the first effect, partial mutation, and the fixed no-delete/no-shell surface.

Closing `physical_descriptor_relative_helper` does not close durable W2
integration, resource/live effect-time replay, direct transport, real qsub,
inspect/fetch, or live-smoke evidence.  It changes no legacy `/1` or `/2`
artifact and no `/home/user100/SDL` rule.
