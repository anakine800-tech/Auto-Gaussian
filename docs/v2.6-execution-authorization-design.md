# Auto-G16 v2.6 execution authorization design

## Scope and ownership

PR3 adds exactly two closed, strict-canonical-JSON schemas and one offline
owner. It does not change existing `submit`, `stage` or `auto` behavior and does
not add a CLI, backend abstraction, transport plan, live storage or scheduler
operation.

| Closure | Single owner replayed by PR3 |
|---|---|
| canonical JSON, self-hash, profile, identity, capability, resource catalog | `scripts/platform_contracts.py` |
| exact Gaussian input and scientific approval receipt | `gaussian_rtwin_pbs.py::parse_gaussian` and `validate_input_approval` |
| resource policy, scheduler snapshot, gate and ledger | `resource_efficiency.py` validators and existing gate binding validator |
| batch/task/attempt/idempotency derivation | `execution_batch.py::attempt_id_for` and the resource owner ledger validator |
| request, human authorization, cross-owner closure and readiness result | `scripts/execution_authorization.py` |

The adapter loads and calls the original owners. It does not reproduce their
validator semantics. Where the resource owner lacks a public gate-validation
entry point, PR3 uses the narrow existing `_validate_gate_binding` function and
does not fork its rules.

## Contracts

`auto-g16-execution-request/1` binds exact input bytes, task/attempt and work
kind, profile/backend/capabilities, proposed exact resource tuple and five
ordered upstream artifacts. Fixed markers make it permanently non-authorizing.

`auto-g16-execution-authorization/1` is the human-issued approval provenance.
Its scope digest covers the signer, times, decision, active state, full closure
and exact operations; operation-local scope copies are excluded only to avoid a
recursive hash definition. The document must be approved, active, unrevoked,
unconsumed, single-use and inside both authorization and attestation windows.

Schema/Python parity is asserted only for finite critical shapes: nonzero SHA,
the eight sorted required-capability sets, named and bounded custom resource
tuples, specialist-receipt/work-kind coupling, and backend/hop/attestation
topology. Timestamp schema patterns enforce only the second-precision UTC
lexical shape. The Python owner is the semantic authority for real calendar
dates, ordering and active windows. The repository does not claim a general
JSON Schema runtime validator or `format` enforcement.

## Offline result and replay limit

The gate returns an immutable `closure_valid_offline` result with
`live_ready=false`. A caller registry hit is a rejection, but a miss proves
nothing globally. The result explicitly records the future trusted-owner replay
and atomic-consumption gaps. `ready_to_submit` and `authorized_for_live` are not
states in this implementation.

## Migration and rollback

Legacy approvals remain byte- and semantics-frozen for historical/in-flight
use and are rejected by the new gate. There is no conversion or backfill. New
profile/direct work uses new human-issued authorization artifacts after PR3
integration. Rollback removes only this additive owner and the two schemas;
legacy execution behavior remains unchanged. PR4 is gated on PR3 merge and an
independent L3 review.
